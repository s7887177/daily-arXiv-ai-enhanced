# 多個 AI Agent 同時工作，怎麼確保「沒看到最新消息」時不做出錯誤決定？

> 原始論文：Causal Past Logic for Runtime Verification of Distributed LLM Agent Workflows
> 作者·單位：Benedikt Bollig（Université Paris-Saclay、CNRS、ENS Paris-Saclay、LMF）
> arXiv：2605.20923v1 ・ 分類：cs.LO、cs.AI、cs.PL

一句話說重點：當多個 AI Agent 分散執行任務，某個 Agent 做決定時可能還沒收到其他 Agent 的最新訊息，這篇論文提出「因果過去邏輯」（Causal Past Logic），讓每個 Agent 只用它確實「看得到」的資訊來驗證規則，同時用向量時鐘（vector clock）做數學上嚴格的即時監控。

---

## 背景：分散式系統裡的「資訊不對稱」問題

現代軟體開發越來越依賴多個 AI Agent 並行工作——一個負責跑測試、一個負責掃安全漏洞、另一個負責決定是否合併程式碼。這種分散式架構帶來效率，但也帶來一個根本問題：**事件在不同 Agent 之間的傳遞需要時間，某個 Agent 做決定時，另一個 Agent 的最新結果可能還沒送達**。

傳統的「事後驗證」方法把所有 Agent 的日誌合在一起，用一條時間線排序、再去檢查規則。但這在分散式系統裡行不通——你在本地看到某件事「已經發生了」，但遠端 Agent 的決策點可能還沒收到這個更新。用全局日誌驗證，等於要求 Agent 遵守它根本「不知道」的資訊，這在現實中無法做到。

## 解決方案：只用「因果可見」的資訊做判斷

這篇論文的核心貢獻是把 **Causal Past Logic（因果過去邏輯，CPL）** 整合進 ZipperGen 分散式 Agent 框架。CPL 是一種「過去時序邏輯」（past-time temporal logic），專門用來寫條件判斷規則——只參照在邏輯上確實先發生、且已傳遞到當前 Agent 的事件。

CPL 的關鍵語法元素：

- **previous（上一個）**：目前 Agent 生命線上的上一個事件
- **since（自從）**：「自從某事件以來，某條件持續成立」
- **@A.x**：「Agent A 的最新變數 x 的值」——但這裡的「最新」不是全局最新，而是「在因果上對當前 Agent 可見的最新」

舉個例子：程式碼審查場景中，合併決策者（Committer）有個規則「允許合併，只有在它能看到的 TestRunner 狀態是通過、且沒有更晚的失敗可見」。這個規則用 CPL 精確表達，然後在 Committer 自己的事件流上即時求值。

## 實現機制：向量時鐘 + 最新值視圖

論文給出了一個具體的執行監控器（monitor），使用**向量時鐘**（vector clock）來追蹤因果順序。向量時鐘是分散式系統裡的標準工具：每個 Agent 維護一個計數器陣列，每次通訊都更新，用來判斷哪些事件「在因果上先於」哪些事件。

這個監控器同時維護每個「姐妹 Agent」（sister lifeline）的最新可見變數值（latest-value view）。作者在論文中嚴格證明了：**監控器在本地計算出的 CPL 值，與 CPL 的形式化語義（denotational semantics）完全一致**——也就是說，即時在線監控的結果等同於理論上「完全知情後」的正確答案。

這張架構圖展示了整個系統的互動關係。**Orchestrator**（指揮者）同時把 patch 發給 **TestRunner**（測試執行者）和 **Security**（安全掃描者），這兩個 Agent 並行工作，完成後把結果送給 **Committer**（合併決策者）。關鍵是：Orchestrator 發出 merge proposal 的時機可能早於兩個審查者的最終結果送達 Committer 的時機——這正是「分散式決策」的核心難題。CPL 讓 Committer 能夠在自己的因果視角下正確評估規則，而不依賴一個全局的「等大家都結束」的同步點。

## 做不到的地方

- 論文目前是純理論貢獻，提出了邏輯語義、監控器設計、正確性證明，但**沒有大規模實驗數據**來衡量效能開銷。
- CPL 的表達力有其限制：它是「過去時序邏輯」，無法表達「未來會發生什麼」的斷言（不支援未來模態詞）。
- 在非 FIFO（先進先出）訊息傳遞下，收件人需要重建發件人的本地順序，論文提及這需要額外的序列號或因果元資料，但細節留給未來工作。

## 怎麼看這件事

隨著「AI Agent 工作流」（agent workflow）快速普及，多個 AI 同步工作的場景越來越常見：一個 Agent 爬資料、一個分析、一個寫報告、一個決定下一步行動。在這種分散式環境裡，「我的決定是根據最新資訊嗎？」這個問題比看起來難得多。

這篇論文從形式方法（formal methods）的角度切入，提供了一個數學上嚴格的答案框架。它的貢獻不在於讓 Agent「更聰明」，而在於讓我們能夠**驗證 Agent 的決定是否符合預期的因果規範**——這正是工業界在建構可靠 AI 系統時，越來越需要面對的治理問題。

對實踐者的意義是：下一次你設計多 Agent 系統時，「分散式監控」不應是事後補丁，而應該從設計階段就考慮每個 Agent 的「信息視野」邊界。
