# AI 智能體會自我進化了：Autogenesis 協定讓代理程式邊跑邊升級

> 原始論文：Autogenesis: A Self-Evolving Agent Protocol
> 作者·單位：Wentao Zhang、Zhe Zhao、Haibin Wen、Yingcheng Wu、Cankun Guo、Ming Yin、Bo An、Mengdi Wang（南洋理工大學、史丹佛大學、普林斯頓大學、香港城市大學、中國科學技術大學）
> arXiv：2604.15034v4 ・ 分類：cs.AI

一句話說重點：這篇論文提出 Autogenesis 協定，讓多智能體（multi-agent）系統能在執行任務的過程中，自動提出、評估並提交對自身提示詞、工具和記憶的改進，且每次修改都可追溯、可回滾。

---

## 背景：現有 AI 代理為何難以自我改進？

近年「智能體（agent）」系統——讓 LLM 不只回答問題，還能呼叫工具、規劃步驟、執行長鏈任務——已成為 AI 研究的前沿。但現有系統有個根本缺陷：**提示詞、工具、記憶等元件都被硬編碼在程式碼裡**，無法在執行時動態調整。

Anthropic 的 **MCP（Model Context Protocol）** 和 Google 的 **A2A（Agent-to-Agent）** 協定解決了智能體之間「如何通話」的問題，但沒有解決「如何安全地改進自己」的問題——沒有版本管理、沒有生命週期控制、沒有出錯後回滾的機制。

## 怎麼做：兩層協定架構

**AUTOGENESIS PROTOCOL（AGP）** 用兩層架構解決問題：

**第一層：資源基底協定層（RSPL）** 把所有可能需要進化的東西——提示詞（prompt）、智能體（agent）、工具（tool）、環境（environment）、記憶（memory）——都抽象為「協定資源」，每個資源有：
- 明確的**狀態**（當前版本的內容）
- **生命週期**（創建、更新、棄用）
- **版本索引**（每次修改留下可查詢的歷史記錄）

**第二層：自我進化協定層（SEPL）** 定義了一個閉迴路算子介面，讓系統能系統化地改進自己，步驟如下：
1. **反思（Reflect）**：追蹤分析，識別哪個資源表現差
2. **選擇（Select）**：選定要優化的目標資源
3. **改進（Improve）**：對選定資源提出變更
4. **評估（Evaluate）**：在受控環境測試新版本
5. **提交（Commit）**：確認改進後更新主線版本（可回滾）

基於 AGP，**AUTOGENESIS SYSTEM（AGS）** 是一個完整的多智能體系統實作，包含規劃代理、工具呼叫代理、深度分析代理、撰寫代理等，透過「代理匯流排（Agent Bus）」協同工作。

## 結果：在五個困難基準上超越強基線

評估使用五個挑戰性基準：
- **GPQA**（研究生程度科學問答）
- **AIME**（美國邀請數學測驗）
- **GAIA**（通用 AI 能力評估）
- **HLE**（人類最後的考試）
- **LeetCode**（程式設計題目）

AGS 在所有基準上都取得一致且明顯的改進，超過了當前強基線方法。論文展示了資源管理與閉迴路自我進化對長程規劃與工具使用任務的有效性。

## 做不到的地方

- **自我進化的邊界**：AGS 只能優化現有資源的參數/內容，無法憑空創造全新的系統架構設計，進化空間受限於初始設計。
- **安全風險**：自我修改的系統若優化目標設定不當，可能朝非預期方向演化；論文雖有審計機制，但對抗性情境下的安全性未深入驗證。
- **計算成本**：頻繁的反思-評估循環帶來額外的推論成本，在低延遲或低成本場景下可能不切實際。
- **基準多樣性**：評估集中在問答與程式設計類，對開放式創意任務或真實世界操作型任務（如電腦使用）的有效性驗證較少。

左側是「協定」部分：RSPL 層管理五類核心資源（提示詞、智能體、工具、環境、記憶），透過伺服器介面與情境管理器控制版本與生命週期；SEPL 層以五步算子閉環（反思→選擇→改進→評估→提交）驅動自我進化。右側是「應用」部分：多智能體系統透過代理匯流排協調，支援遊戲、數學解題、電腦操作、網頁瀏覽等多種任務類型。整個架構的核心精神是「任何可進化的東西都是一個有版本號的資源」。

## 想自己判斷這篇可不可信？

| 訊號 | 這篇的情況 | 怎麼解讀 |
|---|---|---|
| 代碼開放 | GitHub 連結已提供（DVampire/Autogenesis） | 可重現性有保障 |
| 基準多樣性 | 5 個不同類型的挑戰性基準 | 泛化性初步驗證，非單一資料集 |
| 比較方式 | 對比強基線，但未與 EvoAgentX 等最新自演化系統完整對比 | 部分競爭對手可能未完整呈現 |
| 安全分析 | 有版本回滾機制描述，但安全性系統實驗有限 | 安全聲明仍以設計為主 |
| 機構背景 | 南洋理工、史丹佛、普林斯頓等多機構合作 | 學術背景強，但商業部署驗證缺乏 |

## 怎麼看這件事

智能體自我進化是 AI 系統走向更強自主性的關鍵一步，但「安全且可審計的自我修改」長期以來缺乏工程標準。AGP 把這個問題定義為協定層的問題，而非個別系統的問題——這個抽象層次的提升有助於讓不同廠商的智能體系統都能遵循相同的進化規範，類似於 HTTP 之於網頁通訊的角色。當然，真正的考驗是：當智能體在高風險場景（如金融交易、醫療決策）中自我修改時，版本控制與回滾機制能否在實際故障情境下可靠運作。
