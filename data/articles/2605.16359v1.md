# 看圖問答的 AI 其實看太多了——學果蠅覓食,只挑「跟問題有關」的畫面細節

> 原始論文：How Many Visual Tokens Do Multimodal Language Models Need? Scaling Visual Token Pruning with F^3A
> 作者·單位：Yijie Huang、Yiqun Zhang、Zhuoyue Jia、Xiaocui Yang、Junzhao Huang、Zihan Wang、Shi Feng、Daling Wang、Yifei Zhang、Yongkang Liu（東北大學[中國瀋陽／秦皇島]、上海人工智慧實驗室）

> arXiv：2605.16359v1 ・ 分類：cs.CV

一句話說重點：能看圖回答問題的 AI,把整張圖切成成百上千個小塊全部塞給語言模型,既慢又貴;這篇借用「果蠅覓食」的策略,讓 AI 先看「問題在問什麼」,再只挑出最相關的少數畫面小塊——刪掉 80% 後仍保住約 94% 的準確度。

---

## 背景:看圖的 AI,其實在「狼吞虎嚥」

現在能同時看圖又能對話的 AI(叫**視覺語言模型**,vision-language model),處理一張圖時會把它切成很多個「視覺 token」(把圖像分成的小塊,每塊變成一串數字餵給語言模型)。圖越清晰、越想看清細節,這串小塊就越長——文件、圖表、OCR、多圖理解都靠它。

問題是:**這些視覺 token 非常貴。** 它們常常比文字提示長得多,主導了運算成本,撐大記憶體(KV cache),拉長回應延遲。當模型從小型長成超大型(論文測到 2350 億參數),「該保留哪些畫面小塊、要留多少才不掉效果」就變成一個資源分配難題。

現有的「免訓練剪枝」方法(在不重訓模型的前提下丟掉部分 token)大多用一次性的代理分數:看解碼器注意力、看視覺相似度、看多樣性,然後留下分數最高的一批。作者主張:**這種「靜態排名」在大幅壓縮時不夠用**——同一張圖,問「招牌寫什麼」「兩物的空間關係」「圖表數值多少」,該保留的小塊根本不一樣。token 的價值不只看它顯不顯眼,而要看它對**當下這個問題**有沒有證據力。

## 怎麼做:把剪枝看成「帶著問題去覓食」

論文提出 **F³A**(Fruit-Fly-Foraging Algorithm,果蠅覓食演算法)。它把「挑 token」重新定義成一個「**被任務（問題）牽引的證據搜尋**」,而不是靜態排名。它放在視覺塔之後、語言模型吃進圖像之前,**不需要重訓模型,也不需要額外跑一次大模型**。

流程像果蠅靠氣味找食物,分三步：

1. **粗搜索（Coarse Search）**：先把問題轉成幾種「線索」(全域線索、目標線索、任務線索),用凍結的稀疏感測頭跟整張圖的格狀小塊比對,形成一張「任務氣味場」——哪裡氣味濃,代表那區可能藏著答案證據。
2. **視覺鎖定（Visual Lock-on）**：在氣味濃的區域做局部精修,鎖定真正關鍵的小塊,同時避免「貪心地把旁邊一堆冗餘鄰格也選進來」。
3. **救援跳躍（Rescue Jump）**：對「沒被覆蓋到、但可能重要」的區域做補救,把固定的 token 預算重新分一點過去,避免漏掉邊緣的小細節。

整個過程一趟搞定,保留原本的多模態提示與解碼流程不變。

這張圖的讀法:最左欄是「**把問題變成線索**」——一個關於「哪些是乳製品」的問題,被拆成三種線索（Global / Target / Task Cue）。下方「Vision Tower」是把圖切成格狀小塊。中間三欄就是三步覓食:**Step 1** 比對後產生底下那張「任務氣味場」熱力圖,**紅色越亮代表那區跟問題越相關**;**Step 2** 在亮區畫綠框「鎖定」關鍵小塊（Lock-on Score）;**Step 3** 那條標著「Jump」的箭頭,就是把預算「跳」去救援沒被覆蓋到的區域,得出右側那張只剩少數深色方塊的「最終選取集」。最後右上角只把這些被選中的小塊送進「LLM」回答（Answer: B）。重點:**淺色＝丟掉的、深色＝保留的、最淺＝被救回來的**——大部分畫面被刪,只留跟問題有關的證據。

## 結果:刪掉 80% 還能保住約 94% 效果

作者在 Qwen3-VL 系列模型上大規模驗證,從 20 億到 2350 億參數（含密集型與混合專家型 MoE),涵蓋 11 個多模態基準、3 種保留比例：

- 在所有 10 個模型 × 3 種保留比例設定下,F³A 的壓縮後準確度都**高於** FastV、VisionZip、DivPrune、CDPruner 四個對手。
- **只保留 20% 視覺 token 時,平均仍維持滿 token 表現的 93.86%**;在最大的 2350 億模型上同樣達到 93.86%。
- 換個角度看「要多少 token 才能保住 97% 的滿分表現」：F³A 平均只需 **39.9%** 的 token,最強對手要 50.1%。
- 在 30 組「模型×保留比例」配對中全勝對手,雙尾符號檢定 p = 1.9×10⁻⁹（統計上極顯著）。
- 效率上：8B 模型在 20% 保留時,端到端延遲從 354.7ms 降到 274.3ms,KV cache 從 117.7MB 降到 29.0MB,同時仍是同壓縮比下最準的方法。

消融實驗也確認:問題導向的線索、多線索路由、局部鎖定、未覆蓋區救援,每一項都有貢獻,而且在壓縮越狠（40%、20%）時越重要。

## 做不到的地方

幾點值得保留：這是 arXiv 預印本,尚未經同儕審查。論文的核心觀察是「不存在一個放諸四海皆準的保留比例,要多少 token 取決於模型規模與剪枝器保留證據的能力」——也就是說 F³A 的優勢來自更聰明地分配,但「該留多少」本身仍是隨情況變動、需要試的問題。它是免訓練的路由器,主要在 Qwen3-VL 系列上做主實驗（另在 Qwen2.5-VL、InternVL3.5 補測）,跨更多異質架構的普適性仍待更廣驗證。另外,評測靠的是基準分數,壓縮後對「真實長尾使用情境」的影響不會被基準完全反映。

## 怎麼看這件事

**為什麼值得在意?** 多模態大模型的推論成本,很大一塊是被冗長的視覺 token 吃掉的。如果能在不重訓、不改流程的前提下砍掉八成 token 還保住九成多效果,對降低部署成本、縮短延遲是直接有感的——這對想實際用這類模型的人比單純的準確率數字更重要。

**哪裡該保留懷疑?** 這是預印本,且主實驗集中在 Qwen3-VL 一個模型家族。「在基準上全勝」距離「在你的真實應用上同樣穩」之間仍有距離;基準分數無法涵蓋所有使用情境,壓縮帶來的細微資訊損失在某些任務上可能放大。

**怎麼理解這個研究方向?** 它呼應了大模型領域一個越來越清楚的共識:效能由「資源如何分配」決定,而不是單純把某一個軸（模型大小、token 數量）加大。把視覺剪枝從「靜態排名」重新框架成「帶問題的搜尋」,並借用生物覓食的直覺,是這篇在思路上比較有意思的地方。
