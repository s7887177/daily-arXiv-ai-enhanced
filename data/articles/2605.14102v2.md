# 越強大的指揮官，不見得越能打勝仗——AI Agent 評測的反直覺發現

> 原始論文：ChromaFlow: A Negative Ablation Study of Orchestration Overhead in Tool-Augmented Agent Evaluation
> 作者·單位：Tarun Mittal（Octave-X）
> arXiv：2605.14102v2 ・ 分類：cs.AI

一句話說重點：研究者打造了一套能呼叫多種工具的自主 AI Agent 框架「ChromaFlow」，卻在實驗中發現，更積極地加入協調機制、讓系統「更聰明地指揮自己」，反而讓答題正確率下滑、操作噪音增加——多一道管控，不一定比較好。

---

## 背景/問題

現在的大型語言模型（Large Language Model, LLM）已不是單純問答機器。它們被裝上「工具」——可以搜尋網頁、執行程式碼、解析 PDF、操控瀏覽器——變成能規劃、行動、修正的「自主 Agent」。

這類系統的評測通常只看最終答對率。但問題是：**答對率相同的系統，背後可能差很多**。有的高效穩定，有的耗費大量 token、動輒逾時、retry loop 不停，只是「僥倖」答對。這篇論文的核心問題是：加更多協調邏輯（所謂的 orchestration），能讓 Agent 更可靠嗎？

## 怎麼做

研究者建立了 ChromaFlow，一個支援規劃器指揮（planner-directed）執行的自主推理框架，包含：
- **規劃控制層**：負責任務分類、工具路由、可靠性檢查閘
- **執行層**：文件解析、網頁搜尋、Python/shell 執行、多媒體 OCR
- **共享證據狀態**：各工具輸出的中繼事實庫
- **最終回應合成**：整合所有證據產出答案

他們在 GAIA 2023 Level-1 驗證集（53 道題）測試三個配置：

1. **凍結基準**（frozen baseline）：29/53 正確，54.72%
2. **強化協調版**（recovery configuration）：更多重試、更多工具調度 → 27/53，50.94%，但錯誤追蹤、逾時事件、token 用量都上升
3. **嚴格提供者控制版**（strict-provider）：30/53，56.60%，代價是大幅更高的 token 成本

此外進行了兩次 20 題隨機抽樣測試，結果分別是 12/20 和 11/20，顯示小規模評測的不穩定性。

## 結果

最關鍵的發現是一個**負消融（negative ablation）**：把 orchestration 堆得更複雜，不只沒讓正確率變好，還讓整個系統產生更多噪音——更頻繁的錯誤回傳、更多超時事件、更高的推論成本。20 題煙霧測試感覺還不錯，但放到完整 53 題後，結果反轉。

嚴格控制版（strict-provider）雖然比基準多答對一題，但差距只有一題，遠不足以宣稱這是能力提升。

## 做不到的地方

- ChromaFlow 在 GAIA Level-1 的絕對分數並不突出（最佳 56.60%），論文本身也坦承這不是排行榜競賽
- 測試規模小（最多 53 題），統計顯著性有限
- 多次重跑之間存在不一致，令人懷疑結果的重現性
- 嚴格控制版的 token 成本大幅提升，現實部署的經濟性尚未解決

## 圖解

![ChromaFlow 系統架構圖：控制平面、執行平面、共享證據狀態與回應合成四層](assets/articles/2605.14102v2-fig1.webp)

ChromaFlow 的核心結構分為四層。最上層的「任務接收」把題目交給「Optimus 規劃器」，規劃器決定呼叫哪些工具、設定 token 預算與可靠性檢查門；「執行層」的各種工具（文件解析、網頁搜尋、Python、OCR 等）把中間結果寫入「共享證據狀態」；最後由合成器統整所有觀察、正規化答案格式，輸出最終回應。這種設計的目的是讓整個推理過程有跡可循，而不只是看「答對沒有」。

## 想自己判斷這篇可不可信？

| 訊號 | 這篇的情況 | 怎麼解讀 |
|---|---|---|
| 評測題目數量 | 53 題（GAIA Level-1 全集） | 規模偏小，正確率差個位數就能翻轉排名 |
| 隨機性控制 | 有兩次 20 題隨機抽樣，結果不穩定 | 作者誠實揭露，沒有掩蓋不利結果 |
| 是否宣稱 SOTA | 明確說「不是」，論文定位為方法論分析 | 誠實程度加分 |
| 實驗重現性 | 沒公開原始預測與題目，遵守 GAIA 評測誠信規範 | 符合學術慣例，但也讓外人難以驗證細節 |
| 機構背景 | 僅一位作者，機構為「Octave-X」，資訊有限 | 需以更謹慎態度解讀結論 |

## 怎麼看這件事

這篇論文的最大價值不在技術突破，而在**態度**：它誠實地說「我們試了，效果反而變差，這是為什麼」。在 AI 領域，大多數論文只報告成功，失敗幾乎是禁忌。

「Agent 協調越複雜，性能越好」這個直覺並不總是成立。系統越複雜，失效模式也越多——每多一道閘卡、每多一次重試，都可能在某個地方崩潰。這和人類組織管理的教訓如出一轍：中間層越多，不一定辦事越有效率。

對工程師來說，這篇論文提醒我們：評測 AI Agent 時，**除了答對率，還要追蹤 token 消耗、逾時次數、錯誤率、重現性**。一個「省力地答對」的系統，才是真正實用的系統。
