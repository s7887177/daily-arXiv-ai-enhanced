# AI 特工偷偷傳訊息：零寬字元、超音波、亮度——十六條隱蔽通道都被堵死了

> 原始論文：An Application-Layer Multi-Modal Covert-Channel Reference Monitor for LLM Agent Egress
> 作者·單位：Alfredo Metere（Enclawed, LLC，美國加州）
> arXiv：2605.20734v1 ・ 分類：cs.CR・cs.AI

一句話說重點：當一個 AI 代理（LLM agent）被惡意指令操控後，它可以把秘密藏在零寬字元、同形字、音訊超音波，甚至圖片亮度裡偷偷外傳——這篇論文把 16 條這樣的「隱蔽通道」全部列出，並設計了一套量化防禦體系，在完全執行模式下把殘餘容量壓到零。

---

## 問題：允許清單和關鍵字掃描都沒用

企業把 LLM 代理部署到工作流程時，通常會加兩層防護：**目的地允許清單**（只能連特定伺服器）和**內容掃描**（不能夾帶已知敏感字串）。兩層都沒防到的是：一個被「間接提示注入」（indirect prompt injection，即攻擊者把惡意指令藏在代理讀取的網頁或工具結果裡）入侵的代理，可以把秘密藏進看起來完全無害的訊息裡。

這就是資安界從 1973 年以來就知道的**隱蔽通道問題**（covert channel）：不是透過「明顯的傳輸路徑」，而是透過「根本不該用來傳資訊」的管道。

## 有哪些隱蔽通道？

論文整理了 16 條，跨文字、圖片、音訊三種形態：

- **文字類**：在訊息裡插入肉眼不可見的零寬字元（zero-width space）、用外形一樣的西里爾字母替換拉丁字母（同形字 homoglyph）、用空格數量編碼位元、用 JSON 欄位排列順序傳送資料……
- **圖片類**：把位元藏在每個像素的最低有效位元（least-significant bit，LSB），或用一批圖片的平均亮度、排列順序來編碼。
- **音訊類**：用人耳聽不見的超音波（> 20 kHz）傳資料，或把整個位元流「聲化」（sonification）成聽起來像音樂的聲音。

## 防禦架構：一個管道 + 一本容量帳本

論文提出的**出站監視器**（egress reference monitor）有三個核心設計：

1. **文字管道（10 個階段）**：從規範化（刪除不可見字元、同形字正規化）→ 污點追蹤（攔截憑證）→ 熵掃描（量化可能藏了多少位元）→ 噪音注入（打亂空格、標點模式）→ 語義擾亂（同義詞、主被動互換標準化）→ LLM 改寫（整段重新生成，消除字句選擇傳遞的資訊）→ 時序控制（固定速率釋出，讓傳送時間間隔不再受攻擊者控制）。

2. **媒體擾亂器（圖片 + 音訊）**：
   - 圖片：把每個像素的每個 RGB 色頻量化到 64 個等級（6 位元/色頻），讓 LSB 和次 LSB 都無法攜帶資訊，最多每像素改變 2 個顏色值，肉眼不可察。
   - 音訊：做快速傅立葉變換（FFT），清零 20 Hz 以下和 20,000 Hz 以上的所有頻段，以及低於最響頻率一定閾值（感知底限）的音訊，再做逆 FFT。人耳聽到的不變，超音波和隱藏的極微弱音調消失。

3. **開機時的密碼學合法性驗證**：音訊隱蔽通道最難防的是「把位元流聲化成可聽的音調」——這在頻譜上看起來和真正的音樂一樣，任何分類器都會誤判。解法是不分類，改用簽章：每個合法媒體產生者在開機時向審計者取得 Ed25519 私鑰，輸出的每個媒體檔附上簽章。監視器只放行有效簽章的媒體；沒有簽章的一律視為可疑並加以擾亂。

**容量帳本**：監視器對每個出站目的地維護一個「漏桶」（leaky-bucket），熵掃描器測出殘餘隱蔽容量後，帳本決定是否延遲或取消傳送。

## 圖解：音訊擾亂器的頻譜防禦

![論文 Figure 3：三張頻率-強度圖，分別是乾淨音訊（上）、被污染音訊（中）、被擾亂後的輸出（下）。](assets/articles/2605.20734v1-fig1.webp)

三張圖的橫軸是頻率（對數尺度，20 Hz 到 20 kHz），縱軸是強度（分貝，dB）。

- **上圖（藍色，乾淨）**：一個三音和弦（440、554、659 Hz）——三個可見的音峰，其餘都很低。
- **中圖（紅色，污染）**：同一個和弦，但右側出現兩個超音波 BFSK 峰值（21.5 kHz 和 22.5 kHz，各約 -15 dB），還有一個在 5 kHz 的隱藏暗音調（箭頭標示的 sub-perceptual）。這就是攻擊者偷藏資料的地方。
- **下圖（綠色，擾亂後）**：和弦的三個峰值完全保留，但超音波雙峰和 5 kHz 暗音調**消失**了。這一次 FFT 掃除了 1,372 個超出頻段的頻率箱，和 5,792 個低於感知底限的頻率箱。

關鍵：人耳聽到的音樂未被破壞，機器解碼的訊號被抹除。

## 量化結果：做不到的事也說清楚了

- 文字通道在完全執行模式下：所有 11 條通道殘餘容量為 0（Miller-Madow 修正互資訊 = 0）。
- 圖片 LSB 通道：殘餘容量為 0（攻擊者把編碼移到次 LSB 也無效）。
- 音訊通道（超音波 + 次感知）：殘餘容量為 0。
- **唯一無法完全消除的**：每張圖片的平均亮度（mean luminance）通道——把每張圖亮度歸一到同一個值會讓圖片失真。防禦方式是把亮度分成 8 個桶（bucket），把每張圖的容量上限壓到 log₂8 = 3 位元，再配合容量帳本進行速率限制，而不是宣稱「100% 消除」。

這個誠實的界定是論文少見的亮點。

## 做不到的地方

- **攻擊者若已取得執行環境本身的控制權**，監視器就形同虛設——它保護的前提是代理被攻擊但執行環境未被攻陷。
- **LLM 改寫器**增加延遲和成本，且本身也是一個提示注入面——論文用固定提示、把輸入封裝為資料來緩解，但不能完全排除。
- **可聽頻段聲化**是「軍備競賽」，論文只對已測試的 FSK 聲化編碼器宣稱有效，無法保證對所有可能的聲化手法皆如此。
- 文字側管道（大小、排列）需要「常速率釋出」這一層，但這帶來可見的延遲，所以預設關閉。

## 怎麼看這件事

AI 代理正從「只看文字」進化到「同時讀圖、聽音樂、操作工具」。每種新能力都帶來一條新的隱蔽通道。傳統的安全審計問的是「這段輸出有沒有違禁內容」，但一個被入侵的代理問的問題是「這段輸出表面無害，裡面藏了多少位元」——這是兩種完全不同的量。

論文的核心貢獻是把這個問題問清楚了：**隱蔽通道的安全聲明必須是容量聲明，必須用互資訊量化，必須用真實的攻擊編碼器測量**。這套評估框架即使脫離這篇論文的產品，也值得成為業界標準。
