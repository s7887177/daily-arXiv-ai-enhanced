# 用四叉樹讓 AI 看螢幕截圖快 13%：無需重新訓練的 GUI 代理加速術

> 原始論文：AQuaUI: Visual Token Reduction for GUI Agents with Adaptive Quadtrees
> 作者·單位：Yuankai Li、Tinghui Zhu、Ha Min Son、Zhe Zhao、Xin Liu、Muhao Chen（加州大學戴維斯分校）
> arXiv：2605.19260v1 ・ 分類：cs.AI / cs.CV / cs.MA

一句話說重點：介面截圖大片空白、選單規律重複，資訊密度極不均勻；AQuaUI 用自適應四叉樹找出「有東西的地方」，只把那些區域的 token 送進多模態大模型，在保留 99% 效能的前提下，視覺 token 數減少 30%、速度提升 13%，而且完全不需要重新訓練模型。

---

## 問題在哪裡

讓 AI 代理操作電腦介面（GUI agent）需要把螢幕截圖輸入給大型多模態模型（Large Multimodal Model，LMM），而截圖在視覺上有一個關鍵特性：**資訊密度高度不均勻**。空白背景、大片留白、重複的選單列，這些區域佔截圖很大比例，但資訊量極低；真正重要的文字和圖示只集中在小塊區域。

問題是，現有的圖像 token 化方法把截圖切成大小均等的 patch，不管有沒有內容一律送進模型，浪費大量計算資源。更糟的是，GUI 代理在每一步操作後都要重新處理一張新截圖，token 冗餘反覆累積。

## 怎麼做

AQuaUI 的核心是一個**自適應四叉樹（adaptive quadtree）**演算法——這個數據結構常見於電腦圖形學，特別適合處理空間資訊不均勻的情況。

具體流程如下（見下圖）：

1. **截圖輸入** → 建立四叉樹：計算每個區塊的「資訊量分數」S(n)，超過門檻就繼續細分成四個子區塊，直到葉節點。
2. **每個葉節點保留一個代表 token**：均勻空白區域變成大葉節點（一個 token），圖示或文字密集區域變成小葉節點（但每個仍只取一個代表）。
3. **保留空間位置資訊**：確保後續位置編碼一致，不破壞模型對位置的理解。
4. **條件四叉樹精化（Conditional Quadtree Refinement）**：比較相鄰步驟的截圖相似度——「靜態」（幾乎不變）、「位移」（整體偏移）、「替換」（內容變化）——用上一步的四叉樹作為參考，幫助下一步更穩定保留精細區域。

這整個過程在**推斷時**插入，不改模型權重，不需重新訓練。

## 結果

在 GUI-Owl-1.5-32B-Instruct 模型上：
- 視覺 token 減少 **29.52%**
- 推斷速度提升 **13.22%**
- 完整 token 的效能保留 **99.06%**

在 GUI grounding 和多步導航基準（ScreenSpot、GUI-Owl-Bench 等）上，AQuaUI 一致優於現有的 token 壓縮基線（FastV、VisionZip 等），在準確度-效率取捨上更有優勢。

## 做不到的地方

- 截圖資訊量分數 S(n) 的計算方式是 AQuaUI 的核心，但論文對它的設計細節著墨較少，是否適用於所有類型的 GUI（如遊戲、3D 介面、黑暗主題）需要驗證。
- 只在選定的幾個基準測試，若截圖風格差異很大（如高解析度、非標準佈局），效果可能下降。
- 條件四叉樹精化假設相鄰步驟截圖連貫，若代理跳轉頁面幅度很大，這個假設可能不成立。

## 怎麼看這件事

GUI 代理是 AI 代理最具挑戰性的場景之一：它需要在視覺、語言、操作三個層面同時工作。現有方法多半靠更大模型、更多計算換取更好效果；AQuaUI 的切入點是「不多花錢，先把浪費的部分去掉」，方向務實。

不過這類「訓練無關」加速方法的天花板明確：它只能消除冗餘，無法補足模型能力的缺口。對於資訊密集的截圖（如程式碼編輯器、文件頁面），四叉樹節省空間的效果會打折扣。此外，99% 效能保留的數字漂亮，但那 1% 的差距在長多步任務中是否會累積放大，值得更仔細研究。
