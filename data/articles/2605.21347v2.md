# AI Agent 除蟲不靠「抓一隻蟲」，靠讀懂幾千隻蟲共同說了什麼

> 原始論文：Insights Generator: Systematic Corpus-Level Trace Diagnostics for LLM Agents
> 作者·單位：Akshay Manglik、Apaar Shanker、Kaustubh Deshpande 等（Scale AI Research）
> arXiv：2605.21347v2 ・ 分類：cs.AI / cs.LG / cs.SE

一句話說重點：診斷 AI Agent 哪裡出問題，過去是靠工程師一筆一筆看執行紀錄猜原因；這篇論文讓多個 AI Agent 自動分析數千筆紀錄、提出假說、跨整個語料庫驗證，最終生成有證據支撐的診斷報告，讓人類工程師據以改進後性能提升 30%。

---

## 問題：AI Agent 壞掉了，你怎麼知道為什麼？

現在的 AI Agent（執行多步驟任務的 AI，例如寫程式、查資料庫、回覆客服的 AI）是由大型語言模型（LLM）驅動的。它們在執行時會留下**執行軌跡**（trace）——記錄每一步做了什麼、用了哪些工具、輸出了什麼。

問題是，一旦 Agent 在某類任務上表現差，**找到原因非常困難**：

- 每條執行軌跡可能長達數萬個 token（相當於幾百頁文字）
- 線上系統每天產生數千條，不可能一一人工審查
- 問題往往不出現在某一筆軌跡，而是跨多筆才浮現的**系統性模式**

傳統做法是工程師抽查幾十筆、憑直覺猜測、提出假說、試改看看。這個流程慢、有盲點、無法規模化。

## Insights Generator：讓 Agent 審查 Agent

Scale AI 這篇論文提出的 **Insights Generator（IG）** 是一個多 Agent 系統，把診斷過程拆成三個角色：

**1. 偵察兵（Scout Agent）**：從完整語料庫中隨機取樣部分軌跡，生成**候選假說**——例如「模型在需要多步驟計算的問題上常常沒有使用 Python 工具，而是直接口算」。

**2. 調查員（Investigator Agent）**：拿到候選假說後，去**整個語料庫**（所有幾千條軌跡）做統計驗證。它不讀原始軌跡，而是透過 Python 腳本把軌跡轉換成結構化欄位（提取特徵），再做跨群組對比——「有這個問題的軌跡」vs「沒有這個問題的軌跡」，看假說是否成立。

**3. 指揮官（Orchestrator Agent）**：分派任務、彙整結果、去重、生成最終的**洞察報告**。報告包含：問題描述、影響範圍的估計、引用的軌跡片段作為佐證、建議修復方向。

整個流程不需要讀完每一筆軌跡的全文，而是透過 Python 腳本抽取特徵、做統計，保持了可規模化的分析能力。

## 結果有多實用？

論文在多個基準上測試：

- **人類工程師使用 IG 報告改進 Agent 框架**，相比未修改的基線提升了 **30.4 個百分點**
- **寫程式的 AI Agent 使用 IG 洞察**（直接把報告餵進提示詞），在測試集上也有**穩定正向收益**
- 在和其他診斷工具的比較中，IG 的「偵測涵蓋率」相當，但人類專家評估 IG 報告在**深度和證據品質**上表現最好

圖的左側是輸入：分析問題 Q、Schema 快取 S（描述軌跡欄位的結構）、以及完整的軌跡語料庫 C。中間是 Agent 空間：**指揮官**（Orchestrator）掌握全局，負責分派任務和彙整報告；**偵察兵**（Scout）負責從取樣軌跡中生成候選假說集 H；**調查員**（Investigator）負責把假說在語料庫尺度上統計驗證，輸出已確認或已推翻的假說集 H*。最底層是工具層，包括搜尋、特徵提取、群組比較、Python 計算等共用工具。最右側是輸出的報告，包含有證據支撐的發現、干預建議、軌跡引用和普遍性估計。整個流程清楚分工：偵察兵廣撒網找線索，調查員用資料驗假說，指揮官彙整成可行動的報告。

## 做不到的地方

論文承認，IG 的分析品質高度依賴 Schema（描述軌跡欄位的結構化後設資料）的品質——如果軌跡沒有良好的結構化設計，很多特徵提取腳本會失效。此外，IG 自己也是 LLM 驅動的系統，它的診斷報告本身也可能有 AI 幻覺問題，論文建議仍需人類最終判斷。評估方式也依賴人工打分，難以完全自動化。

## 怎麼看這件事

AI Agent 的部署規模越來越大，但「怎麼知道 Agent 系統性地在哪裡失敗」一直是黑盒問題。這篇論文提出了一個讓 Agent 自己診斷自己的閉環架構，實用性顯而易見。

但有一個值得思考的隱憂：如果診斷工具本身也是 LLM，那誰來診斷診斷工具？「偵察兵提出的假說可能有偏見」、「調查員可能錯誤解讀統計」——這些風險論文承認了但沒有系統性解決。未來若要在高風險系統上使用，人工審查仍是不可省略的。

從更宏觀的角度看，這篇論文代表的趨勢是：隨著 AI Agent 滲透軟體開發流程，**AI 測試和 AI 除錯本身也會逐漸 AI 化**。這是一個自指性很強的方向，充滿潛力，也充滿需要小心的地方。
