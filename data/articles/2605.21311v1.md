# AI 同時設計斑馬線位置和調整紅綠燈時序，讓行人等待少了 79%

> 原始論文：DeCoR: Design and Control Co-Optimization for Urban Streets Using Reinforcement Learning
> 作者·單位：Bibek Poudel、Lei Zhu、Kevin Heaslip、Sai Swaminathan、Weizi Li（田納西大學、北卡大學夏洛特分校）
> arXiv：2605.21311v1 ・ 分類：cs.LG / cs.AI

一句話說重點：一套強化學習框架讓 AI 同時決定「要在哪裡畫斑馬線、畫多寬」和「紅綠燈要怎麼調」，在真實的 750 公尺城市走廊上，行人等待時間減少 79%，車輛減少 65%，而且使用的斑馬線比現有設計還少。

---

## 背景：城市設計和交通控制，兩件事從來沒一起優化過

城市街道有兩個獨立的設計問題：

1. **基礎設施設計**：斑馬線要蓋在哪裡？幾條？多寬？這通常由城市規劃師在建設階段決定，一旦蓋好就很難改。
2. **動態交通控制**：紅綠燈要怎麼調？每個路口的行人燈和車輛燈要開多久？這由交通管理中心即時決定。

這兩件事過去幾乎總是**分開優化**：先規劃好基礎設施，再在固定的基礎設施上優化交通控制。但這樣做有一個根本問題：一個斑馬線位置很糟糕的設計，即使紅綠燈調到最好，還是沒辦法讓行人舒服走路。反過來，最優化的基礎設施如果配上呆板的固定時序紅綠燈，也大打折扣。

**為什麼不能同時一起優化？** 一方面因為問題空間太大（要搜尋的設計組合太多），另一方面傳統方法缺乏把這兩層連結起來的機制。

## DeCoR 怎麼解：兩個強化學習 Agent 分工合作

**DeCoR**（Design and Control Co-Optimization with Reinforcement Learning）把問題分成兩個學習階段，但讓兩個 Agent 共享反饋：

### 第一階段：設計 Agent（斑馬線在哪裡？多寬？）

設計 Agent 把整個行人路網表示成一個**圖**（Graph）：交叉路口是節點，街道是邊，每個節點和邊帶有特徵（路寬、流量等）。Agent 用**圖注意力網路**（Graph Attention Network）讀懂這個圖，然後輸出一個**高斯混合模型**（Gaussian Mixture Model，GMM）——這個機率分布描述「在哪個位置、放多寬的斑馬線」的可能性。每個訓練回合從這個分布裡取樣出一組斑馬線配置。

### 第二階段：控制 Agent（紅綠燈怎麼調？）

對於每個斑馬線配置，控制 Agent 在 SUMO（一個開源交通模擬器）裡跑 N 個並行環境，接收行人和車輛的即時狀態，輸出每個路口的信號燈時序。目標是最小化行人和車輛的合計等待時間。

### 雙向回饋連結

每個回合結束後，兩種獎勵都被計算：「控制獎勵」告訴控制 Agent 信號調得好不好；「設計獎勵」（即控制 Agent 優化後的整體等待時間）告訴設計 Agent 這次的斑馬線配置整體上是好是壞。設計 Agent 根據這個信號更新策略，傾向於生成那些讓控制更有效的斑馬線佈局。

## 在真實走廊上的結果

測試場景是美國一段 **750 公尺的真實城市走廊**，行人流量資料來自路口攝影機和 Wi-Fi 訊號的人流統計：

- **行人到達最近斑馬線的走路時間**：減少 **23%**（相比現有配置）
- **行人等待時間**：相對固定時序減少 **79%**
- **車輛等待時間**：相對固定時序減少 **65%**
- 使用的斑馬線數量比現有設計**還少**

圖分兩個大方塊。上方的 **Design** 部分：左側是行人路網圖 G（節點和邊代表路口和街道），輸入節點特徵 X 和邊特徵 Z，經過圖注意力（Graph Attention）得到節點嵌入 H，再由 Actor-Critic 架構輸出參數化高斯混合模型（Density surface over Location × Width），從中取樣出新斑馬線（藍色點）加入路網，得到更新後的圖 G'。下方的 **Control** 部分：G' 加上真實世界的需求資料（影片和 Wi-Fi 偵測），在 SUMO 模擬中的 N 個並行環境（Env 1 到 Env N）裡，控制 Agent 接收行人和車輛的觀察（Observation），輸出信號時序動作（Action），獲得控制獎勵（Control Reward）。回合結束後的旅行時間指標向上回饋給設計階段，形成閉環優化。

## 做不到的地方

論文坦承目前只在單一走廊場景測試，控制政策是針對特定流量訓練的（雖然論文顯示對訓練外流量有一定泛化能力）。斑馬線設計學習的是「連續位置」，實際施工的限制（如地下管線、現有路口設施）沒有納入模型。模擬器和現實世界的落差（Sim-to-Real Gap）也是已知但未解的問題。

## 怎麼看這件事

城市規劃有一個長期的分工問題：基礎設施工程師和交通運營部門是兩個不同的職能，往往缺乏對話。DeCoR 的技術貢獻是提供了一個讓兩者在同一框架裡共同優化的方法，學術上有意義。

更有趣的是它揭示的設計洞察：「AI 自己設計的斑馬線比城市規劃師的少，但行人等待時間更短」——這暗示我們對「多放幾個斑馬線就更好」的直覺可能是錯的，位置比數量更重要。但這個結論只在一個地點成立，需要更多真實場景驗證才能成為通則。

從更大的視角看，這是「AI 輔助城市設計」這個方向的一個早期嘗試——讓資料和強化學習參與到過去純由專業規劃師主導的決策。技術可行性這篇論文做了示範，但政治可行性（誰會相信 AI 設計的斑馬線？）是完全不同的問題。
