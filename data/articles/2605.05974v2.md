# 給 AI 代理的提示詞上鎖：PragLocker 讓提示詞只能在特定模型上用

> 原始論文：PragLocker: Protecting Agent Intellectual Property in Untrusted Deployments via Non-Portable Prompts
> 作者·單位：Qinfeng Li、Yuntai Bao、Jianghui Hu、Wenqi Zhang、Jintao Chen、Huifeng Zhu、Yier Jin、Xuhong Zhang（浙江大學；佛羅里達大學；螞蟻集團）
> arXiv：2605.05974v2 ・ 分類：cs.CR / cs.AI

一句話說重點：PragLocker 把有價值的 AI 代理提示詞混淆成只有目標模型才能正確理解的形式，讓攻擊者即使竊取到提示詞，也無法把它搬到其他大型語言模型上使用。

---

## 問題背景：精心設計的 AI 代理提示詞是真實的智慧財產

大型語言模型（LLM）本身只是基礎能力，讓它真正有用的是**提示詞（Prompt）**：系統提示詞定義了代理的任務規則、工具使用方式、回答格式、以及各種行為約束。一個在客服、醫療、法律等高價值場景中表現出色的代理，其背後精心調教的提示詞可能花費了大量時間和專業知識。

問題是：在不受信任的部署環境中（例如第三方雲端服務、共享推理平台），攻擊者可以：
1. 透過大量查詢、上下文注入、成員推斷等方式**竊取提示詞**
2. 把竊取到的提示詞**直接搬到其他（可能更便宜或未授權的）LLM**，完整復現代理功能
3. 開發者既無法追責，也無法阻止

現有的防護方法（提示詞浮水印、加密儲存）都有根本缺陷：加密只保護傳輸過程，推理時必須解密；浮水印可偵測竊取但無法阻止使用。

## 怎麼做：讓提示詞和目標模型的「神經網路個性」綁定

**PragLocker** 的核心洞察：**讓混淆後的提示詞只在目標 LLM 的特定激活空間中有效**，而對其他模型而言則是雜訊或語義損壞的文本。

**兩階段流程（見圖）**：

**第一階段：提示詞初始化（語意錨定）**

用**領域特定語言（DSL）編碼器**把自然語言提示詞轉換成「代碼符號形式」（Code-Symbol Form）。這種轉換保留語義，但把提示詞改寫成類似程式碼的結構（使用特殊符號、非自然語言詞彙），讓它在視覺上不可讀，但在目標 LLM 的 token 解析下仍能保留原始功能。此階段在目標 LLM 以外的模型上「不夠好」——這是第二階段的起點。

**第二階段：黑盒混淆調優（注入噪聲）**

用**隨機搜索（RS）**在混淆後的提示詞中注入字符級噪聲，目標函數三項：
- **任務損失**（L_task）：在目標 LLM 上仍然能完成預設任務
- **距離損失**（L_dist）：混淆後的提示詞和原始提示詞距離盡可能大（避免語義恢復）
- **非語言偏差**（L_non-lang）：讓文字的字符熵盡量高（避免語義可讀）

整個優化只需要目標 LLM 的 API 輸出，**不需要存取模型參數**（真正的黑盒攻擊模型）。

優化完成後的「最終混淆提示詞」：
- 在目標 LLM 上仍能正常執行代理任務
- 在其他 LLM 上無法使用（可移植性低）
- 人類無法直接理解（語義不透明）

## 結果：跨模型可移植性大幅降低，目標模型效能幾乎不損失

在多種代理系統（LexiAgent、ReadAgent、LoCoMo、DueSum）、多個資料集、多種 LLM（GPT-4o、Gemini-2、GPT-4o-mini、DeepSeek）上：

- **不加保護時**：提示詞在跨 LLM 可移植性（Mean Portability Loss）約為 0.2（即 80% 的效能可移植）
- **PragLocker 保護後**：Mean Portability Loss 達到 **0.82+**，大幅接近完全不可移植（1.0）
- **對目標 LLM 的性能保留**：PragLocker 代理在目標 LLM 上的性能接近原始提示詞（性能保留率 ≈ 0.99）
- **對抗自適應攻擊者**：即使攻擊者知道保護方案並針對性調整，可移植性仍顯著低於基線

## 做不到的地方

- PragLocker 只保護提示詞**不被搬到其他模型**，並不阻止攻擊者在**同一目標模型**上使用竊取到的提示詞
- 混淆後的提示詞可能讓代理在面對**未見分布的指令**時更脆弱
- 若攻擊者能夠存取**目標 LLM 的參數**（白盒攻擊），混淆的阻力會大幅降低
- 對目標模型版本升級的魯棒性未測試——廠商更新模型後，已混淆的提示詞是否仍有效？

## 想自己判斷這篇可不可信？

| 訊號 | 這篇的情況 | 怎麼解讀 |
|---|---|---|
| 威脅模型 | 明確定義攻擊者能力（API 存取、無模型參數） | 邊界條件清晰，結論範圍可信 |
| 評測涵蓋 | 4 種代理系統、5 種 LLM、多個資料集 | 不依賴單一模型的特殊性質 |
| 自適應攻擊測試 | 有（攻擊者知道方案後的對策） | 誠實測試最難情形 |
| 侷限透明度 | 明確承認白盒攻擊和同模型重用的問題 | 可信度高 |
| 開源 | 未提及 | 需自行聯繫 |

## 怎麼看這件事

隨著 AI 代理在各行各業的商業化，「提示詞工程」正在成為一種新型知識產權。PragLocker 提出的思路——讓提示詞的有效性和特定模型的神經網路特性綁定——是一個有創意的保護機制，填補了現有加密/浮水印方案的空白。但這也是一場軍備競賽的開始：隨著攻擊者技術提升（如更精密的模型提取、轉移學習），保護機制需要持續演化。從更廣的視角看，這個問題還會隨著開放權重模型（Open-Weight Models）的普及而更加複雜——當攻擊者可以完全存取模型時，純黑盒保護的前提就不再成立。
