# 網頁AI助手能選對日期嗎？這個基準用真實網站考驗最強模型

> 原始論文：WARC-Bench: Web Archive Based Benchmark for GUI Subtask Executions
> 作者·單位：Sanjari Srivastava、Gang Li、Cheng Chang、Rishu Garg、Manpreet Kaur、Charlene Y. Lee 等 10 位作者（Salesforce AI Research）
> arXiv：2510.09872v2 ・ 分類：cs.LG / cs.AI

一句話說重點：WARC-Bench 把 23 個真實網站封存成可重播的測試場景，用 438 個子任務考驗 AI 代理能否正確操作下拉選單、日期選取器、滾動容器等日常 UI 元件——目前最強模型成功率僅 64.8%。

---

## 背景：AI 代理學會「瀏覽網頁」，但日常小動作仍是難關

讓 AI 代理自動完成「幫我訂機票」、「把這個選項改成月結付款」這類任務，是近年「電腦使用（computer use）」研究的核心目標。這類任務往往需要 AI 在真實網頁上執行一連串動作：點擊、輸入、滾動、選擇——看起來簡單，但稍有不慎就會出錯。

現有的網頁代理基準（如 WebArena、WorkArena）主要評估長任務（multi-step planning），即「完成一個目標需要做 10 步以上的動作」。但這些基準很少深入評估**子任務（subtask）**：那些短而精確的 UI 互動——例如「在日期選取器中選 3 月 21 日」、「在下拉選單中選擇正確城市」。若 AI 在子任務上就出錯，長任務計畫再完美也是白費。

更大的問題是：現有基準大多使用靜態快照或簡化的模擬網站，無法捕捉真實網頁的動態性（CSS 動畫、JavaScript 事件、跨頁導航）。

## 怎麼做：把真實網站「封存」成可重播的沙盒

**WARC-Bench**（Web Archive Benchmark）的核心創新是使用 **Web ARChive（WARC）格式**——一種可以把整個網頁（包含 HTML、CSS、JavaScript、圖片）凍結存檔的格式——來創建可重播的互動沙盒。

這讓評估具有三個關鍵優點：
1. **真實性**：測試環境是真正的 airbnb、GitHub、Zendesk 等網站的動態頁面，不是簡化的模擬
2. **可重現性**：每次測試在完全相同的初始狀態下開始
3. **可擴展性**：任何人都可以把新網站封存加入基準

**438 個任務**涵蓋 23 個真實網站，分 15 個子任務類別：
- **日期選取（Date Picker）**：選正確的出發日期
- **滾動（Scroll）**：在容器內滾動找到特定項目
- **下拉選單（Dropdown）**：選擇正確選項
- **拖放（Drag and Drop）**：排序、移動元素
- 以及更多表單互動、多步驟 UI 操作...

評估採用 **JavaScript 驗證函數**：每個任務有一段 JS 程式碼，直接查詢 DOM 狀態確認任務是否完成（Reward=1/0）。這讓評估完全自動化且客觀。

**訓練提升**：論文還探索了兩種改善開源模型的方法——**監督微調（SFT）**和**從可驗證獎勵的強化學習（RLVR）**。從一個 72B 開源模型出發，SFT 後成功率達 48.8%，在稀疏資料條件下再加 RLVR 提升至 **52.8%**，超越許多前沿閉源模型。

## 結果：連最強模型也只過六成，子任務是真實難關

在主要結果（Table 2）中：

- 最好的前沿閉源模型（**Claude Sonnet 4.0**）成功率僅 **64.8%**——三分之一的子任務仍然失敗
- GPT-4.5、Qwen2.5-VL-72B 的成功率在 48～61% 之間
- 開源模型若不微調，成功率多在 17～51% 區間
- RLVR 對資料稀少的場景特別有效，與僅用 SFT 相比提升達 4 個百分點

子任務類別分析顯示（Table 3）：
- **表格操作（Table）**和**多步驟序列**是最難的類別，成功率常低於 30%
- **基本點擊**類任務成功率相對高，但仍不到 80%

## 做不到的地方

- 438 個任務雖然種類多元，但每個類別的樣本數量有限，可能不足以捕捉所有 UI 設計模式的多樣性。
- WARC 封存是靜態時間點的快照，若真實網站設計更新，封存版本可能與現有網站不一致。
- 評估仍侷限於孤立子任務，未測試「把多個子任務串接成長任務」時的累積失敗效應。
- RLVR 訓練需要二元可驗證獎勵（成功/失敗），對於「部分正確」的任務（如日期選對了月份但年份錯了），這種稀疏獎勵可能訓練效率低。

## 想自己判斷這篇可不可信？

| 訊號 | 這篇的情況 | 怎麼解讀 |
|---|---|---|
| 評估客觀性 | JavaScript 函數直接查詢 DOM 狀態，完全自動化評估 | 不依賴 LLM 自評或人類主觀評分 |
| 模型多樣性 | 測試 8 個模型包含閉源（Claude、GPT）和開源（Qwen、Llama）| 結論不是針對特定模型調優的 |
| 資料集公開 | 基準網站公開於 GitHub，可以下載驗證 | 可重現 |
| 訓練實驗透明度 | 詳細報告 SFT 和 RLVR 的設定、資料量和超參數 | 可以重現訓練結果 |
| 失敗分析 | 按任務類別細分成功率，並分析 RLVR 改善的機制 | 不只報告總分，有深度分析 |

## 怎麼看這件事

我們評估 AI 代理「是否能用電腦」的方式，決定了我們改進它的方向。WARC-Bench 的貢獻是把「短程精確 UI 操作」這個長期被忽視的能力放到聚光燈下，用真實網站告訴我們：即使是當今最強的模型，完成「選正確日期」這麼基礎的任務，成功率也只有約六成。對於真正想把 AI 代理部署到生產環境的工程師，這個數字是一個清醒的提醒：在能做大事之前，先學好小事。
