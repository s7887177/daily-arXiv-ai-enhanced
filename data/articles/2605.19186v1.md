# AI 代理人查資料庫前，得先搞清楚「這個資料庫對我有用嗎」

> 原始論文：Discoverable Agent Knowledge — A Formal Framework for Agentic KG Affordances (Extended Version)
> 作者·單位：Terry R. Payne、Valentina Tamma（利物浦大學）；Enrico Daga（公開大學 Milton Keynes）
> arXiv：2605.19186v1 ・ 分類：cs.AI

一句話說重點：當 AI 代理人要查詢知識圖譜（knowledge graph，簡稱 KG）前，現有的資料庫描述標準只告訴它「裡面有什麼」，卻無法告訴它「我能從這裡得出什麼可靠結論」——這篇論文提出了一個四維框架來填補這個空缺。

---

## 背景：AI 代理人查知識圖譜，會做出「沒依據的結論」

想像一個負責回答醫療問題的 AI 代理人，它需要從多個知識圖譜中查資料來完成任務。問題是：目前描述知識圖譜的標準（如 VoID 和 DCAT）就像圖書館目錄，只列了「館藏有哪些書」，卻沒說：

- 這個資料庫的推論引擎支援哪種邏輯？（我問「所有子類的屬性」，它能回答嗎？）
- 查不到結果是因為「確定沒有」還是因為「資料不完整」？
- 我用「ICD-10 代碼」的詞彙去查，這個資料庫能理解嗎？

不知道這些，AI 代理人就可能把「查無資料」誤解為「確定不存在」，或者用不相容的詞彙查詢卻毫不知情——在法律或醫療場景中，這種無聲的失敗可能釀成嚴重後果。

## 怎麼做：四個維度定義「對我有用的程度」

研究者提出 **AAP（Agentic Affordance Profile，代理人可用性剖面）** 框架，從四個維度描述「一個特定代理人對一個特定任務，能從這個 KG 得到什麼」：

**1. 語意表達能力（Semantic Expressivity，E）**：這個資料庫的本體論（ontology，定義概念和關係的「字典」）是用什麼描述邏輯（description logic，DL）寫的？支援 OWL-QL（允許高效查詢重寫）還是更受限的 RDFS？這決定了代理人能做什麼推論。

**2. 任務相對性基礎（Task-Relative Grounding，G）**：代理人用來提問的詞彙，是否能在資料庫的本體論中找到對應？若代理人用 SNOMED-CT 術語問問題，但資料庫用的是完全不同的醫學詞彙，就算查到了也沒意義。

**3. 推理一致性範疇（Reasoning Consistency Scope，R）**：資料庫宣稱支援的推論引擎，與它實際運行的有多大差異？若宣稱支援 OWL 2 DL 但實際只跑 RDFS，代理人可能對「查無結果」做出錯誤的封閉世界假設。

**4. 代理人可發現性（Agentic Discoverability，D）**：僅憑資料庫的 metadata（不實際查詢資料），代理人能多快確認這個資料庫適不適合這個任務？越高代表可在規劃階段就做出決策，不需要「試查」。

這四個維度最終匯入一個**任務可行性謂詞**：任務詞彙完全有基礎（G=1）且推論引擎至少符合任務最低要求（R ≥ 所需）。

## 結果：以「學術論文查詢」工作示範三種 KG 的命運

論文用一個學術搜尋任務（找有關機器學習與醫學影像的論文）作為具體例子，分析三個表面上「都可以查學術文獻」的知識圖譜：

- **KG₁（OWL 2 DL，完整 AAP）**：詞彙完全對應，推論引擎符合，可發現性高 → 可行
- **KG₂（RDFS，無閉包宣告）**：G 分數高，但 R 不足，代理人無法信任「查無結果」→ 需要調解器
- **KG₃（僅 SPARQL 端點，無 metadata）**：可發現性為零，代理人必須花成本試查才能判斷適用性 → 可行性不確定

這個例子展示了 AAP 的核心價值：**在任務規劃階段就做出理性的資源選擇決策**，而不是等到查詢失敗才發現資料庫不合適。

## 做不到的地方

這篇論文是**理論框架提案**，不是已實作的系統：

- **沒有計算實作**：四個維度的評分方法目前只有概念定義，作者自己也說還需要解決計算複雜度問題（評估語意對齊的計算開銷可能很高）。
- **需要共享任務本體論**：整個框架依賴代理人和資料庫共享一個「任務類型詞彙表」，而建立這套詞彙表本身就是個未解決的研究問題。
- **規模化挑戰未知**：在有成百上千個知識圖譜的真實 Web 環境中，如何有效率地進行 AAP 匹配，論文留給未來工作。
- **五點研究議程都是開放問題**，論文誠實地標記為「待解決」：本體論形式化、計算可行性、組合語意、知識服務規格，以及工程整合。

## 怎麼看這件事

這篇論文做的是「語意 Web 服務的老問題在新場景下的復活」——二十年前 OWL-S 和 WSMO 試圖解決的「代理人如何理性地選擇和組合 Web 服務」，今天換上了 LLM 代理人和知識圖譜的外衣，問題本質完全相同。

研究者的觀察很敏銳：現在每家 AI 代理人框架（LangChain、LlamaIndex 等）查 KG 時，大多是「試查看看」，沒有任何正式的適用性評估機制。一個設計用來查詢 WikiData 的代理人，直接去查 Gene Ontology 是否能得到有意義的結論？現在沒人知道——因為元數據根本不包含這類資訊。

AAP 框架提供了一個語言，可以讓 KG 發布者說清楚「我的資料庫對哪類代理人、哪類任務有用、在什麼條件下有用」。但從框架到標準到廣泛採用，是一條漫長的路，而且歷史上語意 Web 的野心計畫屢屢遭遇「好理論、難落地」的命運。這篇論文的貢獻在於清晰地定義了問題空間，後續能否實現，取決於整個社群是否願意投入那五點未解決的研究議程。
