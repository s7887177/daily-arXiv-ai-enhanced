# 一個 API 優化所有事：LLM 搜尋引擎的萬能鑰匙

> 原始論文：optimize_anything: A Universal API for Optimizing any Text Parameter
> 作者·單位：Lakshya A Agrawal、Donghyun Lee、Shangyin Tan 等（UC Berkeley、MIT）
> arXiv：2605.19633v1 ・ 分類：cs.CL / cs.AI

一句話說重點：把任何優化問題轉成「改進一段文字」，讓 LLM 反覆改寫、評分函數評判，這個極簡框架在 CUDA 核心、雲端排程、ARC-AGI 智能體等六個完全不同的領域都達到了業界頂尖水準。

---

## 優化問題的共同語言

「讓這段 CUDA 代碼跑得更快」「找一個排程策略讓雲端費用最低」「設計一個能解 ARC-AGI 謎題的 AI 智能體架構」——這三件事看起來風馬牛不相及，但這篇論文發現了一個共同點：**它們都可以被表述為「改進一段文字，直到評分函數對它打出更高分」**。

CUDA 核心是一段程式碼字串；排程策略是一段描述規則的文字；AI 智能體架構是一段設定；甚至 SVG 圖片也是文字。只要能把它序列化成字串，就能讓 LLM 當優化器。

## optimize_anything 的極簡框架

系統只有一個核心循環：

1. **給出一個「文字 artifact」**（初始解，或直接提一個目標）
2. **評分函數評估它**，回傳分數和「副訊息（Side Information，SI）**——不只是數字，還包括「為什麼這個分數？哪裡出問題了？」
3. **LLM 智能提案者**讀取分數和副訊息，生成一個改良版本
4. **重複**，直到滿意

副訊息是這個框架的關鍵差異點。純給分數是一個非常稀疏的學習訊號；告訴 LLM「你的 CUDA 核心在 warp shuffle reduction 步驟上發生了記憶體溢出，profiler 顯示這裡耗時佔 70%」，LLM 能跳過無效探索，直接針對性修正。

消融實驗顯示，有副訊息的版本比只有分數的版本**快 4–6 倍收斂**，最終表現也顯著更高。

## 六個完全不同的任務，一樣的 API

論文在六個領域做了實驗：

- **ARC-AGI 智能體架構搜尋**：Gemini Flash 的 ARC-AGI 準確率從 32.5% 提升到 **89.5%**（接近三倍）
- **雲端排程策略**：探索出的策略在 CloudCast 基準上節省了 **40.2%** 的雲端費用
- **CUDA 核心生成**：在 KernelBench 上，**87%** 生成的核心達到或超越 PyTorch 基線性能
- **ARC-AGI 提示優化**：GPT-4.1-mini 的 AIME-2025 準確率從 46.67% 提升到 60.00%
- **圓形填充（數學最優化）**：n=26 的解優於 AlphaEvolve 的公開結果（2.63598 vs. 2.60+）
- **設施支援分析（NLP）**：提示優化也在這類文字任務上有效

## 多任務模式的加成

除了單任務搜尋，系統還支援**多任務搜尋**：把一批類似問題一起丟進去優化，讓不同問題發現的技巧互相轉移。

在 KernelBench 上，多任務模式比獨立優化每個核心的效果更好——在相同的評估次數（預算）下，多任務模式跨核心轉移了更有效的優化模式（如記憶體對齊技巧、warp 減少策略），讓整體品質提升。好發現不需要重複發現。

## 做不到的地方

- 評分函數需要人工設計，對複雜問題的評分本身就是難題（例如：什麼叫做「更好的 AI 智能體架構」？）
- 副訊息設計需要領域知識，不同領域需要不同診斷資訊，「通用性」部分轉移到了 SI 設計上
- ARC-AGI 的 89.5% 數字很驚人，但 ARC-AGI 本身的版本和評估細節需要仔細核對，和公開排行榜比較時需留意
- 多任務模式的遷移效果依賴任務之間的相似性；差異太大的任務組合未必有收益

## 怎麼看這件事

這篇論文的核心主張是：**LLM 加評分函數，是一個通用問題解決器**，不只適合提示工程，而是適合任何可以被表述為「改進文字」的優化問題。這個主張有強力的實驗支持。

對 AI 從業者來說，這指向一個很實際的工具——下次你有一個可以量化評估、但不知道怎麼系統性改進的問題時，值得試試把它套進這個框架。副訊息的設計（你給 LLM 什麼反饋）是決定效果的關鍵，比選哪個模型更重要。
