# AI 看第一人稱影片很慢？這篇用「事件相機」當外掛幫它砍掉八成沒用的畫素

> 原始論文：EventPrune: Cascaded Event-Assisted Token Pruning for Efficient First-Person Dynamic Spatial Reasoning
> 作者·單位：Pengtao Ma、Ziliang Zhou 等（清華大學深圳國際研究生院、哈工大、香港大學）
> arXiv：2605.19506v1 ・ 分類：電腦視覺

一句話說重點：當你要讓 AI 處理頭戴攝影機的第一人稱影片（例如室內導航或穿戴式 AR），畫面 token 太多算不動是老問題；研究者發現可以借助一種叫「事件相機」的特殊感測器當輔助訊號，**砍掉 80% 的視覺 token 還能比不砍時更準**，推理速度快 1.89 倍。

---

## 背景／問題：影片大模型很慢，但「動態空間推理」根本經不起慢

近兩年的 Video-LLM（能看影片的多模態大模型，例如 Qwen2.5-VL、LLaVA-OneVision）越做越強，但在「第一人稱動態空間推理」這種應用上有個老問題：**計算量太大跟不上即時需求**。

舉個具體例子：你戴著智慧眼鏡走在房間，眼鏡上的 AI 要回答「沙發離電視多遠？」這類問題。模型需要從一段影片裡同時掌握「相機本身在動」、「物體幾何結構不變」、「物體之間的相對位置」三件事。但因為 Transformer 的注意力複雜度是 token 數的平方，輸入幾秒鐘的高解析度影片就會爆炸。

業界既有的做法是**訓練免費的 token 剪枝**（training-free token pruning）：在不重新訓練模型的前提下，找出「不重要的視覺 token」直接丟掉。但作者指出現有方法有兩個致命缺陷：

- **跨影格剪枝**靠比較像素差或特徵相似度——速度慢，且抓不到速度、軌跡這類連續動態。
- **單影格內剪枝**靠注意力分數選 token——但作者發現一個有趣的偏見：**注意力會異常集中在畫面邊緣**（Fig. 3 顯示），結果中央的關鍵物體常常被剪掉。

## 怎麼做：請事件相機當「外部顧問」

作者提出的 **EventPrune**（論文裡叫 ECP, Event Cascade Pruning）核心想法很特別：**借用一種叫「事件相機」（event camera）的硬體訊號當作外部先驗**。

事件相機是仿生感測器，跟普通相機不同——它不是每秒拍 30 張完整畫面，而是**只在每個畫素的亮度變化時才產生一個事件**，具有微秒級時間解析度。這給了兩個天然優勢：

- **跨影格**：哪些影格有真正的動作變化，事件密度可以直接告訴你，不需要拿像素去比對。
- **單影格內**：哪些區域有邊緣與紋理（也就是有「結構」），事件分佈會自然標出來——這正是注意力會忽略的地方。

EventPrune 把這兩個訊號串成三個級聯模組：

**1. ETCS（事件觸發因果採樣）**：根據事件活躍度找出真正包含動作變化的關鍵影格，丟掉時間上多餘的影格。

**2. EMSF（事件導引動作顯著性過濾）**：把事件密度做成「動作顯著圖」，靜止區域的 token 直接丟掉。

**3. EARF（事件—注意力排名對齊融合）**：把模型內部注意力分數與事件顯著性做「排名融合」，校正前面提到的「注意力集中在邊緣」這個偏見。**重點是這個融合在 Transformer 的不同層用不同權重**——淺層偏重幾何結構保留，深層偏重語意保留。

![EventPrune 三階段架構：左側 ETCS 透過事件活躍度時序圖（柱狀曲線）挑選關鍵影格；中央 EMSF 把非同步事件投影成動作顯著圖，據此過濾靜態區域的 token；右側 EARF 在 Transformer 的淺、中、深三層分別把事件顯著性與注意力做排名對齊融合，產生最終要保留的 token。](assets/articles/2605.19506v1-fig1.webp)

圖中可以看到完整的「時間—空間—表徵」三層剪枝流程。注意右側三層架構不是隨意設計——作者觀察到淺層需要「修正偏見」、中層保留「物理結構」、深層保留「語意」，每層的融合權重都不同。下方圖示說明保留的 token 同時涵蓋影像、文字與系統 token。

## 結果

在常用的第一人稱空間推理基準上：

- **保留 20% token 的情況下**，ECP 仍能達到 37.62% 準確率，**比保留 100% token 的基線（36.31%）還高**——這代表「砍對 token」反而能減少干擾。
- **推理速度提升 1.89 倍**，GFLOPs 減少 52%。
- 在作者新建的 **ESR-Real**（第一個真實 RGB-事件第一人稱空間推理基準，超過 700 組 QA 跨 6 種類別）上，保留 50% token 時準確率比全 token 基線高 2.68 個百分點。

## 做不到 / 沒解決的

- **依賴事件相機硬體**：這套方法的前提是你有事件相機資料。雖然事件相機在學術圈與工業圈越來越普及，但消費級設備幾乎不配備。作者沒給出「用 RGB 模擬事件訊號」當替代方案的詳細比較。
- **訓練免費但不通用**：所謂 training-free 是指不需要重新訓練 Video-LLM，但這套剪枝流程的超參數（每層融合權重、各階段保留比例）需要針對特定 Video-LLM 與任務調整。
- **長影片仍是挑戰**：論文示例多半是幾秒鐘的場景。要應用到分鐘級的連續第一人稱影片（例如監視器、第一人稱遊戲串流），跨更長時間視窗的事件累積策略沒有討論。
- **能耗未討論**：事件相機本身耗電低，但增加事件處理流程後整體能耗會不會反而升高，論文沒給出數據。

## 怎麼看這件事

**為什麼在意？** 「眼前看到的世界」這類即時空間理解任務是 AR/VR、機器人、自駕車等所有具身 AI（embodied AI）的基礎。但現在的 Video-LLM 太重，根本跑不到手錶、眼鏡這種裝置上。如果靠事件相機這種便宜（單顆十幾美元）且省電的感測器就能讓推理快兩倍、準確率不降，這對邊緣裝置的實用性是大利多。

**哪裡該保留懷疑？** 「保留 20% token 還比 100% 高」這種結論最容易引起質疑——它依賴於「現有方法注意力分數有偏見」這個假設，如果未來 Video-LLM 改善了這個偏見，事件相機的優勢可能就會縮小。另外，ESR-Real 是作者自己建的基準，自家基準上表現好不算完全中立評估。

**怎麼理解這個方向？** 這篇代表「多感測器融合」在 AI 推理階段的新趨勢。過去多感測器融合主要用於訓練（讓模型同時看 RGB + 深度 + 雷射），這篇則是在**推理階段**用事件相機當「外部仲裁」——這個思路可能延伸到其他輔助訊號：IMU、麥克風、深度感測器等。當大模型推不動時，硬體層的協同往往比軟體優化還有效率。
