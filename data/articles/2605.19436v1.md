# 教 AI 數學推理時別「亂發獎」:同樣是答對,「真正關鍵的那一步」該領更多獎金

> 原始論文:CEPO: RLVR Self-Distillation using Contrastive Evidence Policy Optimization
> 作者·單位:Ahmed Heakl、Abdelrahman M. Shaker、Youssef Mohamed、Rania Elbadry、Omar Fetouh、Salman Khan(阿聯穆罕默德·本·扎耶德人工智慧大學 MBZUAI);Fahad Shahbaz Khan(瑞典林雪平大學);Salman Khan(澳洲國立大學)
> arXiv:2605.19436v1 ・ 分類:cs.LG、cs.CL、cs.CV 機器學習・自然語言・電腦視覺

一句話說重點:用強化學習教大型語言模型(LLM)做數學推理時,目前主流做法(GRPO)是「答對全文加分、答錯全文扣分」,連語助詞和關鍵推論步驟都領一樣的獎金。這篇提出 CEPO:**同時讓「正確答案」和「錯誤答案」分別當老師**,只獎勵那些「正答會選、錯答不會選」的 token——這才是真正決定推理對錯的關鍵字。在多模態數學推理 benchmark 上,2B 模型平均準確率從 41.17% 升到 43.43%,4B 從 57.43% 升到 60.56%。

---

## 先說情境:RLVR、GRPO,以及「全文一起獎勵」的問題

當代訓練大型語言模型做推理時,流行的方法叫 **RLVR(Reinforcement Learning with Verifiable Rewards,有可驗證獎勵的強化學習)**:讓模型生一個答案 → 用驗證器(例如數學答案對不對)打分數 → 用分數更新模型。

其中最被廣泛採用的演算法是 **GRPO(Group Relative Policy Optimization)**,DeepSeek 等推理模型都用它。但 GRPO 有個粗糙的地方:**它把整個答案當成一個整體來獎懲**——只要最終答對,整段話裡每個 token(包括「因此」、「我們得到」、語助詞)都領同樣的正分;答錯,整段話每個 token 都領同樣的負分。

問題:**數學推理裡通常只有少數幾個 token 是決定對錯的關鍵**——一個算術錯誤、一個正確的推論步驟,就決定整條推理的成敗。把獎金平均分發,等於浪費了大半 gradient 訊號在無關緊要的字上,真正關鍵的少數 token 反而沒被加強。結果是訓練收斂慢、噪音大、樣本效率差。

## 過去的修法為何失敗

很自然會想到:用「正確答案」當老師(teacher),問模型「如果你早知道答案,你會多生哪些 token?」這就是**自蒸餾(self-distillation)**的思路。但這條路有兩個陷阱:

1. **答案洩漏(information leakage)**:把正確答案丟給老師會在 gradient 裡留下「正答 → 某字」的捷徑,訓久了模型不是學會推理,而是學會猜「老師暗示什麼」。
2. **訊號太弱**:就算用了避免洩漏的技巧(RLSD),它只用「正確老師 vs 學生本身」的比值,但這個比值無法區分「填充字(filler)」和「關鍵推理字」——兩者對學生來說都看起來一樣 surprising。

## 他們怎麼做:用「兩個老師」做對比

CEPO 的核心精神可以用一句話概括:**不要只問「正答喜不喜歡這個字」,要同時問「錯答是不是討厭這個字」**。

具體做法:
- 從目前訓練 batch 裡找一個**錯誤的 rollout**(模型自己之前產生但被打為錯誤的答案),把它當作「**錯誤老師(wrong teacher)** P_T-」;
- 把原本的「**正確老師(correct teacher)** P_T+」也保留;
- 對每個 token y_t,計算對比比值 P_T+(y_t) / P_T-(y_t)——這個比值高,代表「正答會選這個字,而錯答不會」,這才是真正的關鍵 token;比值接近 1 代表「正答錯答都會選」,那是填充字。

理論上的漂亮之處在於:**學生模型自己的分布 P_S 完全從比值裡消掉了**(分子分母都來自「老師」,學生只在比值計算後當權重調整器)。這解決了過去方法的兩大毛病:
- **沒有 fluency confound(流暢度干擾)**:學生分布是否流暢不再混進訊號;
- **沒有資訊洩漏**:對比比值是基於兩個老師的對稱差異,gradient 不會走捷徑。

論文還證明 CEPO 繼承了前作 RLSD 的安全性,同時在關鍵 token 上獲得更尖銳的 credit assignment。

## 結果

在五個多模態數學推理 benchmark 上:
- **2B 規模模型**:CEPO 平均 43.43%,GRPO 41.17%(+2.26 個百分點);
- **4B 規模模型**:CEPO 平均 60.56%,GRPO 57.43%(+3.13 個百分點);
- **OPSD、SDPO 等過往的「分布匹配」自蒸餾方法掉到比 baseline 還差**,實驗證實了論文預測的「資訊洩漏」陷阱真實存在。

這張圖最清楚的部分是中間的「Correct Teacher / Wrong Teacher」雙塔結構——這是 CEPO 跟前作 RLSD 最大的差異。RLSD 只有一個老師、跟學生比;CEPO 有兩個老師、互相比,因此能精準篩出「兩個老師意見分歧的位置」就是真正關鍵的推理步驟。

## 它做不到 / 沒解決的

- **錯誤老師的品質仰賴 batch 裡有「結構性不同」的錯答**:如果某些題目大家都用同一種錯法,P_T- 就會跟 P_T+ 太接近,訊號變弱。
- **多模態數學推理 benchmark 上的提升是個位數百分點**:雖然有意義,但不是質的躍升;對其他類型的推理任務(常識、程式、長文閱讀)能不能複製,還要更多實驗。
- 訓練成本相對 GRPO 增加(多跑一次 wrong teacher 的 forward pass),但作者指出 wrong rollout 本來就在 batch 裡、不需要額外採樣。

## 怎麼看這件事

**為什麼在意?** 訓練推理 LLM 的算力成本越來越誇張(動輒上萬塊 GPU·日)。**每一單位 gradient 訊號的價值越高,訓練成本就越低**。GRPO 的「平均獎勵」浪費掉很多訊號,CEPO 這類「token-level credit assignment」的改進雖然每次提升只有幾個百分點,但對於 7B、70B 規模的訓練,節省的算力是非常可觀的。

**哪裡該保留懷疑?** 5 個 benchmark 的平均提升 2-3 個百分點,放到更大模型(70B、400B)是否還成立、是否會被其他訓練 trick 蓋過,還沒驗證。另外「正確/錯誤老師」的構造需要 batch 內同時有對錯答案,在某些訓練設定下(例如蒸餾、SFT)可能難以套用。

**怎麼理解這個方向?** 過去 RL 用在 LLM 上的訊號設計都很粗(序列級獎勵),近期研究方向一致是「**怎麼把獎勵訊號做到 token 級**」。對比學習的想法(正例 vs 反例)被搬到 RL 訊號設計上是個漂亮的延伸,可預期未來會看到更多「兩個老師、多個老師」的對比式 credit assignment 方法。
