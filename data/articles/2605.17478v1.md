# AI 看影片重建 3D 空間，看久了會「失憶走鐘」——這篇給它加了一條外接記憶體

> 原始論文：Mamba-VGGT: Persistent Long-Sequence Video Geometry Grounded Transformer via External Sliding Window Mamba Memory
> 作者·單位：Tianchen Deng、Zhenxiang Xiong、Nailin Wang、Fangjinhua Wang、Jiuming Liu、Jianfei Yang、Hesheng Wang（上海交通大學、蘇黎世聯邦理工學院、劍橋大學、南洋理工大學）
> arXiv：2605.17478v1 ・ 分類：cs.CV

一句話說重點：用 AI 看一段影片就能重建出拍攝環境的 3D 模型，但影片一長，AI 會「忘記前面看過的場景」導致空間越拼越歪；這篇給它外掛一個「滑動視窗記憶體」，讓它在長影片裡也記得住、拼得準，而且計算量不會隨影片變長而暴增。

---

## 背景：AI 從影片重建 3D，但「看久了會失憶」

從一段普通影片（單一鏡頭拍的）重建出拍攝場景的 3D 結構，是電腦視覺、自動駕駛、機器人、世界模型的基礎能力。近年出現一類「3D 基礎模型」，其中代表作叫 **VGGT**（視覺幾何接地 Transformer，Visual Geometry Grounded Transformer；可以理解為「一個專門把 2D 畫面還原成 3D 幾何的大模型」），重建短片效果很驚人。

但它有個根本瓶頸：核心機制「全局注意力」的計算量隨輸入長度**平方成長**——影片變兩倍長，計算量變四倍。為了不爆掉，模型只能一次看一小段（截斷的時間視窗）。後果就是論文說的「災難性幾何遺忘」與「累積漂移」：

- **幾何遺忘**：看新片段時忘了前面的場景長怎樣，失去「歷史感」。
- **累積漂移**：每段拼接都有一點誤差，一段段累加下去，整個 3D 地圖就越拼越歪——尤其在「繞一圈回到原點」或「到處都是重複紋理（像空蕩走廊）」的場景特別嚴重。

已有一些方法想用「稀疏注意力」或「測試時訓練」解決，但常常犧牲局部重建品質。所以需要一個既能長期記憶、計算量又只是線性成長、還不破壞 VGGT 原本強大空間能力的記憶機制。

## 怎麼做：把「記憶」和「當下處理」分兩條路

這篇提出 **Mamba-VGGT**。核心點子是：**把「3D 空間記憶」和「長期時間脈絡」拆開處理**，互不干擾。具體三個設計：

- **滑動視窗 Mamba 記憶模組（SWM）**：維護一個明確的「外接記憶 token」，跨時間視窗一路傳遞。這裡用的 Mamba 是一種「選擇性狀態空間模型」（可以想成一種計算量只隨長度線性成長的序列記憶機制，不像 Transformer 那樣平方暴增），用它把全局幾何先驗（對整個場景結構的整體認知）蒸餾、傳播下去，繞過傳統 Transformer 的記憶限制。
- **零初始化空間記憶注入器（Zero-Init Spatial Memory Injector）**：把長期記憶融進當下的影像 token 流時，怕一注入就把預訓練好的空間能力「震壞」。所以用「零卷積層」（zero-convolution，一開始輸出為零、再慢慢學起來）來逐步、溫和地融合，確保結構穩定、特徵對得齊。
- **雙路架構**：一條「主路」負責高解析度的當下空間重建（沿用預訓練 VGGT），一條「外接記憶路」負責長期時間脈絡傳遞，兩條解耦。

這張圖把雙路設計講得很清楚。**上半部「Main Path」（主路）**：左邊一串 Input Frames（輸入影格）進入預訓練的 VGGT Encoder，轉成 Patch Tokens（影像區塊單元），通過 Geometry Transformer Blocks（幾何 Transformer 區塊），中間橘色那兩塊 `ZeroConv` 就是「零初始化注入器」，最後右側三個 Head 分別吐出點雲、相機位姿、深度圖——這是重建出來的 3D 成果。**下半部「External Memory Path」（外接記憶路）**：左邊 `Historical Chunk Memory`（歷史片段記憶）流入，經過中央 `Sliding Window Mamba-based Memory Encoding`（滑動視窗 Mamba 記憶編碼）那串圓圈，更新成新的記憶緩衝，再沿著向上的箭頭（`Update Memory to Next Chunk`）餵回主路。重點是兩條路分工：**主路顧「現在看到的細節」，記憶路顧「以前看過的全局結構」**，記憶路的計算量是線性的，所以影片再長也不會爆。

## 結果：長影片不再走鐘，速度還更快

論文做了大量實驗，主要結論：

- **明顯優於現有 VGGT 系方法**，在「維持空間一致性」與「降低軌跡累積誤差」上都更好。對照方法隨著時間拉長而品質下滑，Mamba-VGGT 的重建品質則保持穩健。
- **記憶體佔用恆定**：不隨影片長度增加而膨脹，是「線性複雜度」的可擴展解法。
- **長序列下速度更快**：在串流與長序列設定下，輸入視角數從 50 增加到 300 以上，它的執行時間都比 ZipMap、VGGT-SLAM 等基準更好。
- 消融實驗（拿掉某組件看影響）證實：拿掉記憶模組後，超過 100 影格的序列重建完整度明顯下降；不用零初始化則第一階段訓練不穩、點雲扭曲——兩個關鍵設計都有實際作用。

## 做不到的地方

這篇沒有獨立的「限制」章節，這本身就是要留意的點——對失敗案例與適用邊界揭露偏少。從內文可推知幾項保留：

- 它建立在預訓練 VGGT 之上，效能與適用範圍受限於底座模型本身的能力，不是從零打造的通用方案。
- 論文主打「長序列、線性複雜度」，但對極端場景（如劇烈動態物體、極稀疏紋理）能撐到什麼程度，文中未深入界定。
- 文末提到「具備大規模 SLAM（同時定位與建圖）框架的潛力」——這是「潛力」而非已驗證的完整系統，實際整進機器人即時系統還有距離。

## 怎麼看這件事

**為什麼值得在意？** 「從影片重建 3D 環境」是自動駕駛、機器人、AR 的地基能力。「影片一長就走鐘」是這類模型落地的真實痛點，這篇提出一個計算量可控、又不破壞既有能力的記憶機制，方向務實。

**哪裡該保留懷疑？** 這是預印本，成果靠論文自己的實驗證明，缺第三方驗證，也沒有獨立的限制與失敗案例章節；「最佳」是相對它選的對照方法。能在實驗基準上勝出，距離「真實機器人長時間穩定運行」仍有工程差距。

**怎麼理解這個研究方向？** 這反映一個共同趨勢：當 Transformer 的「平方計算量」撞上「長序列」需求，研究界正大量把線性複雜度的狀態空間模型（如 Mamba）當作「外掛記憶」接到既有大模型上。能不能在「記得久」與「不破壞原本能力」之間取得平衡，會是這條路能否真正落地的關鍵。
