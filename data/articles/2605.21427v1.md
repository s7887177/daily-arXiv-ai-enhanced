# AI 伺服器電費太高？這套系統能同時省電26%又不讓服務變慢

> 原始論文：PALS: Power-Aware LLM Serving for Mixture-of-Experts Models
> 作者·單位：Can Hankendi、Ayse K. Coskun（Boston University）、Rana Shahout（Harvard University）、Minlan Yu（Harvard University）
> arXiv：2605.21427v1 ・ 分類：cs.AI / cs.DC

一句話說重點：研究者設計了 PALS 系統，把 GPU 功率上限（power cap）當成可調旋鈕與批次大小（batch size）聯合優化，在滿足吞吐量目標的前提下，讓 LLM 推論的能源效率最高提升 26.3%，同時將違反服務品質協議（QoS）的次數減少 4 至 7 倍。

---

## 先說問題：AI 伺服器的電費帳單正在失控

每次你問 ChatGPT 或 Claude 一個問題，背後都有一或多張 GPU 在高功率運轉。全球 AI 推論工作負載快速增長，資料中心的電力消耗也跟著急遽攀升。問題是：現有的 LLM 服務系統（如 vLLM）把 **GPU 功率當成固定的硬體限制**，不把它視為可操控的變數。

這帶來兩個浪費：當系統負載低時，GPU 仍以最高功率運轉；當電網要求降低用電時，系統沒有機制配合。對資料中心來說，浪費電力就是浪費金錢，也是碳排放。

## PALS 的核心想法

PALS（Power-Aware LLM Serving）的核心洞見是：**功率上限（power cap）與批次大小（batch size）對吞吐量和效率的影響可以互補，應該聯合調整**。

舉例來說：降低 GPU 功率上限會減慢計算速度，但如果同時增大批次大小，就能讓 GPU 在更低的瓦數下處理更多請求，維持整體吞吐量，同時省下電力——這個甜蜜點就是所謂的「帕列托前緣（Pareto frontier）」上的最佳點。

PALS 的架構分三層：

1. **遙測層（Telemetry）**：即時收集 tokens/秒吞吐量與 GPU 使用率，這些訊號直接從 NVML 等標準介面取得。
2. **控制層（Control Layer）**：使用事先建好的輕量「功率-效能預測模型」（離線訓練，不需重跑大模型），預測不同功率與批次組合的吞吐量；再用一個回饋控制器根據偏差即時調整，對工作負載波動與建模誤差都有魯棒性。
3. **執行層（Actuation Layer）**：透過廠商介面（NVML）直接設定 GPU 功率上限，並調整 vLLM 的請求排程批次大小。

整個系統**不需要改動模型架構或 API**，插入現有的 vLLM 框架即可運作。

## 實測結果

研究者在配備 4× A100 的單節點上，針對混合專家模型（Mixture-of-Experts，MoE）架構（OLMoE-1B-7B、Qwen 1.5-MoE、Microsoft-Phi-3.5）進行實測：

- **能源效率提升最高 26.3%**：在給定吞吐量目標下，PALS 選出的功率＋批次組合，比預設最大功率設定更省電。
- **QoS 違規減少 4–7 倍**：在功率有上限約束的場景（例如電網需求側管理）下，PALS 能在不違反延遲目標的前提下最大化吞吐量，遠優於只靠軟體或只靠硬體調整的單一旋鈕策略。
- **多節點有限制**：MoE 模型在 Qwen 架構下，節點數增加到 3 個時因 InfiniBand 通訊飽和，效率下降約 30%；Mixtral 下降較溫和（約 15%）。PALS 在多節點場景的收益因模型的計算/通訊比而異。

## 它做不到的地方

PALS 目前僅在 NVML 支援的 NVIDIA GPU 上實現，AMD 或其他加速器需重新適配。功率-效能預測模型需要針對每種模型架構離線建立，切換到新模型時需要重新建模。此外，論文尚未評估在多租戶（同一 GPU 跑多個模型）場景下的表現。

## 怎麼看這件事

**為什麼重要？** 全球 AI 推論的電力消耗正在快速接近某些中型國家的用電量。在「省電」與「快速回應」之間找到動態平衡，是讓 AI 推論在經濟上和環境上都可持續的關鍵。PALS 等於示範了一條路：**不需要更新模型，只要更聰明地控制硬體，就能省下四分之一的電費**。

**哪裡要保留？** 實驗是在 4 張 A100 的單一設定下進行，真實資料中心通常有數百到數千張 GPU、複雜的混合工作負載、以及更嚴格的延遲 SLA。實際部署效果是否能達到論文數字，需要更大規模的驗證。

**怎麼理解這個方向？** 這是「AI 系統效率」研究正從「如何讓模型更快」轉向「如何讓推論更省電」的縮影。隨著電力成本在 AI 總成本中占比上升，像 PALS 這類將功率管理融入推論框架的技術，會越來越成為工業部署的標配。
