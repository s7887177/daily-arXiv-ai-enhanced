# AI 優化提示詞越改越臃腫、越來越偏，用「正則化」剪掉那些過度客製化的規則

> 原始論文：TextReg: Mitigating Prompt Distributional Overfitting via Regularized Text-Space Optimization
> 作者·單位：Lucheng Fu、Ye Yu、Yiyang Wang、Yiqiao Jin、Haibo Jin、B. Aditya Prakash、Haohan Wang（喬治亞理工學院、伊利諾大學香檳分校）
> arXiv：2605.21318v1 ・ 分類：cs.CL / cs.AI / cs.LG

一句話說重點：自動優化提示詞（prompt）的方法往往把提示詞越改越長、越塞越多針對訓練題目的特殊規則，導致在新題目上效果變差；TextReg 透過正則化機制讓提示詞保持「通用」，在各類推理測試的泛化性能上最高提升 16.5%。

---

## 問題：自動優化提示詞為什麼會「過擬合」？

要讓 LLM 表現更好，很多時候靠的是精心設計的提示詞（prompt）——也就是給模型的任務說明和指令。近幾年出現了一批**自動提示詞優化**（Automatic Prompt Optimization）的方法，思路是：讓 LLM 自動迭代改寫提示詞，看哪個版本讓模型答對更多訓練題目。

但這個過程有一個問題，叫**提示詞分布過擬合**（Prompt Distributional Overfitting）：

- 優化過程看的只是訓練題目，所以提示詞會越來越針對訓練題目的特殊模式（「如果看到數字，就拆成中間步驟」）
- 這些窄化的規則讓提示詞**越來越長**（容量膨脹）、**規則越來越具體**（適用範圍越來越窄）
- 結果是在訓練題目上表現很好，但在**沒見過的新題目**（Out-of-Distribution，OOD）上效果差

這就像一個學生死記真正考卷的解題技巧，卻因此失去了面對新題目時靈活思考的能力。

## TextReg 的解法：像 L2 正則化，但作用在文字空間

機器學習中對付過擬合有個經典工具叫**正則化**（Regularization）——在優化目標裡加一個「懲罰項」，讓模型不要太極端。TextReg 把這個概念移植到提示詞優化的文字空間。

TextReg 的優化目標是：`最小化 (訓練損失) + λ × (提示詞低效度)`

其中「**提示詞低效度**（Representational Inefficiency）」由兩個因素乘積決定：

1. **容量成本（Capacity Cost）**：提示詞有多長——越長代表塞了越多規則，容量膨脹越嚴重
2. **範圍狹窄度（Scope Narrowness）**：提示詞裡的規則適用範圍有多窄——只對少數特定題目有效的規則被認為範圍更窄

這兩個因素一起衡量：一條規則若又長又窄，過擬合風險最高；若是短而廣的通則，則懲罰最小。

## 三個機制組合

TextReg 把這個正則化目標落實成三個元件：

**1. 雙重證據梯度淨化（Dual-Evidence Gradient Purification）**：
計算提示詞改進的「梯度」時，同時考慮兩個來源的證據：當前 mini-batch 裡的題目反饋，以及一個「RuleBank」（記錄哪些規則在過去多個 batch 都有效）。只有兩個來源都支持的改動才被保留，過濾掉只對當前 batch 特別有效的偶發性修改。

**2. 語義編輯正則化（Semantic Edit Regularization）**：
分析每次編輯是「讓規則更廣泛」還是「讓規則更窄化」。窄化的編輯會被標記並透過壓縮模式處理（強制把 case-patch 類的具體規則合併成通則）。

**3. 正則化引導提示詞更新（Regularization-Guided Prompt Update）**：
把上述正則化信號作為方向，從候選提示詞中選擇最符合「任務表現好又不過擬合」的版本，而不是單純選訓練分數最高的版本。

## 結果

在多個推理基準上（包括 TextGrad、REVOLVE 等現有方法的測試集）：
- 泛化性能（OOD accuracy）最高提升 **+11.8%** over TextGrad，**+16.5%** over REVOLVE
- 訓練集內的表現也沒有明顯下降

圖分三個面板。**左側**（Dual-Evidence Gradient Purification）：給定當前提示詞和一個批次的訓練資料，透過「局部案例證據」（這個批次支持的修改）和「全局復現證據」（RuleBank 記錄頻繁出現的廣泛規則）兩個信號，過濾出泛化性梯度 g_task。**中間**（Semantic Edit Regularization）：分析提示詞的容量頻道（prompt 有多長）和範圍頻道（規則適用多廣），診斷是「完全不正則」、「壓縮」、還是「全正則」模式，並產生正則化梯度 g_reg。**右側**（Regularization-Guided Prompt Update）：把 g_task 和 g_reg 組合成一個方向，從候選提示詞集合中選出最不過擬合的版本作為下一輪提示詞。三個步驟串聯，形成完整的閉環優化。

## 做不到的地方

TextReg 需要維護 RuleBank（記錄歷史規則的資料庫），這引入了額外的計算和記憶體成本。此外，「範圍狹窄度」的估計本身依賴 LLM 來判斷，可能引入偏差。論文測試的是推理類任務，在生成類（如寫作）或對話類任務上是否同樣有效尚不清楚。

## 怎麼看這件事

自動提示詞優化是讓 LLM 更好用的一條路，但「讓 AI 自己調整自己的指令」本質上和機器學習的訓練過程一樣，同樣有過擬合風險。TextReg 把機器學習中對付過擬合的「正則化」概念遷移到了文字提示詞的優化上，思路直觀且有說服力。

更深層的意義是：這篇論文在說，提示詞不只是「你告訴模型做什麼的話語」，它有結構上的屬性（長度、規則範圍），而這些屬性本身就可以被最優化和被約束。隨著 AI 進入更多自動化場景，「如何防止 AI 的自我調整偏離通用能力」會是一個越來越重要的問題。
