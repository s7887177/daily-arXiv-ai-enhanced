# 讓多模態 AI 邊看圖邊學新任務而不忘舊技能：串流持續學習框架 StrLoRA

> 原始論文：StrLoRA: Towards Streaming Continual Visual Instruction Tuning for MLLMs
> 作者·單位：Chang Che、Ziqi Wang、Hui Ma、Zenglin Shi（合肥工業大學）、Cheems Wang（清華大學）
> arXiv：2605.16353v2 ・ 分類：cs.CV / cs.AI

一句話說重點：現有的多模態大型語言模型（MLLM，即能看圖又能對話的 AI）持續學習新任務時，假設每次只學一種任務——這在現實中根本不成立；StrLoRA 提出一套「串流持續視覺指令微調」框架，讓模型從混雜不同任務的資料流中學習，在學新技能的同時不遺忘舊技能。

---

## 背景與問題

像 LLaVA 這類多模態大型語言模型（MLLMs），能同時理解圖像和文字，執行多種視覺問答任務：辨認物體、辨識圖中文字（OCR）、定位目標位置（Grounding）、回答財務圖表問題（FinVQA）等。

為了讓這些模型能「邊使用邊學習」新技能（稱為**持續視覺指令微調，Continual Visual Instruction Tuning, CVIT**），研究者設計了逐步微調的機制。但現有方法有一個不切實際的假設：**每次訓練只對應一種單一任務**（任務遞增式設定）。

真實世界的資料流根本不是這樣：同一批新資料可能混雜了 OCR 樣本、物體辨識樣本、定位任務樣本，比例還會隨時間改變。一旦資料流變成「多任務混雜的串流」，現有方法的路由器（Router）就會崩潰——因為它看不出眼前這個樣本屬於哪個任務，導致所有任務都走差不多的路徑，專家模組無法真正專業化。

## 怎麼做

研究者提出 **StrCVIT**（串流 CVIT）這個更貼近現實的設定，並設計了 **StrLoRA** 來應對：

**核心架構：兩階段專家路由**

StrLoRA 以低秩適應矩陣（LoRA）為基礎組成「混合專家（MoE）」架構，關鍵改進在路由策略：

1. **任務感知專家選擇（Task-Aware Expert Selection）**
   分析發現，同樣是多模態資料，**文字指令的嵌入向量（text embedding）在不同任務間形成清晰的分群，視覺特徵則大量重疊**。因此，StrLoRA 讓路由器只看文字指令，以 Top-K 選出最相關的幾個專家，過濾掉不相關的干擾。

2. **逐 Token 專家加權（Token-Wise Expert Weighting）**
   在選出的專家子集內，再根據每個視覺 token 與全局指令表示之間的跨模態注意力，為每個 token 分配不同的專家貢獻權重。這讓模型能針對圖像的不同區域動態調整。

3. **路由穩定性正則化（Routing-Stability Regularization）**
   在非平穩的串流資料中，路由分布容易劇烈抖動。StrLoRA 維護一個歷史指數移動平均（EMA）路由器，對當前路由和歷史路由之間的 KL 散度施加懲罰，讓路由決策逐漸平滑過渡而非突然跳變。

**新基準測試 StrCVIT Benchmark**

研究者也建立了新的評測基準，包含多種視覺任務（OCR、物體辨識、Grounding、FinVQA 等）的串流混合設定，持續測量歷史最高準確率的相對下降幅度來衡量遺忘程度。

## 結果

在新設計的 StrCVIT 基準上，StrLoRA **大幅超越**現有的 CVIT 方法：
- 在新任務的學習速度上領先
- 在降低遺忘程度上表現突出——基準線方法在遇到任務組成改變時會出現大幅準確率下降，而 StrLoRA 維持穩定
- 消融實驗顯示三個組件（任務感知選擇、逐 Token 加權、EMA 正則化）各自都有顯著貢獻，缺一不可

## 做不到的地方

- **需要文字指令清晰標示任務類型**：如果指令本身模糊，或同一指令可能對應多種任務，文字引導的路由就會失準。
- **測試任務數量有限**：目前在 4–6 種視覺任務上測試，真實部署可能面臨更多種類的任務混合，擴展性有待驗證。
- **EMA 的超參數設定敏感性**：EMA 衰減率直接影響路由穩定性和適應速度之間的平衡，不同資料集可能需要不同調整。
- **計算開銷**：兩階段路由和 EMA 維護會增加額外計算量，論文中有說明但未與所有基線做嚴格計算量控制的比較。

## 圖解

![StrLoRA 框架架構圖](assets/articles/2605.16353v2-fig1.webp)

這張架構圖展示了 StrLoRA 在多模態 LLM 內部的完整資料流。**左側**：視覺編碼器（Vision Encoder）處理圖像、Tokenizer 處理文字指令，兩者合併後進入 StrLoRA 模組。**右上方（Task-Aware Expert Selection）**：文字指令的平均池化向量透過線性路由器（W_g）計算 Softmax，Top-K 選出最相關的一組專家（LoRA 塊 B_1, A_1 等）。**右中方（Token-Wise Expert Weighting）**：在選出的子集中，每個視覺 token 透過 W_Q × W_K × W_E 的注意力計算獲得個性化的專家貢獻分數，加權後輸入 LLM。**右下方（Routing-Stability Regularization）**：當前路由器參數 θ 和歷史 EMA 路由器 θ̄ 之間計算 KL 散度，作為正則項防止路由分布劇烈抖動。

## 想自己判斷這篇可不可信？

| 訊號 | 這篇的情況 | 怎麼解讀 |
|---|---|---|
| 問題設定新穎性 | 首次系統定義 StrCVIT 串流混合任務設定 | 問題定義有說服力，有實際需求支撐 |
| 與基線比較 | 與多個 CVIT 方法（EMR、MoE-LoRA 等）比較 | 比較面向完整，但全部都是非串流設計，略有不公平 |
| 消融實驗 | 逐一移除三個組件，每個都有貢獻 | 組件必要性有依據 |
| 程式碼開源 | 已公開在 GitHub | 可重現 |
| 任務選擇 | 包含視覺問答、OCR、定位等多種類型 | 多樣性合理，但未包含更開放式的生成任務 |

## 怎麼看這件事

「邊用邊學而不忘」是讓 AI 系統真正長期有用的關鍵能力。現有的持續學習研究大多在「一次只學一件事」的簡化假設下進行，而 StrCVIT 指出這個假設在真實應用中根本不成立。StrLoRA 的設計思路——用文字的清晰度彌補視覺的模糊度、用 EMA 平滑非平穩漂移——是把持續學習研究往現實場景推進的一步。
