# 給 AI 一張「先畫好的座位表」，它就不會在陌生文件上抓狂跳針

> 原始論文：Structured Layout Priors for Robust Out-of-Distribution Visual Document Understanding
> 作者·單位：Peter El Hachem（ETH Zurich）、Ahmed Nassar、A. Said Gurbuz、Christoph Auer、Peter W. J. Staar（IBM Research Rüschlikon）
> arXiv：2605.19866v1 ・ 分類：電腦視覺・文件理解

一句話說重點：把一份 PDF 餵給「視覺語言模型」（VLM）讓它自己讀，碰到沒看過的版型常會整段消失、亂湊結構或無限迴圈跳針；IBM 這組人用一個輕量的版面偵測器先畫好「這頁哪邊是標題、哪邊是表格、哪邊是圖」的草圖塞給模型參考，**markdown F1 從 0.37 直接拉到 0.92**，而且只多耗 15% 的推論時間。

---

## 背景：為什麼小模型一遇到「沒看過的文件」就會抓狂

最近一批「視覺語言模型」（Vision-Language Model，把圖片和文字一起讀的模型，下面簡稱 VLM）很流行用來做文件解析——直接把整頁圖片丟進去，叫它輸出結構化的 markdown 或 HTML 表格。Donut、Nougat、DeepSeek-OCR、Qwen2-VL、SmolDocling 都是這一類。

但 VLM 在訓練時看過的文件版型有限。一遇到結構奇怪的學術期刊、中文表格、人資文件、能源報告，常會出現三種災難：

- **整段不見**（omission）：模型直接跳過某個區塊。
- **結構亂掉**（malformed structure）：表格的 cell 數不上，標題下面接的是別段的內文。
- **autoregressive 跳針**：最糟的一種——同一句話一直重複到輸出 token 上限為止才停。

作者把這個現象歸納成一個「兩跳瓶頸」：模型要先做**第一跳**——分辨「眼前這塊到底是標題、是段落、是表格還是圖」並標出座標；再做**第二跳**——把那塊裡面的內容讀出來。第一跳一失誤，第二跳就跟著崩。對 258M 參數這種小模型來說特別致命，因為它的容量已經很緊。

## 怎麼做：把「座位表」事先畫好塞進 prompt

他們的招數聽起來很笨但有效：**不要逼小模型自己同時做兩跳，先用一個輕量偵測器把第一跳的答案做出來給它看。**

具體流程是這樣：

1. 一個叫 `docling-layout-heron` 的 RT-DETR 偵測器（小型 transformer，速度快、精度也夠）先掃過整頁，吐出一堆「這塊是 Title，座標 [24,32,63,54]；這塊是 Text，座標 [90,19,140,200]；這塊是 Chart，座標 [200,19,32,31]」。
2. 把這些偵測結果**用模型自己的 DocTags 詞彙序列化**（不是硬塞純文字描述），變成一段「page 的藍圖」。
3. 把這段藍圖跟原圖**一起**丟給 VLM。注意是「一起」——以前的「先切後解析」流派（Dolphin、GLM-OCR）會把頁面按偵測框切成一塊塊餵給模型，偵測器漏掉的東西就永遠看不到；這篇的做法保留整頁圖當「fallback」，藍圖只是給提示。

訓練細節上有個聰明的設計：座標 token（`<loc_100>`、`<loc_200>` 那些）在 prompt 裡已經有了，模型只是抄過去就好，所以**反向傳播時把座標 token 的 loss 蓋掉**，只在「類別 token」和「實際內容 token」上算 loss——把梯度集中在真正需要學的多模態推理上。

## 結果：一邊變強，一邊變穩

三組外分布（out-of-distribution，跟訓練資料分布不同）測試的提升幅度都很誇張：

- **結構性外分布**（自家 1 萬頁 NoveltySet 基準）：markdown F1 從 **0.37 拉到 0.92**，編輯距離從 0.78 降到 0.39。
- **語言性外分布**（OmniDocBench 中文子集）：表格 TEDS 從 **0.01 拉到 0.36**——基線等於完全做不到中文表格，加了藍圖後至少能做出一半像樣的東西。
- **穩定性**（ViDoRe V3 共 2.6 萬頁，跨 7 個產業）：「無限迴圈」失敗率平均從 3.9% 降到 2.4%，最不熟的領域降幅最大（HR：7.4%→3.6%、Energy：4.3%→2.2%、Finance EN：4.6%→1.5%）。
- **同分布**也沒有變差，BLEU 從 0.65 升到 0.70。

而代價只有：推論時間 +15%，prompt 多出中位數 74 個 token，**完全不改基底 VLM 的架構**。

另一個有趣的副產品是「注意力分析」——他們發現模型在「輸出結構標籤時」會去看注入的藍圖 token，「輸出實際內容時」會去看圖片 patch，呈現雙峰式切換。這也算間接證明那個「兩跳」假說是對的：藍圖確實是被當作骨架在用，而不是被忽略。

## 做不到的地方

作者誠實列了幾點限制：

- **預偵測器本身的品質會傳遞下去**——雖然他們設計上保留整頁圖讓模型有 fallback，實驗也顯示偵測 dropout 很高時模型仍能維持功能，但偵測器系統性偏差仍會壓低天花板。
- **訓練資料中中文只佔 1%**，所以中文文字級指標只是「沒變差」，真正進步的是結構性指標（表格）。如果你的應用是中文純文字流，效益就沒那麼大。
- **這套是針對 258M 這種小模型最有用**——因為小模型最容易卡在兩跳瓶頸。大模型（7B 以上）原本就有容量同時處理兩跳，加 prior 的邊際收益會變小。論文沒在大模型上重複實驗。

## 怎麼看這件事

**為什麼在意？** 文件解析是 RAG（檢索增強生成）和企業文件處理最底層的基礎建設。如果這層在「沒看過的版型」上會跳針或掉內容，後端不管接 GPT-4 還是 Claude 都救不回來。這篇給了一個很實用的訊號：與其把所有希望寄在「更大的模型」，**在 prompt 前面放一張結構化的草圖**也能拿到大幅提升，且成本只多 15%。

**哪裡該保留懷疑？** 在自家 NoveltySet 上 F1 從 0.37 跳到 0.92 這種數字，工程上會立刻問「是不是基線當初就沒被妥善 fine-tune」。論文有用同一個 backbone（granite-docling-258M）做對照，但 OOD 基準的「OOD 程度」由作者選擇，外部要等他們釋出 NoveltySet 才能驗證。

**怎麼理解這個方向？** 這篇代表的趨勢是「結構化 prompting」——與其讓 VLM 在像素裡同時做版面和內容兩件事，**把版面這層用便宜的專家模型先處理掉**。這個思路也會延伸到其他「兩跳」任務：先用小模型把可結構化的部分做出來、再把藍圖丟給大模型專心做難的那一跳。這是把 LLM 當「分工協作」而不是「一鍋端」的典型例子。
