# 給 AI 駭客代理的操作手冊反而越詳細越沒用？

> 原始論文：When Skills Don't Help: A Negative Result on Procedural Knowledge for Tool-Grounded Agents in Offensive Cybersecurity
> 作者·單位：Samuel Jacob Chacko, James Hugglestone, Chashi Mahiul Islam, Xiuwen Liu（佛羅里達州立大學，美國）
> arXiv：2605.20023v1 ・ 分類：cs.AI / cs.MA

一句話說重點：在有清晰工具反饋的網路安全代理任務中，給代理讀越詳細的操作手冊（Agent Skills），通過率反而幾乎沒有提升——因為環境本身已經在教代理「對不對」了。

---

## Agent Skills 是什麼？

大型語言模型（LLM）驅動的代理在執行任務時，往往缺少特定領域的「程序知識」——知道怎麼一步步做某件事的知識。**Agent Skills**（代理技能）是一種解決方案：在代理執行任務之前，把結構化的操作手冊（包含說明、腳本、參考範例）載入上下文，讓代理擁有領域專業知識。

SkillsBench 是目前最大規模的 Agent Skills 評測基準，測試了 84 個任務、11 個領域。結果顯示平均加上 Skills 能提升通過率 **+16.2 個百分點**——聽起來很有效。

但有個問題：這個平均值背後有巨大的差異。醫療領域 Skills 帶來 +51.9pp，軟體工程只有 +4.5pp，16 個任務甚至在加入 Skills 後反而更差。沒有人解釋清楚**什麼時候 Skills 有用、什麼時候是多餘的負擔**。

## 這篇論文的核心論點

研究者重新分析了一份已發表的 180 次試驗研究——一個自主 **CTF（Capture the Flag，奪旗競賽）**代理在進攻型網路安全任務上的實驗。該實驗設計了四種文件豐富程度（55 行、1478 行、1976 行、4147 行的說明文件），研究者發現這四種條件恰好對應到：

- **55 行** ≈ No-Skills（無技能）
- **1478 行** ≈ Experiential-Skills（經驗型技能）
- **1976 行** ≈ Curated-Skills（整理型技能）
- **4147 行** ≈ Comprehensive-Skills（全面型技能）

在這個進攻型網路安全任務中，從無技能到全技能的通過率差距只有 **8.9 個百分點**（p = 0.71，統計上不顯著）。六對成對比較中，五對的效應量 Cohen's h 都低於 0.2（小效應門檻）。

## 為什麼網路安全場景特別不需要 Skills？

研究者提出的解釋是**環境反饋頻寬（environment-feedback bandwidth）**：

CTF 任務中代理使用的工具（MCP，Model Context Protocol）提供嚴格的 schema 驗證、低延遲的結構化輸出。比如執行一條命令後，工具會立刻明確告訴代理結果是什麼格式、成功還是失敗。這種高頻寬、高精度的環境反饋本身就在提供「程序修正訊號」——告訴代理什麼做法有效、什麼沒效。

Skills 的功能原本就是「補充代理缺少的程序知識」，但當環境反饋已經在即時提供這個訊號時，Skills 就變成多餘的——甚至在某些計時側通道（timing side-channel）攻擊場景中，過多的程序知識反而限制了代理的探索空間，讓它更差。

## 做不到的地方

- 這是一篇 4 頁的立場文章（position paper），基於對單一公開研究的再分析，而非全新實驗設計
- 180 次試驗、15 個挑戰，樣本量偏小，統計功效有限
- 只測試了一種代理和一個 CTF 框架，結論的可推廣性需謹慎
- 研究者沒有直接操控環境反饋品質（比如刻意降低反饋精度）來驗證「反饋頻寬假說」，屬於間接推論

## 怎麼看這件事

這篇論文的貢獻在於提供了一個**可偽證的假說**：Skills 的邊際效益隨環境反饋品質降低而提升。這不僅解釋了網路安全場景的數據，也與直覺一致——當外部環境已經把「好不好」講清楚了，額外的操作手冊就沒那麼必要。

這對設計 AI 代理系統的工程師有實際參考價值：在工具反饋清晰、schema 嚴格的場景（如 API 呼叫、資料庫查詢）投入大量精力整理 Skills 文件，效益可能有限；反而應該優先確保工具反饋的品質和結構性。不過這個結論建立在少量數據和間接推論上，需要更系統的實驗來確認。
