# 一個提示詞不夠用：讓 AI 自動替你找到「省錢又夠好」的最佳提示組合

> 原始論文：MO-CAPO: Multi-Objective Cost-Aware Prompt Optimization
> 作者·單位：Jan Büssing, Moritz Schlager, Timo Heiss, Tom Zehle, Matthias Feurer（LMU 慕尼黑、慕尼黑工業大學、弗萊堡大學、多特蒙德工業大學）
> arXiv：2605.18869v1 ・ 分類：cs.LG / cs.AI / cs.NE

一句話說重點：MO-CAPO 能自動找出一整組提示詞方案，讓你看到「準確率高但費用貴」和「便宜但稍差」之間的完整取捨光譜，而不是只給你一個「最好」答案。

---

## 問題在哪裡

在實際部署大型語言模型（LLM）時，每次呼叫的費用是真實的業務考量。一段詳細的提示詞加上幾個示範例子，準確率可能高出幾個百分點，但每百萬次呼叫的費用也可能貴上兩三倍。

現有的「自動提示詞最佳化」工具幾乎都只追求一個目標：**把準確率最大化**。它們給你一個「最佳提示詞」，但完全忽略這個提示詞的使用成本。少數考慮成本的方法，要求用戶事先設定「我願意用多少準確率換多少省錢」的權重比例——而這個值根本沒有人知道該設多少。

---

## MO-CAPO 怎麼做

MO-CAPO（Multi-Objective Cost-Aware Prompt Optimization，多目標成本感知提示詞最佳化）把這個問題重新框架為**多目標最佳化**：

**不問「哪個提示詞最好」，而是問「完整的帕雷托前沿（Pareto front）長什麼樣？」**

帕雷托前沿是「再也找不到一個方案能同時在所有目標上都更好」的解集合。具體而言：
- 一端是「超省錢、精簡零樣本」的短提示詞；
- 另一端是「加很多示範例子、準確率最高」的長提示詞；
- 中間有一系列不同取捨點。

**核心改良點有兩個：**

1. **成本目標更完整**：不只算提示詞長度，也計算輸出 token 數（思考鏈模型的輸出可能比輸入更貴）以及實際 API 單價，得到「每百萬次呼叫的美元成本」這個部署導向的指標。

2. **最佳化本身更省錢**：借鑑 CAPO 的預算分配競速機制——表現差的候選提示詞早早淘汰，不浪費 LLM 呼叫次數。對比 NSGA-II（非支配排序遺傳演算法，Nondominated Sorting Genetic Algorithm-II）基準，MO-CAPO 在相同預算下更快找到好的帕雷托前沿。

---

## 結果如何

在四種任務（程式碼、數學、旅遊計畫、主觀判斷）與三種 LLM 上測試，MO-CAPO 在 12 組實驗中的 8 組，以 noisy R2 指標（衡量帕雷托前沿品質的指標）優於 NSGA-II-PO 基準，且通常在 token 預算還剩一半時就已達到接近最終的帕雷托前沿品質。

最佳性能候選方案的準確率，與單目標最佳化器（只追求準確率）的結果相當，但額外提供了一整組不同成本等級的方案。

---

## 做不到的地方

- 帕雷托前沿只涵蓋準確率與成本兩個目標；延遲（latency）、隱私、回應風格等其他實際考量未納入。
- 評估仍需大量 LLM 呼叫，若 LLM API 費用很高，最佳化本身的成本就不可忽視。
- 論文只測試了最多 5 個 few-shot 示範例子的情境，更大規模的提示詞空間（如更多示範或複雜指令鏈）未涵蓋。
- 測試的三款 LLM（Mistral、GPT-OSS、Qwen）都是開源或有明確定價的模型；對私有 API 模型的適用性需自行驗證。

## 怎麼看這件事

「自動找最佳提示詞」是個實用工具，但只給一個「最佳解」往往不符合實際部署決策——你需要知道「多花一倍錢能多幾個百分點」這樣的資訊。MO-CAPO 把這個問題顯式化，是一個有意義的工程實用貢獻。限制是：最佳化本身也要花錢，對小型應用來說可能不划算。
