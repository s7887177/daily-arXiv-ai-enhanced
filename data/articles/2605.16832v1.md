# 讓 AI 重建室內格局時別漏掉門窗：給 3D 點雲「上四種顏色」當提示

> 原始論文：Coarse Semantic Injection for LLM-Conditioned Structured Indoor Prediction
> 作者·單位：Shuliang Zhu、Tomiwa Adey、Jinjia Zhou
> arXiv：2605.16832v1 ・ 分類：cs.CV

一句話說重點：用大型語言模型把 3D 掃描重建成「有牆、門窗、家具框」的室內格局時，門窗這種又薄又細的東西常被漏掉、雜亂房間的單件家具也常被混在一起；這篇不改原有架構，只在點雲送進模型前替每個點塗上「家具/牆/門窗/其他」四種顏色當語意提示，在三個資料集上讓門窗定位和逐件家具偵測變好——但作者也誠實說明，提升不是全面的、還有顏色本身的干擾未完全排除。

---

## 背景：把掃描變成「可編輯的室內格局」，門窗最容易被吃掉

「結構化室內建模」是要把一個房間的 3D 掃描，還原成精簡、可參數化的表示——包含牆、門、窗這些建築佈局元素，以及家具的 3D 邊界框。這種結構化輸出對機器人導航、具身互動、AR 內容製作、可編輯的「室內數位分身」都很有用。

近年的做法是用**大型語言模型（LLM）當「結構化解碼器」**：先把 3D 幾何透過「體素化、稀疏序列化、池化」轉成一串緊湊的點 token（把無序的 3D 點變成模型能讀的序列），再讓 LLM 像寫文章一樣，自迴歸地「描述」出這個房間的牆、開口、家具框。

但這條稀疏點 token 管線有個老問題：**會把細微的結構證據稀釋掉**。兩種失敗特別常見：(1) 又薄又靠邊界的元素（如門、窗）只占極少體素，幾何證據在池化後幾乎消失；(2) 在雜亂擁擠的房間，個別家具實例容易被混在一起、漏掉。

## 怎麼做：在點雲上「塗四種顏色」當語意提示，但不動下游架構

研究者的核心思路是「保留介面的語意增強」——**不新增任何任務專屬的偵測器、佈局頭或分割解碼器**，只在點雲被 token 化之前，給它注入一點語意線索：

- **四色 RGBB 編碼**：把語意證據（可由 RGB 影像得來）壓縮成一個粗略的「四群組」編碼——家具、牆、門窗開口、其他——分別塗成**紅、綠、藍、黑**四種顏色。注意「RGBB」是用現有的三個 RGB 顏色通道表達這四種狀態，**沒有多加第四個通道**。這組語意顏色直接接在原始點的屬性後面，於是「幾何」和「語意」走同一條稀疏 token 化路徑，而下游的語言模型解碼器與輸出格式完全不用改。
- **輕量的「路由式語意位移」模組**：在稀疏池化後再補強語意線索，只多了約 0.2M 個可訓練參數（相對基準幾乎微不足道）；另有一個只在訓練時用的輔助頭，做比例/預算/熵的正則化與分析。
- **附帶的可控性**：因為語意是「輸入層」的，使用者可以在 2D 視圖上點一下某個目標物，用可提示分割（SAM）取得遮罩，只把該目標的點上色、其餘塗黑，就能在不改解碼器的情況下，把模型的框輸出「偏向」這個被選中的物件。

這張圖把流程拆成清楚的六步。最左是輸入：RGB 視圖經「3D Foundation Model」或「SAM」取得語意，據此把點雲依四群組上色（圖例：藍＝門窗、紅＝家具、綠＝牆、灰／黑＝其他或背景，且灰點僅作脈絡、不參與融合）。接著 **A. 語意子集切分**（把點雲按語意分群，只有選定子集會用於融合）→ **B. 子集編碼與原型池化**（各群編碼後池成「每類一個原型 token」）→ **C. 類別條件的差量生成**（每類用 MLP 生出一個語意差量向量）→ **D. 幾何側路由**（Router 對每個原始點 token 算「該從各語意差量接收多少」的權重，圖中表格就是每點對各語意的權重分配）→ **E. 加權融合**（依權重把差量融合、更新原始點特徵）→ **F. 增強後的點特徵**送進下游預測頭。最右就是輸出的結構化 3D 室內佈局（牆、家具框等）。整條路徑的關鍵是：語意只在「進 token 化之前」注入，下游解碼器原封不動。

## 結果：門窗與逐件家具有改善，但不是全面提升

研究者在三個資料集上做了**受控評測**：Structured3D、SpatialLM 資料集（LLM 解碼器自迴歸生出佈局與家具框的序列化描述）、ARKitScenes（同一解碼器預測定向家具框）。結論是：當語意支援「規格良好」時，這個四色介面能**改善門窗開口定位與逐件家具框預測**，尤其在雜亂場景；而 click/SAM 分支則展示了「指定目標上色」能在不改解碼器下把框輸出偏向選定物件。整體只多了約 0.2M 可訓練參數。

但這篇最值得稱許的是它的**誠實**。作者用消融實驗主動劃出方法的邊界：**提升並非在所有基準與指標上都一致**；那些輔助約束主要是在「佈局 vs 家具框」之間做取捨；而且一個「隨機四色」對照實驗顯示——**顏色/熵本身帶來的干擾仍然不容忽視**（也就是說，部分增益可能來自「有顏色」這件事本身，而非顏色「對應正確語意」）；強度縮放研究也顯示這種可控性並不平滑，伴隨精度與假陽性的取捨。

## 做不到的地方

論文在結論明確列出三項限制：(1) **語意粒度太粗**——只有四群組，無法區分更細的物件類別；(2) **依賴遮罩品質與視角覆蓋**——語意來自 RGB/SAM，若遮罩不準或視角不足，提示就不可靠；(3) **語意意義與顏色未完全解耦**——「隨機四色」對照證明顏色本身的干擾還沒被完全排除，這讓「增益到底來自正確語意還是來自上色這件事」變得不能完全確定。換句話說，這是一個有效但仍受限、且作者主動承認「效果不全面」的方法。

## 怎麼看這件事

**為什麼值得在意？** 把房間掃描變成「可編輯、含門窗家具」的格局，是 AR、機器人、室內數位分身的基礎能力，而門窗這種薄結構恰恰最常被現有管線吃掉。這篇提供了一個成本極低（只多 0.2M 參數、不改下游）的補強思路——在輸入端塞一點粗語意，就能針對性改善最薄弱的環節。

**哪裡該保留懷疑？** 這篇本身就在教你保留懷疑：增益不全面、依賴遮罩品質、而且「隨機四色也有效」說明顏色干擾沒排乾淨。對使用者而言，這代表「有改善」要看具體資料集與指標，不能當成普遍成立的結論——但作者把這些攤開來講，反而比一面倒宣稱 SOTA 的論文更值得信任。

**怎麼理解這個研究方向？** 這屬於「用 LLM 當結構化解碼器來理解 3D 場景」這個新興方向裡的務實改良。它的價值不在刷榜，而在示範一種「保留現有介面、用最小代價注入先驗」的工程哲學，以及一種少見但珍貴的研究態度——用對照實驗主動找出自己方法的混淆與邊界，而不是只報喜。
