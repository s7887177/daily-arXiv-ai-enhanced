# 讓 AI 思考得更好：自動發現「推理模組」讓多智能體系統真正強起來

> 原始論文：ARM: Discovering Agentic Reasoning Modules for Generalizable Multi-Agent Systems
> 作者·單位：Bohan Yao、Shiva Krishna Reddy Malay、Vikas Yadav（Salesforce AI Research）
> arXiv：2510.05746v2 ・ 分類：cs.AI / cs.CL / cs.LG

一句話說重點：ARM（Agentic Reasoning Module，代理推理模組）是一種可自動發現的「思考步驟生成器」，作為多智能體系統的通用積木，在數學和程式推理任務上同時超越手工設計和自動搜尋的多智能體架構，且泛化能力遠勝現有方法。

---

## 背景：多智能體「越搭越複雜，越搭越沒用」

把多個 LLM 串聯成「多智能體系統（Multi-Agent System，MAS）」——一個當偵探、一個當辯手、一個當評審——是當前解決複雜推理任務的主流做法。Alpha Geometry、AlphaCode 等頂尖成果都有多智能體的影子。

問題是：**自動設計這些系統**的方法普遍令人失望。最新的自動 MAS 設計研究（如 AFlow、ADAS）發現，精心搜尋出來的複雜架構，往往和簡單的 Chain-of-Thought（CoT）差不多、甚至更差。而且每換一個任務領域，就要重頭搜尋一次，計算成本極高。

這個現象背後有一個關鍵洞察：**CoT 本身——「一步一步思考」這個基礎推理單元——才是多智能體系統真正的核心**。與其設計複雜的角色拓撲，不如讓這個基礎步驟本身變得更強大。

## 怎麼做：把「一步推理」提升為「智能化推理模組」

**ARM** 的設計邏輯是把每一個 CoT 步驟從「讓 LLM 生成一段文字」提升到「讓一個迷你多智能體系統生成一個步驟」：

**ARM 的核心結構：**

一個 ARM 接收「目前的問題 Q」和「已有的推理步驟 p₁, p₂, ..., pₙ」，輸出「下一個推理步驟 pₙ₊₁」。在內部，ARM 不是讓一個 LLM 直接生成這個步驟，而是：
1. 讓多個候選生成器各自生成一個「步驟候選」
2. 用重排（Rerank）和加權聚合選出最好的
3. 自我精煉（Self-refine）輸出

**ARM 的發現過程（樹搜尋 + 程式空間進化）：**

研究者把 ARM 的設計空間定義為 Python 程式碼——因為程式碼可以精確表達任意複雜的邏輯。搜尋從最簡單的 CoT 模組（一個 LLM 呼叫）出發，透過**對執行軌跡的反思（reflection on execution traces）**產生突變（mutation）——也就是讓一個 LLM 讀取「這次為什麼推理錯了」，然後建議如何改進 ARM 的程式結構。這個進化過程在程式碼空間裡進行，而不是在架構圖上。

**Meta Policy（元策略）：**

發現的 ARM 可以直接作為遞迴推理迴圈使用，也可以被一個更高層的「元策略」調度——元策略本身也是一個被學習出來的模組，它決定什麼時候叫哪個 ARM、叫幾次、如何彙整答案。

## 結果：泛化才是真本事

在數學（MATH、GSM8K）和程式碼（HumanEval、MBPP）推理任務上：

- **超越手工設計的 MAS**（如 Reflexion、LLM-Debate）以及**自動設計的 MAS**（如 AFlow、ADAS），且準確率提升最高超過 **10 個百分點**。
- 關鍵結果：ARM 在 **A 任務上訓練，可以直接在 B 任務上使用，幾乎無性能損失**——這正是現有方法做不到的（它們每個新任務都要重新搜尋）。
- 換不同的底層基礎模型（從 GPT-4o 到 Claude 到 Llama），ARM 的表現保持穩定優勢。
- 論文特別指出：即使和遠強大的 GPT-4o 相比，用 GPT-4o-mini 加上 ARM 的準確率也更高——意味著**好的推理結構可以彌補模型能力的差距**。

左側：ARM 模組接收問題 Q 和已有的推理步驟序列（p₁ ~ pₙ），同時調動多個「Generate Step」（步驟生成器）並行生成候選步驟，再透過「Rerank and Weighted Aggregate」排序加權，最後「Self-refine」自我精煉，輸出下一步推理步驟 pₙ₊₁。右側：Meta Policy 用 ARM 作為子模組，把多個 ARM 以矩陣方式並行展開——每個問題 Q 可以由多條 ARM 鏈各自推進，最終彙整成一個問題解答 A = [p₁, p₂, ..., pₘ]。整個架構是可遞迴的：ARM 自己就是一個小型 MAS，而 Meta Policy 則把多個 ARM 組成更大的 MAS。

## 做不到的地方

- ARM 的搜尋過程（程式空間樹搜尋 + 執行軌跡反思）需要大量 LLM API 呼叫，搜尋一個好的 ARM 模組本身仍然有一定計算成本。
- 目前主要在數學和程式碼任務上驗證，對需要工具使用（tool use）、網頁瀏覽、長上下文理解的任務是否同樣有效尚未確認。
- 「程式碼空間進化」依賴 LLM 的程式碼撰寫能力，若底層模型的程式能力弱，搜尋品質可能受限。
- Meta Policy 的設計雖然是學習出來的，但初始的搜尋仍需要一些種子任務，完全零樣本的遷移尚未實現。

## 怎麼看這件事

ARM 的核心思想可以一句話概括：與其搭建更複雜的智能體拓撲，不如讓每一個「思考步驟」本身更聰明。這個視角的轉換，讓多智能體設計從「優化系統架構圖」變成「優化推理程式模組」，而程式是可以自動搜尋、跨任務複用的。如果這個方向成立，它意味著未來的多智能體研究應該更關注「推理單元的品質」，而不是「智能體之間的溝通協議」。對於想在有限算力下擠出更多推理能力的工程師，ARM 是一個值得認真試試的框架。
