# 多模態 AI 看圖時把畫面切成「死板格子」很浪費：他們改成按「語意」切，像人說話那樣

> 原始論文：A More Word-like Image Tokenization for MLLMs
> 作者·單位：Hyun Lee、Hyemin Jeong、Yejin Kim、Hyungwook Choi、Hyunsoo Cho、Soo Kyung Kim、Joonseok Lee（首爾大學 Seoul National University、梨花女子大學 Ewha Womans University）
> arXiv：2605.17954v1 ・ 分類：cs.CV

一句話說重點：能看圖又能對話的 AI，目前是把圖硬切成固定數量的「方格小塊」餵給語言模型，既冗餘又跟文字格格不入;這篇改成「按語意把相關區塊聚成一個概念單位」，圖簡單就用少一點塊、複雜就多一點，結果用少很多的視覺單位就達到甚至超過原本效果，還能在不重訓的情況下調快慢。

---

## 背景：圖被硬切成格子，跟「文字字詞」很不一樣

能同時理解圖與文字的 AI 叫**多模態大型語言模型（MLLM）**。常見做法是：保留一個現成的語言模型（負責推理），加一個現成的視覺編碼器（把像素轉成語意特徵），中間訓練一個「視覺投影器」（projector）把圖的特徵翻譯成「語言模型看得懂的 token 序列」。理想上，這串視覺 token 應該要像「文字 token」一樣有清楚語意、有結構，語言模型才能好好推理。

但現有投影器幾乎都沿用 ViT（視覺 Transformer）那套**死板的格子切法**：把圖平均切成固定大小的方塊，每塊各自對應一個 token。論文指出這跟「文字字詞」有三個根本落差：

- **語意糾纏**：方塊是按位置硬切的，不管內容;而且這些特徵在視覺編碼器裡已經過多層自注意力「攪在一起」，導致 token 之間意思混雜。文字 token 則是被切成獨立的單位（如 BPE 編碼），各自乾淨。
- **數量固定，不看內容**：不管圖多簡單或多複雜，都產出固定數量的視覺 token。一張只有單一概念的圖被切成一堆冗餘 token;複雜的圖卻被硬塞進不夠用的 token。但人「描述一個場景」時，話的長短是隨場景複雜度變的。
- **無法控制「每個 token 裝多少資訊」**：文字可以選擇切成子詞或整詞來平衡表達力與長度;視覺切法卻只能靠空間操作，沒有原則性的「粗細旋鈕」。

論文還用實驗佐證了「糾纏」：在 CLIP、SigLIP、DINOv2 等視覺編碼器裡，**越深的層、各方塊之間越像**——重複的自注意力把同一張圖內的方塊特徵越攪越均質、越冗餘。

## 怎麼做：按「語意」把方塊聚成「視覺詞」，數量隨圖自動變

這篇提出 **DiVT**（Disentangled Visual Tokenization，解纏視覺切詞）。核心不是「每塊各自映射」也不是「按空間鄰近硬合併」，而是**把視覺編碼器的方塊特徵按「語意」聚類**——意思相近的方塊聚成一群，每一群形成一個獨立的視覺 token（一個「視覺詞」）。這樣每個 token 更對應一個明確的視覺概念（一個物件、部位或顯著區域），而不是一坨不相關內容的混合。

三個關鍵特性：

- **只用語言模型目標訓練、無需外部標註**。聚類器是端到端跟著語言模型一起學的，所以「怎麼切」是被「語言模型內部如何組織語意」塑造出來的，自然對齊語言模型的需求。
- **token 數量隨內容動態決定**。簡單場景不會塞一堆冗餘 token，雜亂場景也不會資訊不足。實驗顯示視覺單純的測試集（如 SQA-IMG）平均只需約 48 個 token，文字密集的（如 TextVQA、POPE）則需 80 個以上——這正是預期行為。
- **粗細可調，且推論時免重訓即可調**。訓練時用一個聚類門檻 θ 控制「每個 token 裝多少資訊」;這個門檻**推論時也能直接調**，讓使用者在「細節 vs. 記憶體/延遲」之間自由取捨、配合部署算力，不必重新訓練。

## 結果：用少很多的視覺單位，打平甚至超過

把 LLaVA-1.5 的 MLP 投影器換成 DiVT，其餘設定不變，在 8 個常用多模態基準上測試（對手包括多種免訓練的 token 削減法與需訓練的 TokenPacker）：

- **大幅減量仍維持競爭力**：用約 136.5 個 token（θ=0.75）時，MMBench 達 66.7、VQAv2 達 78.2，**與完整 LLaVA 用 576 個 token 的 64.3／78.5 相當甚至更好**。
- **token 越少優勢越明顯**：θ=0.5（約 35.7 個 token）時 MMB 65.0、VQAv2 77.0，明顯勝過 TokenPacker 36-token 版的 62.8／75.0;甚至最精簡的 θ=0.3／0.4（只用 13.5～22.4 個 token）在多數基準上仍勝過其他基準方法。
- **贏在「控語意粒度」而非「壓縮」**：格子型/削減型方法在極少 token 下會丟核心資訊，DiVT 因為控制的是每個 token 的語意粒度，所以在緊縮預算下更穩。
- 與其他投影器（Resampler、C-Abstractor）相比也一致取得最高分;且**與視覺編碼器選擇無關**，放大到更大語言模型仍有效。
- **程式碼已開源**（論文標明 GitHub 連結）。

## 做不到的地方

這篇論文沒有專門的「限制」章節（須自行警惕），但從內文可歸納幾點：

- **沒有獨立的限制與失敗案例分析**。論文主要在「討論」節對比相近方法、強調自身優勢，未系統列出 DiVT 何時會失靈、聚類在哪些圖上會切錯——這本身是讀者需留意的訊號。
- **聚類門檻 θ 是個需要調的旋鈕**。它帶來彈性，但也意味著「最佳 θ」要靠交叉驗證決定（論文在 0.5/0.65/0.75 等值間調），不同任務的最佳點不同;摘要宣稱的「免訓練即可調」是指「調快慢」，不代表「不用先選好訓練用的 θ」。
- **評估限於影像理解類基準**。8 個基準雖多元，但仍以 VQA/對話/OCR/幻覺為主;在更廣的多圖、影片、生成等任務上的表現未在此驗證。
- **本質仍是「投影器替換」**。它改的是中間那層翻譯器，依賴既有的視覺編碼器與語言模型;若上游編碼器的特徵本身語意就差，聚類能補的有限。

## 怎麼看這件事

**為什麼值得在意？** 多模態 AI 最大的隱形成本之一，就是「一張圖被切成幾百個視覺 token 塞進語言模型」——這會撐大記憶體（KV-cache）、拖慢推論，卻不見得換來等比例的準確度。這篇直指問題根源：那些 token 既冗餘又語意糾纏，根本不像語言模型熟悉的「字詞」。能用十幾到一百多個語意清楚的視覺詞，達到原本五百多個格子塊的效果，對部署成本是實在的節省，而且還能在不重訓的前提下按算力調快慢。

**哪裡該保留懷疑？** 這是預印本，且論文對自身限制著墨不足、沒列失敗案例。它的彈性來自一個需要調的門檻 θ，「免訓練即可調」主要指調快慢、不是免去選訓練設定;漂亮的數字（用 22.4 個 token 還能贏）是在 LLaVA-1.5 這個特定骨幹、特定基準上取得，外推到所有模型/任務要謹慎。

**怎麼理解這個研究方向？** 這屬於「高效多模態」這個熱門領域，和「推論時剪枝」是兩條路線：剪枝是事後丟掉冗餘 token（便宜但會跟訓練行為錯位、激進時掉分），這篇則是**一開始就生成精簡且語意對齊的 token**，從根源解決。它的核心論點——「視覺 token 該像文字字詞那樣按語意切、長度隨複雜度變」——是個直覺上很對、也用動機實驗撐起來的觀點。判斷這類論文時，重點是看它指出的問題是否真實、解法是否對症且可驗證——這篇問題定義清楚、有開源可查，論點站得住;只是它對「方法在哪會失靈」講得太少，這部分要靠後續同儕審查與獨立重現補上。
