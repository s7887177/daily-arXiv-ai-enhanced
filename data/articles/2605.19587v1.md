# 說一句話，AI 就幫你建出一個可以真實互動的 3D 房間

> 原始論文：SceneCode: Executable World Programs for Editable Indoor Scenes with Articulated Objects
> 作者·單位：Puyi Wang、Yuhao Wang、Linjie Li、Zhengyuan Yang 等（香港中文大學；上海交通大學；Microsoft；牛津大學）
> arXiv：2605.19587v1 ・ 分類：cs.AI

一句話說重點：SceneCode 把自然語言描述轉成可執行的 Python 程式，生成的 3D 室內場景不只是靜態網格，而是有關節、能被機器人實際開關的真實物件。

---

## 問題：現有的 3D 場景生成都是「空殼」

具身 AI（Embodied AI）、機器人操作訓練、自動駕駛模擬——這些前沿領域都需要大量逼真的 3D 室內環境供訓練和測試。但現有的場景生成方法有個根本缺陷：

大多數系統生成的是**靜態網格（static mesh）**，物件只有外觀，沒有內部結構、沒有關節（joint）、沒有可以被移動的部件。衣櫃可以渲染，但推不開門；抽屜看起來在那裡，但拉不出來。機器人在這樣的環境裡訓練，到了真實世界就會「不認識」真正的物件。

現有的「可互動物件」通常來自精心策劃的資產庫，你只能用庫裡有的東西。想要一把特定尺寸的椅子、一個帶特定數量抽屜的書桌？對不起，庫裡沒有就沒有。

## SceneCode 的思路：把場景編譯成程式

SceneCode 提出把室內場景生成**重新定義為程式生成問題**。系統接收一段自然語言提示（如「一個青少年的臥室，遠角有一張帶床頭板的雙人床……」），然後輸出：

- **可執行的 Blender Python 程式**：每個物件（衣櫃、書桌、床等）都是一段獨立的程式，明確描述每個零部件的幾何形狀、材質、位置和關節參數。
- **持久化場景狀態（house_state.json）**：記錄每個物件的類型、關節類型（旋轉/平移）、運動範圍等機器可讀的元資料。
- **物理模擬就緒的 SDF 檔案**：可直接載入 Gazebo 等機器人模擬環境。

整個流程分四個階段：

1. **場景規劃**：房間層級的代理人把提示轉化為結構化的房間佈局，並針對每個物件發出 AssetRequest（類型、描述、尺寸、風格、位置、支撐關係）。

2. **程式碼驅動的物件生成**：每個 AssetRequest 被路由到五種程式生成策略之一（靜態簡單物件、複雜多零件物件、帶旋轉關節的物件等）。生成的 Blender Python 程式通過「執行-評估-修復」迴圈自動驗證和修正，最多重試五次。

3. **模擬就緒編譯**：把 Blender 程式編譯成物理屬性（碰撞幾何、慣性張量、摩擦係數）和關節元資料，匯出 SDF。

4. **場景狀態登錄**：把所有物件的請求、程式、渲染幾何和模擬資產連結起來，形成可追蹤、可局部編輯的世界建構過程。

## 實驗結果

在場景層次和物件層次都有評估：

- **場景忠實度**：相比 CNT、HSM 等基線，SceneCode 在提示符合度（CLIP 分數）、物理合理性（穿透檢測）和幾何一致性上均有提升。
- **人類評分**：論文報告 SceneCode 在 prompt 忠實度的五分制評分上最高（均值 Δ > +1 分），物件擺放合理性和整體品質也更佳。
- **下游機器人互動**：生成的場景可被載入模擬器，機器人可以實際與物件互動（開門、拉抽屜），驗證了關節元資料的正確性。

## 做不到的地方

- **複雜物件的程式生成仍脆弱**：帶多個複雜關節的物件（如有多個抽屜 + 活動隔板的書架）成功率仍受限，自動修復迴圈有時無法收斂。
- **場景多樣性受限於代理人能力**：房間佈局的創意度取決於 LLM 規劃器，可能在複雜空間佈局上重複出現相似模式。
- **視覺逼真度不是重點**：輸出是 Blender 預設渲染，材質和光照不如 Gaussian Splatting 或 NeRF 方法逼真，不適合以視覺保真度為主的應用。
- **評估基準新且自建**：部分評估指標是論文自行設計，外部可重現性和基準的代表性仍需社群確認。

## 怎麼看這件事

「可互動」的 3D 場景生成是具身 AI 的真實瓶頸，現有工作要麼只管視覺（靜態）、要麼只靠資產庫（限制多）。SceneCode 用「程式即場景」的思路繞過了這個兩難，讓關節物件可以按需定制生成，這對機器人訓練的場景多樣性是真實的貢獻。

核心挑戰仍在可靠性：生成 Python 程式然後讓 Blender 執行，是一個脆弱的管線，錯誤累積速度快。論文的執行-修復迴圈是工程緩解措施，但不是根本解決。隨著 VLM 代碼生成能力的持續提升，這個瓶頸有望被逐步打通，SceneCode 的整體框架方向是正確的。
