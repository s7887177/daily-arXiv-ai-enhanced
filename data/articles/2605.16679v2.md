# 讓 AI 幫醫院跑行政流程有多難？最強模型也只能完成三成任務

> 原始論文：CHI-Bench: Can AI Agents Automate End-to-End, Long-Horizon, Policy-Rich Healthcare Workflows?
> 作者·單位：Haolin Chen 等 30 餘位作者（actAVA.ai、約翰霍普金斯大學、史丹佛大學、卡內基梅隆大學、加州大學聖地牙哥分校等多所機構）
> arXiv：2605.16679v2 ・ 分類：cs.CL / cs.AI / cs.HC

一句話說重點：研究者打造了一個模擬真實醫療行政流程的 AI 代理人測試基準，涵蓋事先授權、保險審查和護理管理三大場景；測試 30 種模型配置後發現，最佳組合（Claude Code + Claude Opus 4.6）也只能完成 28% 的任務，強調目前 AI 距離真正自動化醫療行政流程還有很長的路。

---

## 背景與問題

美國醫療系統的行政地獄是公認的效率黑洞：醫院要替病人爭取「事前授權（prior authorization, PA）」——也就是在開刀或用藥前，先讓保險公司審核批准——往往要填大量表格、引用臨床指南、與保險公司電話溝通，整個流程可能拖上數週。護理管理（care management）也類似：個案管理師要追蹤病人、協調不同醫療角色、定期電話訪視。

這些工作有三個共同特徵，使其對 AI 代理人特別困難：

1. **政策密度高**：每個決定都必須依據醫療指南、保險規則、內部操作程序，規則龐雜且不斷更新。
2. **多角色切換**：一個完整流程需要醫師、協調員、護理主管、醫療審查員多個角色接力，任何交接都無法回頭。
3. **多邊互動**：過程中有真實的對話（如醫院醫師與保險公司的「點對點複查」通話），不是單純的工具調用。

## 怎麼做

研究團隊打造了 **χ-Bench（CHI-Bench，Clinical Healthcare In-Situ Benchmark）**：

- **模擬器**：20 個醫療行政軟體應用（電子病歷、保險審查系統、護理管理平台等）透過 87 個模型上下文協議（MCP，Model Context Protocol）工具暴露給代理人，場景高度仿真。
- **知識庫技能**：一本包含 1,279 份 Markdown 文件的「管理照護運營手冊」，涵蓋三個角色的操作工作流程、醫療知識庫、平台使用說明。
- **三種任務類型**：（1）提供者事前授權（PA）——醫院端申請；（2）保險方使用管理審查（UM）；（3）護理管理（CM）——護理師追蹤和協助病人。
- **評分機制**：結合確定性規則檢查（例如表格欄位是否正確填寫）和 LLM 評審的評分，現場（in-situ）即時計分，不需人工標注。

共評估 30 種代理人框架與模型配置的組合，每個配置在每個任務類型各跑 15 個案例，共 75 個任務情境。

## 結果

**成績慘淡，遠低於期望：**

- 最佳組合（Claude Code + Claude Opus 4.6）pass@1 = **28.0%**（整體）
- 在嚴格的 pass^3 指標（同一任務三次都成功）下，**沒有任何代理人超過 20%**
- 在「馬拉松模式」（一個 session 跑完所有任務，不重置）下，成功率崩潰到只剩 **3.8%**

三種任務類型之間的表現差異很大：護理管理（CM）對部分 Claude 模型更友好（Opus 4.6 達到 41.3%），但保險端的利用管理審查（UM）和事前授權（PA）對所有模型都很難。Claude Haiku 4.5 在 PA 任務上完全失敗（0.0%）。

## 做不到的地方

- **測試場景雖高仿真，仍是模擬**：真實醫療場景的不確定性（如病人不配合、保險公司系統宕機、規則突然改變）未必能完整重現。
- **評分仍依賴 LLM 評審**：部分評分項目用 LLM 判斷，存在評審本身的偏差和不穩定性。
- **只測商業前沿模型**：開源模型未被納入，不知道在成本敏感的醫療機構中，性價比更高的選項表現如何。
- **工作流程邊界設定**：任務設計聚焦在「可驗證完成」的結構化流程，醫療中大量非結構化、依賴隱性知識的判斷尚未被涵蓋。

## 想自己判斷這篇可不可信？

| 訊號 | 這篇的情況 | 怎麼解讀 |
|---|---|---|
| 任務數量 | 每種任務 15 個案例，共 45 個情境 | 樣本偏小，可能低估高難度長尾任務的影響 |
| 模型版本 | 所有實驗在 2026 年 5 月特定模型版本下進行 | 結果有時效性，模型版本改版後可能不同 |
| 評分公正性 | 混合確定性規則 + LLM 評審 | LLM 評審部分有自我評分偏差風險 |
| 知識庫品質 | 1,279 份 Markdown 文件的操作手冊，由醫療機構參與設計 | 手冊品質對結果影響極大，但細節未完整公開 |
| 機構參與 | 包含 Johns Hopkins Medicine、Wellstar Health System 等實際醫療機構 | 場景設計有臨床基礎，不完全是學術想像 |

## 怎麼看這件事

醫療行政流程是「政策密度極高的長流程任務」的典型代表。χ-Bench 的重要性不只在醫療本身，而在於它明確指出了當前 AI 代理人的結構性瓶頸：不是不夠聰明，而是缺乏跨角色的流程記憶、對大量政策文件的正確遵從、以及在交接點不回頭的不可逆決策能力。在金融、法律、政府審批等類似場景，相似的挑戰很可能同樣存在。
