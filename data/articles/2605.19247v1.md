# 讓 AI 設計神經網路:當搜尋空間是「無限大」時,你怎麼避免它瞎找?

> 原始論文:Structuring Open-Ended NAS: Semi-Automated Design Knowledge Structuring with LLMs for Efficient Neural Architecture Search
> 作者·單位:Yuiko Sakuma、Masakazu Yoshimura、Zitang Sun、Junji Otsuka、Atsushi Irie、Takeshi Ohashi(Sony Group)、Marcel Gröpl(ETH Zurich)
> arXiv:2605.19247v1 ・ 分類:電腦視覺・神經架構搜尋

一句話說重點:設計神經網路架構過去要靠人工試錯,有了「神經架構搜尋」(NAS)後 AI 可以幫你試,但傳統 NAS 只在有限模板裡找;新一代 LLM-輔助 NAS 雖然能無限制地生新架構,卻常常瞎逛。研究者把「網路設計的領域知識」**結構化**成樹狀模板,再用三種互補的變異策略,讓 LLM 在開放空間裡有方向地探索。

---

## 先說情境:神經網路架構誰來設計?

ResNet、Transformer、ConvNeXt 這些經典架構,**都是人手工設計的**——很費時、很費腦,還受限於設計者經驗。為了自動化這個過程,出現了 **NAS**(Neural Architecture Search,神經架構搜尋):讓電腦自己搜尋出好的網路架構。

NAS 的兩個世代:

- **第一代 NAS**:在預先定義好的「搜尋空間」(operator/block 模板)裡找最佳組合。**效率高,但天花板低**——只能組合既有積木,難生創新架構。
- **第二代 LLM-輔助 NAS**:讓大語言模型(LLM)直接寫網路程式碼。**開放空間,沒有預定模板**——可以生出任何想得到的新結構。

但**開放空間有自己的問題**:搜尋空間爆炸,LLM 容易被自己的偏見(例如「我覺得 Transformer 一定比較好」)帶歪、被低品質想法干擾,**效率反而比第一代差**。

## 怎麼做:「半自動化結構化的領域知識」

研究者提出的關鍵想法:**不要讓 LLM 漫無目的地生架構,而是先把「神經網路設計的領域知識」結構化成一棵樹**,再讓 LLM 沿著這棵樹的分支去想。

兩個技術組件:

**(A) 模型設計屬性樹**(Model Design Attribute Tree)
- 先用半自動方式定義一個高層結構模板:主類別 → 子類別 → 粒度(operator level、feature level 等)。
- 讓 LLM 讀大量論文,把每一篇的設計想法**填**進這棵樹的對應分支。
- 結果:一個豐富又有結構的搜尋空間,內含結構化的設計知識。

**(B) FairNAD 多型變異**(Multi-type Mutation)
有了結構化搜尋空間還不夠,還要有好的探索演算法。FairNAD 結合三種變異:

1. **公平想法採樣變異**:把模型設計知識庫 D_kn 中的想法**公平抽樣**,避免被 LLM 偏好特定類別牽著走。
2. **帕雷托感知變異**(Pareto-aware mutation):在「準確率 vs 效率」的帕雷托前沿上採樣,確保探索兼顧大模型和小模型。
3. **LLM 驅動的迭代變異**:把歷史搜尋結果(Arch 1: acc 81%, idea A; Arch 2: acc 82%, idea B)餵給 LLM,讓它根據歷史**逐步精煉**變異方向。

最後接上「**LLM 程式碼生成 + 反饋迴圈**」,包含執行驗證、預算驗證、結構驗證、評估四階段檢查,保證生出的程式碼能跑、不超預算、結構合理。

## 結果:CIFAR/ImageNet 上的顯著提升

在三個標準 NAS benchmark 上:

| 資料集 | 比 SOTA 提升 |
|---|---|
| CIFAR-10 | +0.84 點 |
| CIFAR-100 | +2.17 點 |
| ImageNet16-120 | +2.35 點 |

CIFAR-100 和 ImageNet16-120 的改善尤其顯著——這些是更難的資料集,通常代表方法的真正泛化能力。

## 圖解:FairNAD 三種變異策略

![FairNAD 的多型變異流程。上方有兩個資料庫:左邊是「模型設計知識庫 D_kn」,內含從論文整理的設計屬性樹;右邊是「歷史資料庫 D_hist」,記錄每次搜尋過的架構與分數。三個並列的變異模組:**I. 公平想法採樣變異** — 從 D_kn 公平抽樣想法生成多個子代;**II. 帕雷托感知變異** — 在「accuracy vs efficiency(params)」的帕雷托前沿散點圖上,以 Pareto sampling 同時抽出 Large model 與 Small model 候選,再透過 Hyperparameter adjustment / Upscaling 變形;**III. LLM 驅動的迭代變異** — 把 History(Arch 1: acc 81% Idea A、Arch 2: acc 82% Idea B…)餵給 LLM 做 iterative refinement,根據歷史調整想法。三個變異結果都送進下方「LLM 程式碼生成 + 反饋迴圈」,經過 Execution / Budget / Structural verification 與 Evaluation 四階段檢查。](assets/articles/2605.19247v1-fig1.webp)

這張圖把整個 FairNAD 搜尋流程畫成三個並排的變異產線。**最左邊那條(I)** 解決「LLM 容易偏向自己熟的設計」這個問題——強制從知識庫公平抽樣。**中間那條(II)** 解決「光追求準確率會生成超大模型」這個問題——在準確率/參數量的帕雷托前沿同時保留大小不同的候選,還可以做超參數調整或 upscale。**右邊那條(III)** 是 LLM 的擅長之處——根據歷史學習,逐步精煉想法。三條產線的結果匯流到最底下,經過「能不能跑→預算夠不夠→結構合不合理→實際評估」四關才被接受。整套設計是「**用結構化知識給 LLM 上韁繩,用多元變異避免它走偏**」的工程結晶。

## 它做不到 / 沒解決的

論文坦白幾點限制:

- **領域屬性樹仍需人工設計**:「樹」的高層結構是半自動的,還是要研究者先給個模板。換領域(NLP、語音、Graph)可能要重新設計樹結構。
- **依賴 LLM 的程式碼生成品質**:LLM 寫的程式碼可能有 bug,反饋迴圈雖然會過濾,仍是工程瓶頸。
- **驗證 benchmark 規模**:CIFAR-10/100、ImageNet16-120 都是相對小規模的 NAS benchmark。大型實際任務(完整 ImageNet、COCO 物件偵測等)的效果未驗證。
- **搜尋總成本**:每次變異都要 LLM 生程式碼 + 真實訓練評估,絕對運算成本仍然不便宜。

## 怎麼看這件事

**為什麼在意?** 神經架構設計是「**好設計師很貴、好架構很值錢**」的領域。如果 LLM-輔助 NAS 真的能在開放空間裡有效率地找到 SOTA 架構,等於把「找好架構」這件事從**人類專家瓶頸**變成**運算瓶頸**——後者更容易擴展。

**哪裡該保留懷疑?** 「LLM 輔助 NAS」這個方向目前還在早期,有兩個常見質疑要持續觀察:(1) LLM 是不是只是記住了論文中已有的架構、把它們重新拼湊?(2) 在 toy benchmark 上的改善能不能 scale 到真實大型任務?這篇沒有完全回答。

**怎麼理解這個方向?** 這篇代表了 NAS 領域的一個重要趨勢:**從「在有限積木箱裡組合」走向「在開放空間裡受結構化先驗引導的探索」**。同樣的「**用結構化領域知識引導 LLM**」的思路,也適用於程式碼生成、分子設計、材料探索等其他開放空間搜尋問題。
