# 讓 AI 助理「自毀記憶」：一種無需駭入就能讓它永久失效的攻擊

> 原始論文：OEP: Poisoning Self-Evolving LLM Agents via Locally Correct but Non-Transferable Experiences
> 作者·單位：Kaixiang Wang、Jiong Lou、Zhaojiacheng Zhou、Jie Li（上海交通大學）
> arXiv：2605.18930v1 ・ 分類：cs.CR / cs.AI / cs.LG

一句話說重點：透過提供「局部正確但無法推廣」的邊界案例，加上誇大的後果描述，就能讓 LLM Agent 在自我反思時把這個局部方法蒸餾成高優先規則——不需要任何系統提示或記憶庫的特權存取，攻擊成功率超過 50%。

---

## 現代 AI Agent 如何學習？

當前的 LLM Agent（大型語言模型智能體）不只是問答機器——它們有**長期記憶**，能從過去的執行記錄中汲取經驗，透過「反思（reflection）」把成功和失敗的教訓提煉成規則，然後在下一次任務中應用。例如 Claude Code、OpenClaw 等 Agent 產品，都依賴這種自我演化機制來提升任務完成率。

這帶來一個問題：**記憶和反思機制能不能被操控？**

現有的 Agent 記憶攻擊通常需要「特權」：直接竄改記憶庫、注入惡意指令，這些容易被安全過濾器偵測。本研究發現了一個更隱蔽的漏洞。

## OEP：讓 Agent 自己毒化自己

**OEP**（Obsessive Experience Poisoning，執念式體驗投毒）的核心洞察是：反思型 Agent 存在三個認知弱點——

1. **視角侷限（Perspective Confinement）**：Agent 只能看到局部的任務情境，無法自主判斷一個方法是否具有普遍適用性。
2. **反思過度信任（Asymmetric Trust）**：Agent 傾向過度相信自己生成的反思結果，把「我在這個案例成功了」泛化為「這是一個普遍原則」。
3. **損失厭惡偏斜（Risk-Sensitive Utility Skew）**：如果一個方法與「嚴重後果」掛鉤，Agent 的反思會優先規避這個後果，而不是精準評估情境適用性。

OEP 利用這三個弱點，分三步實施攻擊：

**第一步：構造「乾淨邊界案例」**
攻擊者從任務分佈的尾部（tail region）找一個真實但罕見的邊界案例，並給出一個局部正確的非標準解法 m_e——這個方法對這個案例有效，但在一般情境下應該失效。

**第二步：對抗後果三元組（ACT，Adversarial Consequence Triplet）**
把邊界案例、局部解法 m_e、以及一個誇張但看似可信的負面後果 c_adv 組合成一張「體驗卡」。負面後果的目的是觸發 Agent 的損失厭惡：「如果不用 m_e，可能導致 XX 嚴重問題。」

**第三步：使用者層級注入**
攻擊者只需以普通使用者身份提交這個精心構造的任務，Agent 在反思時會局部驗證 m_e 的有效性（確實對邊界案例管用），同時因為嚴重後果的威脅，把 m_e 蒸餾為高優先的記憶規則——然後這條錯誤的規則就會在後續正常任務中持續造成錯誤。

## 實驗結果

在三個不同領域的 GPT-4o Agent 測試中：
- OEP 的攻擊成功率（Attack Success Rate，ASR）**超過 50%**。
- 在 LLM 稽核防禦（一種讓另一個 LLM 審查記憶內容的防禦方法）下，OEP **仍優於現有攻擊方法**——因為它的輸入內容既局部正確又語義合理，不含明顯惡意指令。

## 做不到的地方

- **成功率不穩定**：50% 以上的 ASR 聽起來高，但也意味著近半的攻擊失敗，成功率受任務類型和 Agent 設計影響。
- **只測試 GPT-4o**：不同架構、不同記憶機制的 Agent 可能有不同的漏洞敏感度，泛化性未確定。
- **需要任務領域知識**：構造有效的邊界案例需要攻擊者對任務領域有相當瞭解，不是完全無差別的攻擊。
- **防禦策略未深入探討**：論文主要分析攻擊，對於如何從根本上防禦 OEP（例如記憶規則的反事實驗證）只有初步討論。

圖中展示 OEP 的完整三階段流程：左側（Phase 1）是從任務分佈尾部採樣邊界案例，並構造局部正確但不可推廣的解法（綠色打勾表示局部正確，紅色叉表示全局不可推廣）；中間（Phase 2）是把邊界案例、解法和誇大負面後果組合成 ACT，此時 Agent 的效用函數被扭曲（正常效用 vs. ACT 偏斜效用的對比直方圖）；右側（Phase 3）是注入與過度泛化——攻擊者提交 ACT 後，Agent 的認識論過濾器因為局部語義合理性而放行，反思過度誘導（over-induction）將局部方法寫入記憶庫，最終導致正常任務的下游推理失敗（標記為 Failure）。

## 怎麼看這件事

OEP 揭示了 LLM Agent「自我演化」機制的一個深層漏洞：當 Agent 把「過去經驗」當作學習素材，它其實正在根據有限的局部觀察形成普遍規則——這和人類的「過度概括」偏見驚人地相似。更令人警惕的是，這種攻擊不需要任何特殊權限，普通使用者層級的互動就足夠。如果你在使用或部署有自我記憶機制的 AI Agent，這篇論文提醒你「反思機制本身可能是攻擊面」——設計時需要加入記憶規則的反事實驗證層。
