# 把語言模型那套 MoE 搬到影片生成，會發生什麼災情？這篇全部解剖給你看

> 原始論文：Sparse Mixture-of-Experts Routing in Visual Diffusion Transformers: Diagnosis, Boundary Calibration and Evolutionary Roadmap from Routing Collapse to Selective Deadlock
> 作者·單位：Haiying Sha（獨立研究者）
> arXiv：2605.19378v1 ・ 分類：影片生成・MoE 訓練動力學

一句話說重點：DeepSeek、Qwen3 用「**專家混合（MoE）**」把語言模型參數爆量擴展很成功，但同樣手法搬到影片擴散 Transformer 上會卡死——本文用 5B 影片模型實測，發現五種失敗模式：路由飽和、選擇性 deadlock、U 形死亡分布、bfloat16 精度陷阱，並提出 **「功能冗餘假說」** 解釋為什麼。

---

## 背景：MoE 是 LLM 變大的關鍵，但視覺領域還在試錯

「Mixture-of-Experts（MoE，專家混合）」是讓大模型參數突破兆級的關鍵架構：把 FFN（前饋網路）拆成多個「專家」子網路，每個 token 只活化 1-2 個專家，於是**模型參數可以爆量，但實際算力不變**。DeepSeek V4 有 1.6 兆參數、384 個專家／層、每個 token 只激活 6 個，這就是這條路。

但這條路在語言領域成功的前提是「token 之間語義斷裂強」——「貓」和「狗」這兩個 token 在表徵幾何上差很多，路由器自然能學會分流。問題是視覺 token **不是這樣**：相鄰 patch 的特徵高度冗餘、又會被擴散時間步攪動，路由器拿到的訊號模糊不清。

於是「視覺 MoE 大規模部署」雖然有 ProMoE、Mamoda2.5、DiffMoE 等先例，但**訓練動力學的失敗模式從沒被系統性解剖過**。這篇就是來填這個坑的。

## 怎麼做:把 5B 稠密影片模型「變成」MoE 然後看它怎麼壞

作者拿一個預訓好的影片編輯模型（Kiwi-Edit，含 Wan2.2-TI2V-5B 影片擴散主幹 + Qwen2.5-VL-3B 多模態編碼器，共 ~8B 參數）做 dense-to-MoE 改造，遵守他歸納的「**三條轉換律**」：

1. **專家結構一致**：所有 routed expert 結構與原 FFN 完全一樣。
2. **1:1 權重克隆**：兩個 routed experts 各自從原 dense FFN **完整複製**權重，避免初始化造成的差異。
3. **shared expert 初始化策略**：驗證期 shared expert 設為零（保證等價於原稠密模型）；訓練期改為**極小非零噪聲**（10⁻⁴），讓它有梯度可學。

**只有 router 從隨機開始學**——所以任何路由失敗都不能用「預訓好的優勢」遮蔽。

他們依序測三種 router：**線性、MLP、cross-attention**，跟蹤 30 層、5000 步、6500 萬 token 的路由決策時序，把問題完整刻畫出來。

## 結果：五種失敗模式

1. **線性 router → 全局軟飽和**：Softmax 進入飽和區，所有梯度趨近於零；專家被同化（cosine 相似度 > 0.99）——所有專家收斂成同一個，MoE 等於沒拆。
2. **MLP router → 選擇性 deadlock**：全局問題消失，但**約 1/3 的層**退化成「只用單一專家」。把 auxiliary loss（負載均衡損失）係數從 0.01 加到 0.08 完全沒用——這條傳統補救藥失效。
3. **Cross-attention router → 自發復甦但仍有殘留**：少數層居然能從 deadlock 自行翻身（業界第一次觀察到），但仍有 **9 層** 頑固卡死。
4. **U 形死亡分布**：deadlocked 層集中在「**淺層視覺處理**（1-10 層）」跟「**深層語義整合**（18-25 層）」，中間層保持均衡——這個結構性形狀對所有 router 一致。
5. **bfloat16 精度陷阱**：MoE 訓練常用 bfloat16 混合精度，但極小的權重更新會被硬體截斷成零。解法是**把 master copy 保留在 float32**，前向才轉 bf16。

最後作者提出一個解釋叫「**功能冗餘假說（Functional Redundancy Hypothesis）**」：deadlock 不是 bug，是系統的「合理等待策略」——當 shared expert 還沒長到夠強之前，routed experts 被刻意噤聲，等共享專家成熟才釋放。這跟系統生物學裡的功能冗餘理論對得上。

## 圖解：表面健康但路由其實已經出事

![Figure 1：線性 router 訓練 2000 步後，每層的「少數派專家利用率」。](assets/articles/2605.19378v1-fig1.webp)

橫軸是 layer 編號（0–29），縱軸是「**少數派專家利用率**」（Minority Expert Utilization）——也就是除了主導專家以外，其他專家被路由到的 token 比例。**綠色長條**是「健康」的層（>20%），**橘色與紅色**是進入 deadlock 邊緣的層。

乍看 26 層綠色一片大好——但這正是作者要警告你的「**表面健康騙術**」。仔細看：layer 0、1、5、6、8、9、16、19、27 這些**橘紅色**長條已經低於 5% 邊界線（虛線），代表這些層**完全靠單一專家撐**。而且這些「壞掉」的層出現位置不是隨機的——它們**集中在淺層**（前 10 層的視覺處理）跟一些深層位置，就是後文要講的 **U 形分布** 的早期徵兆。

更糟的是：增加 aux_loss（負載均衡損失）係數**沒辦法救這些層**——傳統 MoE 訓練的「均衡藥方」對視覺擴散模型失靈了。

## 它做不到 / 沒解決的

- 本文是**診斷**，**不是解法**——作者明確說「完全消除視覺 MoE 的死專家需要從共享專家初始化、權重差異化、或升級路由範式（如 Expert-Choice）著手」，但沒給最終 production-ready 的修法。
- 所有實驗在**單一基座模型**（Kiwi-Edit / Wan2.2-TI2V-5B）上，跨架構的可推廣性需更多驗證。
- 「功能冗餘假說」目前是**直覺＋系統生物學類比**，沒有嚴格數學證明。
- 影片品質指標（VBench、FVD 等）沒有完整對照，重點放在路由行為而非生成品質。

## 怎麼看這件事

**為什麼在意？** 影片生成模型參數越來越大、推論成本越來越貴，業界都在等「視覺版的 MoE」來複製 LLM 的成本曲線奇蹟。但這篇直接告訴你：「直接套用 LLM 那套會炸」，而且炸的方式不是 OOM，是訓練看似在進行、實際路由已死。對任何想做視覺 MoE 的團隊來說，是踩雷地圖。

**哪裡該保留懷疑？** 一篇「獨立研究者」的長篇診斷論文，沒同儕審、沒有大廠對照實驗，「功能冗餘假說」也偏哲學性類比。但實驗本身有 6500 萬 token、5000 步、30 層的時序資料，這個量級的觀察很難造假——所以「現象描述」這部分可信度比「假說解釋」高得多。

**怎麼理解這個方向？** 這篇是視覺 MoE 訓練動力學從「**經驗黑盒**」走向「**系統性病理學**」的一篇墊腳石。它對應到 LLM 領域早年「expert collapse」的研究 ——只是現在輪到視覺。如果你的工作會碰到擴散模型 + MoE，這份「死法清單」應該收藏。
