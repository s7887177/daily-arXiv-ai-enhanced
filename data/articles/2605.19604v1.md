# 讓 AI 代理人按規矩辦事：把「說明文件」升格為「可執行合約」

> 原始論文：Formal Skill: Programmable Runtime Skills for Efficient and Accurate LLM Agents
> 作者·單位：Xi Zhang、Meijun Gao、Yuntian Zhao、Xinyu Tan、Yilun Yao、Feiyu Wang、Yanshu Wang、Dingsiyi、Tong Yang
> arXiv：2605.19604v1 ・ 分類：cs.AI

一句話說重點：現有 AI 代理人的「技能」多半是一份自然語言說明文件，模型看了可能照做可能不照做；這篇論文把技能升格成可執行的狀態機，讓違規行為直接被程式攔截，同時大幅節省 token 用量。

---

## 問題：AI 代理人的「技能說明書」太鬆散了

現代 AI 代理人（agent）已不只是聊天機器人，它們能讀寫檔案、執行程式碼、呼叫外部工具，在真實的工作環境中完成多步驟任務。要讓代理人可靠地完成複雜任務，需要賦予它「技能」——比如「如何修復程式碼 bug」、「如何搜尋文件並整理報告」。

目前的做法大致分兩種：
1. **文字型技能（Markdown/SKILL.md）**：把步驟、注意事項、禁止行為全部寫成自然語言文件。每次執行都要把整份文件塞進 prompt，耗費大量 token；更重要的是，模型「讀了但不一定照做」，因為沒有程式碼強制執行這些規則。
2. **工具呼叫（Function calling / MCP）**：定義每個動作的 JSON 介面，讓工具呼叫更結構化，但這些工具通常沒有「技能層級的工作流狀態」——不知道現在在哪個階段、失敗了要怎麼回復。

結果是：複雜任務中代理人常常亂了套、跳過驗證就宣告完成，或在失敗後不知道下一步。

## Formal Skill 的核心概念

這篇論文提出 **Formal Skill**，把技能從「文件」升格為「可執行合約」，包含五個要素：

1. **JSON 元資料與動作介面**：技能的機器可讀描述，模型看到的是簡短的介面說明，不是長篇文件。
2. **Python 執行器（Executor）**：每個動作對應一個 Python 函式，帶確定性驗證和副作用邊界。比如「套用 patch」這個動作會自動檢查路徑合法、patch 格式正確，而非靠模型自己判斷。
3. **Hook 鉤子控制邏輯**：在每次 LLM 呼叫和工具呼叫的前後，hook 可以過濾可見工具、拒絕不合法呼叫、阻止在驗證未通過時完成任務。
4. **技能本地狀態（Skill-local state）**：紀錄當前階段（`phase`）、驗證是否通過（`verification_passed`）、產出物是否齊全等欄位，讓恢復邏輯可追蹤。
5. **技能路由（Routing）**：決定什麼任務應該觸發哪個 Formal Skill，讓技能的選擇本身也是結構化的。

這套抽象的核心思想是**分工**：語言模型繼續負責推理和決策，程式碼負責強制執行邊界和流程。

## 論文也實作了完整的執行框架 FairyClaw

FairyClaw 是一個事件驅動的代理人執行環境，實作了 Formal Skill 的所有概念，包括技能路由、Hook 管線、帶型別的歷史紀錄（IR）、持久化狀態、子代理人委派。

在 Harness-Bench 基準測試（六個代理人執行環境的比較）上，FairyClaw 平均分數排第三，但每個任務的 token 消耗比其他系統平均低 48%，比次低的系統還低 33%。在最能體現 Formal Skill 優勢的任務上，FairyClaw 表現尤為突出。

## 做不到的地方

- **技能的撰寫門檻提高**：Formal Skill 需要設計 JSON 介面、Python 執行器和 hook 邏輯，比寫一份 Markdown 說明文件複雜得多。作者承認這是實際成本，並提出可以用 LLM 從現有 Markdown 技能自動合成 Formal Skill 組件——但這個合成流程本身的可靠性未有深入評估。
- **Harness-Bench 的可推廣性**：這是一個相對新的基準，外部機構是否認可其評估效度仍有待觀察。
- **非軟體工程任務**：論文展示的核心案例（CODEREPAIROPS，程式碼修復）是軟體工程任務，對其他領域（如資料分析、辦公自動化）的適用性尚未系統評估。

這是論文示範的程式碼修復技能（CODEREPAIROPS）的狀態機。技能從「REPRODUCE（重現問題）」開始，只有收集到足夠的錯誤證據才能推進到「PATCH（套用修復）」；修復後必須通過「VERIFY（結構化驗證）」，才能進入「REPORT（輸出報告）」並完成任務。若驗證失敗，可選擇進入「DIAGNOSE（診斷）」收集更多上下文再重試。圖中最底部的提示「只有在驗證通過且所需產出物存在後才能結束」是 hook 強制執行的硬規則，不是口頭建議。

## 怎麼看這件事

AI 代理人能不能在生產環境中可靠運作，「技能的可靠性」是核心瓶頸之一。把技能從自然語言文件升格為可執行合約，這個方向對任何想讓代理人「按規矩辦事」的人都有直接價值。

Formal Skill 的思路讓人聯想到軟體工程中「契約式程式設計（Design by Contract）」的傳統，把前置條件、後置條件、不變式從文件層面移到程式碼層面。這不是全新發明，但在 LLM 代理人的場景下應用是值得的工程努力。token 節省效果如果能被獨立複現，這將是一個實際部署時頗具吸引力的方案。
