# 智慧手環的資料太多，AI 怎麼知道該看哪一段？把身體數據畫成知識圖譜

> 原始論文：Query-Conditioned Graph Retrieval for Contextualized LLM Reasoning in Personalized Wearable Data
> 作者·單位：Zhenyu Lu（卡內基梅隆大學）、Mahyar Abbasian、Amir M. Rahmani（加州大學爾灣分校）
> arXiv：2605.18763v1 ・ 分類：cs.IR / cs.AI

一句話說重點：WAG 框架把穿戴裝置的長期感測資料組織成知識圖譜，讓 LLM 能按查詢需求只取出最相關的子圖，問答勝率達 70% 以上。

---

## 問題在哪

智慧手環、健康監測手錶等穿戴裝置會長期累積多樣感測資料：心率、步數、血氧、睡眠分段……使用者問一句「我最近睡眠品質怎麼樣？」，系統卻不知道該給 AI 看哪一段資料——全部丟進去太貴又降低準確度，隨便挑又可能漏掉關鍵訊號。

現有方法大多需要人工為特定任務準備資料脈絡（Context），難以應對開放式查詢，也無法同時整合長期趨勢和短期異常。

## 怎麼做

研究者提出 **WAG（Wearable As Graph，穿戴資料圖譜）**，整個框架分四步：

1. **查詢集建構（Query Set Construction）**：從真實世界穿戴資料集挑選參與者，根據資料品質（缺值率、連續性、感測器多樣性）篩選，再自動生成涵蓋單指標與多指標查詢的標準題庫。

2. **知識圖譜建構（Knowledge Graph Construction）**：把各種健康指標（心率、睡眠等）與使用者個人化資料整合成**個人化知識圖譜（PKG, Personalized Knowledge Graph）**。圖的邊（關係）由三個來源組成：網路搜尋、醫療資料庫和 LLM 生成，持續更新。

3. **查詢條件化子圖取回（WAG Retrieval）**：LLM 先從查詢中萃取涉及的指標、時段和「查詢開放度（Openness Score）」，再用**階層式貝葉斯建模（Hierarchical Bayesian Modeling）**捕捉長期群體和個人模式，加上偵測短期異常的局部關係，動態選出最相關的子圖。

4. **評估（Evaluation）**：由 LLM 和人類雙重評分，指標涵蓋洞察性、相關性、有依據性、個人化程度與安全性。

## 結果

在超過 10,000 個真實穿戴資料問答對的評估中，WAG 對比傳統 RAG 和無結構檢索基準方法，達到約 **70% 的勝率**（LLM 和人類評分一致）。框架在涉及多個感測器、長時間窗的複雜查詢上優勢更明顯。

## 做不到的地方

- 論文主要使用已公開的穿戴資料集，真實臨床場景中資料噪聲和感測器漂移的影響尚未充分評估。
- 知識圖譜邊緣權重的初始設定依賴外部 LLM，若 LLM 幻覺出錯誤關係，可能影響整個圖的品質。
- 查詢開放度評分機制由 LLM 自動產生，缺乏對此機制本身的獨立驗證。
- 系統延遲（子圖抽取 + LLM 推論）在即時健康監測場景中的可行性尚未評估。

## 怎麼看這件事

穿戴裝置每天產生的資料遠超人眼能分析的上限，讓 AI 「聰明地」選取脈絡是關鍵瓶頸。WAG 的圖譜思路有其新意，把靜態嵌入換成動態個人化圖結構是往正確方向邁進的一步。但健康 AI 的風險較高，在臨床驗證和安全性評估有更充分的結果之前，這套框架目前更適合研究探索而非直接部署。
