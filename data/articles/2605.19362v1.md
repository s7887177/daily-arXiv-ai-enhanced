# AI Agent 的「說明書」寫得讓人看懂了嗎？878 份技能規格的調查報告

> 原始論文：Toward User Comprehension Supports for LLM Agent Skill Specifications
> 作者·單位：Zikai Alex Wen（華盛頓大學塔科馬分校工程技術學院）
> arXiv：2605.19362v1 ・ 分類：cs.HC, cs.AI

一句話說重點：878 份網路安全 AI Agent 技能規格文件中，只有 2.3% 同時包含使用者真正需要的四種理解支撐要素，多數文件根本讓人不知道這個技能在幹什麼。

---

## 背景：AI Agent 技能也有「使用者手冊」問題

隨著大型語言模型（LLM）驅動的 Agent 愈來愈普及，現在有各種公開的「技能包（skill packages）」可以讓 Agent 載入使用——就像手機的 App，讓 Agent 具備分析 DNS 日誌、偵測漏洞、生成資安報告等能力。

每個技能通常附帶一份 **SKILL.md** 規格文件，供用戶在安裝前了解這個技能「能做什麼」。但問題是：這些說明書，真的讓人看懂嗎？

現有的技能安全審計集中在「有沒有惡意指令」、「會不會提示注入」，但**一個不惡意的技能，不代表用戶能正確理解它、用對場合**。這篇論文研究的是另一個問題：規格文件有沒有給用戶足夠的資訊，讓他們知道這個技能「吃什麼、吐什麼、適用哪裡」？

## 方法：四個「理解錨點」

作者定義了四個用戶理解技能所需的關鍵要素（稱為「comprehension anchors，理解錨點」）：

1. **操作基礎（Operational Basis）**：技能如何運作？（用了哪些工具、API 或方法）
2. **輸出契約（Output Contract）**：技能會產生什麼輸出？格式、欄位是什麼？
3. **邊界揭露（Boundary Disclosure）**：技能做不到什麼？有哪些限制或前提？
4. **能力示例（Example Capability Demonstration）**：有沒有具體的輸入樣本、輸出範例、或測試案例？

用規則式編碼（rule-based coding）掃描 878 份網路安全領域的 SKILL.md 文件，統計各錨點出現的比例。

## 結果

數字相當令人憂慮：

- **操作基礎**：92.1% 的文件有提及（最普遍）
- **輸出契約**：只有 51.4% 有說明輸出格式
- **邊界揭露**：只有 51.8% 有揭露限制
- **能力示例**：只有 **19.0%** 有提供具體範例或預期輸出
- **四者齊備**：只有 **2.3%**（878 份中只有約 20 份）

進一步以 6 份 DNS/C2 遙測相關技能做質化分析：有提供示例的技能，用戶能直接從規格文件建立初步的本地驗證測試；沒有示例的技能，用戶往往要去讀底層的 helper code 才能搞清楚輸入格式和輸出欄位。

## 做不到的地方

- 樣本來自 878 份網路安全技能，可能不代表其他領域（生產力工具、資料分析等）
- 使用規則式編碼而非人工評閱，可能誤判部分有隱含示例的文件
- 質化分析的 DNS/C2 子集只有 6 份，難以歸納一般性結論
- 論文本身是 5 頁的短篇工作（workshop paper 規格），尚未同行審查

## 圖解

本文主要以表格呈現統計結果，沒有適合獨立展示的流程圖或對比圖。核心數據：878 份技能規格中，操作基礎覆蓋率 92.1%，能力示例覆蓋率僅 19.0%，四項全備率僅 2.3%。

## 怎麼看這件事

這篇論文研究的問題聽起來有點「meta」——不是研究 AI 本身，而是研究**描述 AI 能力的文件**。但這個問題其實很重要：當 AI Agent 技能像 App 一樣在市集流通，用戶憑什麼判斷「這個技能適合我的用途？」

對一般用戶而言，SKILL.md 就是他們唯一能讀的「說明書」。如果說明書不夠清楚，用戶可能用了不適合的技能，或對輸出結果有不合理的期待——在網路安全這樣風險高的領域，後果可能很嚴重。

「透明度」不只是倫理問題，更是可用性問題。這篇論文的啟示是：AI Agent 生態系統在成熟之前，需要更好的規格文件標準。
