# AI 能蓋橋嗎？這個測試平台讓你用物理引擎直接檢驗答案

> 原始論文：BuildArena: A Physics-Aligned Interactive Benchmark of LLMs for Engineering Construction
> 作者·單位：Tian Xia、Tianrun Gao、Wenhao Deng、Long Wei、Xiaowei Qian、Chenglei Yu、Tailin Wu（西湖大學 AI for Scientific Simulation and Discovery Lab）
> arXiv：2510.16559v5 ・ 分類：cs.AI

一句話說重點：BuildArena 是第一個讓大型語言模型（LLM）在物理引擎裡實際「蓋東西」並驗證結構是否符合靜力學和動力學的互動基準，目前最強模型也只能通過部分任務。

---

## 背景：語言模型會說「建橋」，但蓋得出來嗎？

工程建設自動化的目標是：把一份自然語言的設計規格，轉化成一個在物理上切實可行的結構。這不只是「生成程式碼」——它要求 AI 同時理解：幾何空間（零件怎麼排列）、物理約束（會不會倒塌、零件會不會互相穿插）、以及逐步組裝的工程邏輯。

這個領域雖然有大量應用潛力（自動化 CAD、施工規劃、甚至遊戲設計），但現有的 LLM 基準（如程式碼生成、邏輯推理）幾乎沒有評估「物理上可行的三維結構建造」。結果就是：我們不知道目前的 GPT-4o、Gemini、DeepSeek 在這方面能做到什麼程度。

BuildArena 就是為了填補這個空白而生。

## 怎麼做：三種任務 × 物理引擎驗證

BuildArena 建立在 **Besiege**——一個被數百萬玩家驗證過的建設沙盒遊戲——之上，確保物理模擬與現實一致。

**三種任務類型**：

1. **Transport（搬運）**：建造一台機器，把指定物體從 A 搬到 B。涉及靜力學、動力學、車輪機構設計。
2. **Support（支撐）**：建造一個結構支撐指定載重，涉及靜力學平衡與承重。
3. **Lift（提升）**：建造機構把物體升起一定高度，涉及力的平衡與運動控制。

每種任務又分三個難度等級（L1-Easy、L2-Medium、L3-Hard），難度由以下因素決定：模組數量、幾何對稱性、目標解的獨特性、以及需要多少精確對齊。

**評估架構**：使用 3D 空間幾何計算函式庫，讓 LLM 可以用程式語言操作建設空間，而不是直接點擊遊戲 UI。評估指標是複合的：
- **TWR**（Thrust-to-Weight Ratio，推重比）：結構是否能自我維持運動
- **任務成功率**：是否完成目標動作
- **組裝有效性**：結構是否符合物理約束（無穿插、穩定）

**多代理工作流基線**：論文也提出一個五代理 LLM 工作流（Planner、Drafter、Reviewer、Builder、Guidance）作為基準，展示如何讓多個 LLM 協作完成建設任務。

## 結果：最強模型也只能勉強通過，難度決定一切

在九個前沿 LLM（GPT-4o、Gemini、Claude-4、DeepSeek-3.1、Qwen 系列、Kimi 系列等）上測試：

- 難度 L1（最簡單）的 Transport 任務，最好的模型（GPT-4o）成功率約 **65%**——仍有超過三分之一的機會失敗。
- 難度 L2/L3 任務成功率在大多數模型上**接近 0**。
- Support 任務表現普遍優於 Transport，因為靜力學推理比動力學規劃更接近語言模型的訓練分佈。
- Lift 任務由於需要精確的力控制邏輯，整體成功率最低。
- 所有模型在面對複雜多零件組合時，最常見的失敗是**幾何碰撞**（零件互相穿插）和**物理不穩定**（結構完成後立即倒塌）。

## 做不到的地方

- 目前基準僅包含靜態結構（橋、塔）和簡單機械運動，複雜機電整合（如液壓、電路）不在範圍內。
- 物理引擎採用遊戲等級的近似（非有限元素法），對精密工程設計的評估精度有限。
- 所有測試均在程式語言接口上進行，LLM 無法直接操作視覺 UI，未必能反映真實 CAD 工具的使用場景。
- 多代理工作流的計算成本高，大量推論 API 呼叫的費用在真實部署中可能難以承受。

## 想自己判斷這篇可不可信？

| 訊號 | 這篇的情況 | 怎麼解讀 |
|---|---|---|
| 評測模型多樣性 | 九個主流 LLM，跨 GPT、Gemini、Claude、DeepSeek、Qwen、Kimi 系列 | 不是針對特定模型調整的基準 |
| 物理驗證機制 | 所有結果由 Besiege 物理引擎直接測量，非 LLM 自評 | 評分客觀，不依賴模型自我打分 |
| 難度分層 | 三種任務 × 三個難度，每組有多個獨立設計 | 細粒度評估，不只是一個總分 |
| 代碼公開 | GitHub 連結已在論文中提供 | 可重現 |
| 失敗分析 | 論文有專節分析常見失敗模式（碰撞、物理不穩定） | 不只報告成功，也解釋為什麼失敗 |

## 怎麼看這件事

BuildArena 的意義不只是「又多了一個基準」。它代表一種評估 LLM 的新思路：把語言理解和物理世界直接對接，用真實的物理引擎來裁判——這比讓另一個 LLM 評分要可靠得多。目前的結果挺殘酷的：即使是最強的前沿模型，面對中等難度的工程建設任務也頻繁失敗。這提醒我們，「能說工程」和「能做工程」之間，可能還差著很長一段路。對於工程自動化 AI 的研究者來說，這個基準提供了一個清晰的努力方向。
