# 讓手機也能「認得出我在哪」：更快或更準，AI 視覺定位第一次可以在同一訓練後自由選

> 原始論文：Faster or Stronger: Towards Flexible Visual Place Recognition via Weighted Aggregation and Token Pruning
> 作者·單位：Zichao Zeng、June Moh Goo、Jan Boehm（倫敦大學學院）、Junwei Zheng、Weijia Fan、Rainer Stiefelhagen（卡爾斯魯厄理工學院）、Jiaming Zhang（湖南大學）
> arXiv：2605.20551v1 ・ 分類：cs.CV・cs.AI・cs.RO

一句話說重點：視覺地點辨識（VPR）系統需要在大型資料庫裡用影像找到「我之前來過這裡」，本文提出加權聚合（WeiAD）和 token 剪枝（WeiToP）兩個模組，讓同一個訓練好的模型在推論時能彈性調整「要快還是要準」，無需重新訓練。

---

## 「認地方」這件事為什麼很難

想像機器人或無人車要確認「我現在在哪條街？」，做法是把當前相機畫面和資料庫裡幾百萬張參考照片比對，找到最像的那張——這就是視覺地點辨識（Visual Place Recognition，VPR）。

難點在於：同一個地方在不同光線、不同季節、不同角度看起來差很多。冬天的積雪、夜晚的燈光、相機偏了 30 度——都可能讓「明明是同一個地方」的兩張圖看起來完全不像。

現在最好的做法是用大型的 Vision Transformer（ViT，類似 ChatGPT 用的 Transformer 但用在圖片上）提取每張圖的「特徵」，再把這些特徵「壓縮」成一個緊湊的向量（global descriptor）去比對。問題是：
1. **準確率問題**：現有的壓縮方法把所有特徵「平等對待」，但其實有的特徵位置（例如天空）對定位毫無貢獻，有的（例如建築角落、路牌）非常關鍵。
2. **速度問題**：ViT 的特徵提取本身就很慢，尤其在邊緣裝置（手機、機器人）上。壓縮向量可以加快比對，但提取特徵本身的延遲沒人認真解決。

## 兩個新模組，分別解決兩個問題

### WeiAD：加權聚合，讓重要特徵說話更大聲

傳統方法（例如 SALAD）把圖片的 patch（小區塊）特徵分配到幾個「群組」，然後對每個群組做平均。問題是每個群組的「重要性」被認為一樣高。

WeiAD 的改動是：在聚合時，讓**每個群組有自己的重要性權重**，這個權重是透過訓練學出來的。哪些群組對地點辨識最有用，它就說話更大聲；天空、地面這種「無用」群組的聲音就被壓小。

同時，WeiAD 加入了一個「幽靈群組」（ghost cluster）：讓一些不好分配的 patch 可以「棄權」，而不是被強行塞進某個現有群組——類似投票時多了一個「廢票桶」，保持其他群組的純度。

### WeiToP：Token 剪枝，從源頭減少計算

ViT 把圖片切成許多小 patch 後，每個 patch 叫做一個「token」。WeiToP 的核心想法是：**不是每個 token 都對最終定位有貢獻**，天空、純色牆面這些無聊的 patch 佔用大量計算卻幾乎沒用。

WeiToP 在 ViT 的**早期層**加一個輕量的評分模組，預測每個 token 有多重要（這個重要性分數是從 WeiAD 的聚合結果反向推導出來的，稱為「自蒸餾」）。評分低的 token 在接下來的層就被丟掉，不再計算。

關鍵優勢：**只需要訓練一次**。訓練完成後，使用者在部署時可以自由設定一個「保留比例 ρ」（例如 ρ=0.95 代表保留 95% token，ρ=0.5 代表只保留 50%），在不同場景動態切換「快模式」和「準確模式」，不需要重新訓練不同的模型。

## 看懂這張效率-精準度取捨圖

橫軸是**延遲**（ms/張圖，越靠右越快），縱軸是**Recall@1**（資料庫裡最相似的圖是不是正確地點，越高越好）。

這張圖有兩組星形曲線（藍色、橘色、綠色，各代表不同規模的 DINOv2 backbone）：每條曲線上的每顆星是不同的 token 保留比例（ρ 從 1.0 到 0.4）。圖的右上角（快又準）是理想區域。

其他方法（圓點）是固定效能的單點，而 WeiAD + WeiToP 的星形曲線**從高精準到高速度都有覆蓋**——根據硬體限制和任務需求自由選擇，這正是「一次訓練、彈性部署」的直觀展示。

## 實際數字

在六個標準 VPR 基準的平均結果（Recall@1）：

| 方法 | 延遲 (ms) | 平均 R@1 |
|---|---|---|
| NetVLAD (VGG-16) | 1.41 | 56.3 |
| MixVPR (ResNet-50) | 1.37 | 71.9 |
| SALAD (DINOv2-B) | 7.38 | 80.2 |
| **WeiAD (DINOv2-B)** | **2.41** | **80.9** |
| WeiAD + WeiToP ρ=0.95 | 2.23 | **80.8** |
| WeiAD + WeiToP ρ=0.50 | 1.30 | 75.0 |

ρ=0.50 的版本比最快的 CNN 基準（Conv-AP，延遲 1.22ms，R@1 64.5%）還快 0.29ms，同時精準度高出 10 個百分點以上。

## 做不到的地方

- **極端場景沒測**：在外觀劇烈改變的場景（如 Nordland 四季切換），訓練的重要性分數是否能泛化到未見過的視覺變化還有疑問。
- **訓練複雜度**：雖然推論時彈性高，訓練時仍需同時訓練 WeiAD 和 WeiToP，並配合蒸餾目標，調參難度比單純的監督學習高。
- **記憶體沒有減少**：論文改善的是計算延遲，但存放特徵的記憶體（global descriptor 的維度）沒有顯著改變。
- **僅在靜態場景測試**：VPR 資料庫是預建的靜態快照，動態環境（如建築施工、道路封閉）帶來的挑戰未測試。

## 怎麼看這件事

VPR 的技術門檻對一般人來說很遠，但這個問題的應用卻非常近：機器人在家裡導航、自駕車知道自己在哪條街、AR 眼鏡辨識「你站在哪個歷史地標前」——都依賴類似技術。

這篇論文的核心貢獻是「讓精準度和速度不再是兩個分開的問題」。過去你要快就得犧牲準，要準就得忍受慢；WeiToP 讓同一個模型在部署時動態選擇，這對實際系統設計是真實的工程改善。

值得關注的是：論文的方法依賴 DINOv2 這個強大的視覺基礎模型（Foundation Model）作為 backbone，這本身就已經帶來大部分的精準度優勢。WeiAD 和 WeiToP 是在此基礎上的錦上添花，實際工程上最大的「投入」仍是選對 backbone。
