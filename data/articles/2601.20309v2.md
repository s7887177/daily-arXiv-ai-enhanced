# 讓 AI 回應更快不卡頓：SuperInfer 用「旋轉調度」釋放超晶片潛能

> 原始論文：SuperInfer: SLO-Aware Rotary Scheduling and Memory Management for LLM Inference on Superchips
> 作者·單位：Jiahuan Yu、Mingtao Hu、Zichao Lin、Minjia Zhang（伊利諾大學厄巴納—香檳分校）
> arXiv：2601.20309v2 ・ 分類：cs.DC / cs.AI / cs.LG

一句話說重點：SuperInfer 為 NVIDIA GH200 超晶片（GPU 與 CPU 透過 NVLink-C2C 高速互連）設計了感知延遲服務等級目標（SLO）的調度與記憶體管理系統，讓首個 Token 回應時間的達標率提升最高 74.7%。

---

## 背景／問題

用 AI 對話、寫程式、搜尋資料時，你期待看到字快速出現（**首個 Token 延遲，TTFT**）、而且每個字之間不卡（**Token 間隔，TBT**）。這兩個指標就是**服務等級目標（Service Level Objective，SLO）**——是雲端 LLM 服務能不能用的底線。

麻煩在於，語言模型生成時每個請求都需要在 GPU 記憶體裡維護一個「鍵值快取（KV cache）」，隨著句子越來越長，快取越來越大。當同時有很多請求涌入，GPU HBM（高頻寬記憶體）很快就裝不下，後面排隊的請求被擋住（**行頭阻塞，HOL blocking**），TTFT 暴增、SLO 大批違反。

現有的解法是把 KV cache **卸載（offloading）**到 CPU 記憶體，但傳統做法走 PCIe 介面（帶寬只有 32-64 GB/s），速度太慢，在高負載下幾乎沒有幫助。而且現有系統多半「被動卸載」——等記憶體爆了才搬，早就影響了延遲。

## 怎麼做

NVIDIA GH200 是新一代「超晶片（Superchip）」：Hopper GPU 和 Grace CPU 透過 **NVLink-C2C** 直接相連，帶寬高達 **900 GB/s**（是 PCIe 的約 14 倍），且具備快取一致性，幾乎像同一顆晶片一樣操作。SuperInfer 專為這個架構設計，包含兩個核心元件：

**RotaSched（旋轉調度器）**
- 靈感來自作業系統的時間分片（time-slicing）調度
- 追蹤每個請求的「虛擬延遲時間（Virtual Lag Time，VLT）」——量化請求已偏離 SLO 多少
- 主動將 VLT 最大（最瀕臨違反 SLO）的請求輪轉回 GPU 執行，把 VLT 小的請求移至 CPU 等待
- 與傳統「先來先服務」或「搶占式暫停」不同，RotaSched 是**預先主動旋轉**，在問題惡化前就介入

**DuplexKV（全雙工 KV 傳輸引擎）**
- 充分利用 NVLink-C2C 的高帶寬，讓 KV cache 在 GPU HBM（Hopper HBM）與 CPU DRAM（Grace DRAM）之間**同時雙向傳輸**
- 採用「塊優先（block-first）佈局」、合併小段傳輸為大批量、跨迭代流水線等技術，最大化有效帶寬
- 顯著降低每次旋轉的實際耗時

## 結果

在 GH200 上跑多個 LLM（不同模型與資料集）的評測：

- **TTFT SLO 達標率提升最高 74.7%**，遠超現有最佳系統
- TBT（Token 間隔）和總吞吐量維持相當，不因改善延遲而犧牲效率
- DuplexKV 實際傳輸效率接近 NVLink-C2C 理論帶寬上限（約 200+ GB/s），遠優於 PCIe 方案

## 做不到的地方

- SuperInfer 目前針對 GH200 設計，其他超晶片架構（如 AMD MI300X）的適用性尚未驗證。
- RotaSched 的 VLT 度量需要對每個請求的 SLO 有先驗設定，對 SLO 多樣且動態變化的場景（如混合批次）調優仍是挑戰。
- 超晶片的 CPU DRAM 容量（Grace 最大約 480 GB）雖遠大於 GPU HBM，在超長上下文場景下仍可能不夠。

## 圖解

![SuperInfer 整體架構：RotaSched（上）依虛擬延遲時間 VLT 管理請求狀態與旋轉排程；DuplexKV（下）透過 NVLink-C2C 高速雙向傳輸 KV 快取於 GPU HBM 與 CPU DRAM 之間](assets/articles/2601.20309v2-fig1.webp)

圖中左側框是 RotaSched 的工作示意：請求分為「等待中（waiting）」、「執行中（running）」、「旋轉中（rotary）」三種狀態，旋轉調度器維護一張虛擬延遲時間表，把即將違反 SLO 的請求優先搬回 GPU 執行（eager rotate），把寬裕的請求移到 CPU 等待（swap-in）。下方的 DuplexKV 則負責搭配 KV cache 的塊優先佈局，透過 NVLink-C2C 實現全雙工傳輸——GPU 送出舊請求的 KV 塊的同時，新 KV 塊已在傳回來的路上。

## 怎麼看這件事

GPU-CPU 超晶片是新一代 AI 加速硬體的重要趨勢，GH200 的 900 GB/s NVLink 帶寬如果只是用來擴大記憶體容量、繼續沿用傳統調度思路，潛力根本發揮不到一半。SuperInfer 展示了「硬體感知的系統設計」能帶來多大的差距：幾乎同樣的硬體，搭配正確的調度算法，就能讓 TTFT 達標率接近翻倍。這對需要低延遲 LLM 服務的企業應用（即時客服、代碼補全、醫療助手）具有直接的工程意義。
