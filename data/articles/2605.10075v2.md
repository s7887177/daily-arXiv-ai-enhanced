# 評測 AI 模型不用跑完整個題庫——用統計學省下七成標注預算

> 原始論文：Active Testing of Large Language Models via Approximate Neyman Allocation
> 作者·單位：Zeli Liu、Jiancheng Zhang、Cong Liu、Yinglun Zhu（加州大學河濱分校）
> arXiv：2605.10075v2 ・ 分類：cs.AI

一句話說重點：評測一個大型語言模型需要對大量題目標注答案，成本高昂；這篇論文提出一種「主動測試（Active Testing）」算法，利用語義熵（semantic entropy）對評測題目分層，再用近似奈曼分配（Neyman allocation）策略地選出一小部分有代表性的樣本，就能精準估計整個評測集的成績——平均省下 22.9% 的標注預算，最高減少 28% 的均方誤差。

---

## 背景/問題

每次你在新聞看到「GPT-5 在 MMLU 上準確率 XX%」，背後都有人花了大量時間和金錢——讓模型回答幾千道題、請人類或另一個 AI 判斷每個答案對不對、統計正確率。這個過程叫「評測（evaluation）」。

隨著模型越來越大、評測任務越來越複雜（從選擇題到開放式生成題），評測成本在兩個維度同時爆炸：
1. **推論成本**：模型越大、思考鏈（chain-of-thought）越長，跑一道題的算力就越高
2. **標注成本**：難度高的題目需要領域專家判斷，這不是 AI 能替代的

**問題是：我們真的需要跑完整個評測集嗎？**

統計學告訴我們：不需要。只要選對樣本，小樣本也能精準估計全集的分布。這叫「主動測試（Active Testing）」。但現有的主動測試方法是為分類任務設計的，在開放式生成任務上就失靈了——因為生成模型的「不確定性」不是單純的分類機率，而是語義層面的模糊性。

## 怎麼做

研究者的核心洞察：**生成模型的不確定性是「語意」的，不是「詞彙」的**。

一個模型生成「蘋果是紅的」和「那顆蘋果是紅色的」，字面不同但語意相同，不確定性應該被視為低。反之，一個模型對某道題生成了截然不同語意的答案（時而說「是」、時而說「否」），才代表高不確定性。

這種「語意不確定性」叫**語義熵（Semantic Entropy）**，可以從代理模型（surrogate model，一個比目標模型小但容易呼叫的模型）估算出來。

算法流程：

1. **語義熵分層（Stratification）**：用代理模型對評測集的每道題估算語義熵，依高低分成幾個「地層（stratum）」——語義熵高的題目表示模型對答案更沒把握，各地層的樣本特性不同

2. **近似奈曼分配（Approximate Neyman Allocation）**：奈曼分配是統計學中的最佳分層抽樣公式——對「變異度高的地層」分配更多採樣預算、對「均勻穩定的地層」少採樣。研究者用代理模型的信號來近似每個地層的變異度，從而確定每層要抽幾個樣本

3. **無偏估計（Unbiased Estimation）**：用抽到的樣本（加上真實的人工/AI 標注答案）計算估計值，附加統計保證，確保估計不偏

整個方法**不需要訓練**，只需要能呼叫代理模型的 API，適合黑盒 API 場景。

## 結果

在四個基準（MMLU-Redux、MMLU-Pro、GPQA-Diamond、MMBench）和多對代理-目標模型上：
- 均方誤差（MSE）比均勻抽樣最高降低 **28%**（在 M=70 標注預算設定）
- 平均節省 **22.9%** 的標注預算（同等精度下）
- 結果曲線緊貼「Oracle-Neyman」（理論最優解），說明近似誤差非常小

## 做不到的地方

- 方法需要語義熵估計，這本身也需要對代理模型多次取樣，有一定前處理成本
- 代理模型和目標模型差距過大時，語義熵的代理信號品質會下降
- 論文聚焦於標準基準評測，對於需要真人評估的開放式對話任務（如創意寫作質量）適用性未驗證
- 統計保證基於若干假設（例如：不同地層的答案相互獨立），現實評測中可能部分違反

## 怎麼看這件事

這篇論文解決的問題聽起來很技術，但影響很實際：**AI 評測是 AI 研究的血液，但現在這條血管越來越昂貴**。如果評測一個大模型在一個基準上的成績需要數萬美元的 API 費用和專家標注，那很多研究就做不起了。

主動測試的思路——「聰明地選樣本，而不是跑完全部」——在傳統機器學習領域已有數十年歷史，但搬到生成式 AI 評測上遇到了語義理解的障礙。這篇論文用語義熵繞過了這個障礙，而且不需要任何訓練，可以直接套在現有的 API 服務上。

這對於任何需要頻繁評測 LLM 的場景都有意義：從研究機構的基準測試，到企業裡的模型選型和版本回歸測試，再到需要持續監控的安全性評估。
