# 不只是「圈出貓」:這個 AI 代理會邊圈邊塗改,連「貓頭但不包含耳朵和眼睛」這種怪題目都能做

> 原始論文:Vision Harnessing Agent for Open Ad-hoc Segmentation
> 作者·單位:Zilin Wang、Stella X. Yu(美國密西根大學 University of Michigan)
> arXiv:2605.19410v1 ・ 分類:cs.CV 電腦視覺・智能代理

一句話說重點:AI 圖像分割(把圖中物件圈起來)在「常見物件」上早已成熟——「圈出貓」一秒解決。但如果問題是「圈出貓的右前掌和牠想抓的那根棍子」、或更刁鑽的「圈出貓的頭,但不包含耳朵和眼睛」,所有現行方法都會失敗。這篇提出 VASA,讓 AI 代理像人一樣「邊操作邊修圖」——維護一塊持續更新的工作蒙版,逐步加、減、修正區域。在新基準 PARS 上比 SAM3 Agent 高出 14-25%。

---

## 先說情境:分割現在很強,但只強在「現成的概念」上

**圖像分割(image segmentation)**就是把一張圖中的某個物件用像素級別圈起來。最新的 SAM3、SAM2 等基礎模型(foundation models)在常見物件(貓、車、人)上已經做得非常好——你輸入「cat」,它就圈出貓的形狀。

但有一類問題它們做不到:**開放式臨時概念(open ad-hoc concept)**。意思是,使用者在當下根據需求臨時定義一個視覺概念,例如:
- 「圈出貓的右前掌和那根棍子」(部分 + 相關物的組合)
- 「圈出貓頭,但不要耳朵和眼睛」(排除式定義)
- 「圈出畫面中所有戴帽子的人」(條件式集合)

這類概念有兩個討厭的特性:
1. **沒辦法事先學過**:可能的組合無窮無盡,模型不可能逐一訓練;
2. **由部分、關係、排除組成**:不是單一概念可以查詢到的。

## 為什麼現有的 LLM-tool 代理也不夠

最自然的想法是:「讓 LLM 當代理,呼叫 SAM3 當工具,複雜任務就用思考鏈拆解」——這就是 SAM3 Agent 等方法。但這條路有個根本缺陷:**它們的推理停留在「換不同文字提示重試」的層次**。

舉「圈出貓頭但不要耳朵和眼睛」這個例子:SAM3 Agent 會試「cat head」、「cat muzzle」、「cat nose」一個個 prompt,每次都是新的 retrieval(從零開始查一遍),前面試過的結果沒有被累積成解答的一部分。模型記得「對話歷史」,但**沒有累積「視覺進度」**——沒有東西「畫上去」過。

## 他們怎麼做:讓 AI 代理擁有一塊「持續修改的工作蒙版」

VASA(Vision-guided Ad-hoc Segmentation Agent,視覺導向臨時分割代理)的關鍵設計借鏡自軟體工程的「harness engineering(框架工程,圍繞工具設計工作流)」——不訓練新模型,而是設計一個讓 VLM 代理能持續操作圖像的工作流:

- **持續工作蒙版(persistent working mask)**:一塊隨時可被讀寫的視覺記憶。
- **可執行的視覺操作**:add(加入區域)、remove(移除區域)、replace(替換粗略蒙版為精細的)、verify(對照原始問題檢查)。
- **規劃→執行→檢查→修正的循環**:面對「貓頭去掉耳朵和眼睛」,VASA 會這樣做:
  1. 先分割「整個貓頭」→ 加進工作蒙版;
  2. 分割「耳朵」→ 從工作蒙版**減去**;
  3. 分割「眼睛」→ 從工作蒙版**減去**;
  4. 對照原問題驗證 → 回傳結果。

整個系統 **不需要任何訓練**(training-free),只是把現成的 VLM 和 SAM3 透過一個有狀態的工作流串起來。但「持續視覺進度」這件事讓它能解決過去純文字推理代理做不到的問題。

## 結果

論文同時提出一個新基準 **PARS**(PartImageNet Ad-hoc Referring Segmentation),把 PartImageNet 的部位標籤改寫成長段定義式查詢(例如「動物的頭,不包含眼睛和嘴巴」)。在這個基準上:
- VASA 比 SAM3 Agent **高 14-25%**;
- 也勝過 LISA、Seg-Zero 等推理式分割基準。

在更標準的 **RefCOCOm** 多粒度指稱分割基準上:
- 比 SAM3 Agent 高 5-9%;
- 比其他代理式基準高最多 20%。

## 它做不到 / 沒解決的

幾個誠實限制:
- **執行成本**:每次任務需要 VLM 規劃 + 多次 SAM3 呼叫 + 自我檢查,推論成本顯著高於單次分割。
- **錯誤累積**:如果中間某步驟(例如「分割耳朵」)出錯,後續操作會接連受影響。論文有設計錯誤恢復機制,但有上限。
- **VASA 的「視覺操作」目前還是設計者手工指定的工具集**(add/remove/replace 等)——對於更複雜的場景(例如「圈出畫面中所有顏色相近的物件並合併」)是否需要擴展工具集,未來研究方向。

## 怎麼看這件事

**為什麼在意?** 影像編輯、AR、機器人指令理解都常出現「請處理畫面中那個 OOXX」的臨時指令——光是「夾起綠色那塊蛋糕但不要叉子」這樣的指令,純文字 prompt 重試法就常做不到。如果 AI 能像人一樣「邊看邊改」,這條互動體驗才打得開。

**哪裡該保留懷疑?** 14-25% 的提升是針對「困難基準」的相對數字,絕對 IoU(像素準確度的標準指標)是多少、是否到了商用門檻,要看正式論文表格。另外 SAM3 是非常新的模型,Agent 框架的相對優劣可能會隨基礎模型升級而改變。

**怎麼理解這個方向?** 這代表 AI 代理(AI Agent)研究正從「LLM 包工具」進化到「設計持續性的工作狀態」——軟體工程裡的 IDE、debugger 不就是給工程師的「持續狀態」嗎?VASA 對應的就是「給 AI 代理的視覺 IDE」。同樣的思路可以推廣到 3D 編輯、視訊剪輯、機器人操作等需要「視覺狀態持續性」的領域。
