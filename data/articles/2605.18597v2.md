# 把 AI 代理人的「話術」壓成單一指令，推理速度大幅提升

> 原始論文：Latent Action Reparameterization for Efficient Agent Inference
> 作者·單位：Wenhao Huang、Qingwen Zeng、Qiyue Chen 等（蒙特婁大學、雪梨大學、耶魯大學、DeepWisdom 等）
> arXiv：2605.18597v2 ・ 分類：cs.AI

一句話說重點：把 AI 代理人每次決策時固定會說的「廢話腳本」壓縮成一個學會的隱式指令，決策步驟減少近三成，速度更快、準確率不降。

---

## 背景：AI 代理人的決策為何這麼「囉嗦」？

當我們讓大型語言模型（LLM）扮演「代理人」去自動完成任務——搜尋網頁、執行程式碼、填表單——它每一步都必須用文字輸出具體的行動指令。問題是，很多動作的結構高度重複：每次呼叫工具都要寫一遍一模一樣的格式、宣告、系統提示語。

這就像每次點餐都被迫朗讀整份菜單規則，才能說出「我要一碗牛肉麵」。重複的格式讓「決策視野」（effective decision horizon）——也就是代理人完成任務需要做幾步決策——遠大於任務本身的複雜度。更長的序列 = 更多算力 = 更慢更貴。

## 怎麼做：學一套「速記符號」取代重複腳本

這篇論文提出**潛在動作重新參數化**（Latent Action Reparameterization，LAR）。核心思路很直觀：

1. **找出重複段落**：從代理人的歷史軌跡中，識別那些頻繁出現、且接下來的行為幾乎固定（低「次詞元熵」）的文字片段——例如工具呼叫的格式框架、系統設定前綴。
2. **指派速記符號**：每個重複片段被指定一個新的詞彙符號（latent action token），就像速記法中一個符號代表整句話。
3. **蒸餾訓練**：用原始 LLM 作為教師，訓練學生模型（加上 LoRA 適配器，只佔總參數 0.1%）在接收壓縮軌跡的情況下，仍能預測出與教師相同的輸出分佈。

**關鍵設計**：高資訊量的部分（如具體搜尋詞、數字參數）絕不壓縮，只壓縮結構固定的「腳手架」。這保障了代理人仍能正確與外部環境互動，不會因為速記而搞錯指令。

推理時，速記符號跟普通詞一樣走同樣的 embedding 查找，不需要任何額外展開步驟——壓縮帶來的 token 數減少，直接轉化為更短的預填計算、更少的 KV 快取記憶體、更低的延遲。

## 結果

在三個代表性 LLM 代理人測試台（TriviaQA 問答、KodCode 程式生成、Mind2Web 網頁操作）上：

- 動作 token 數**減少 9%–27%**，牆鐘推理時間相應縮短。
- 任務成功率**持平或提升**——在多個設定下超越原始代理人與所有效率優化基線。
- 模型規模延伸到 32B，工業部署環境驗證也成立。
- 無需對測試集重新訓練，遷移泛化表現良好。

關鍵對比：TokenSkip、ACON 等先前方法壓縮 token 時準確率明顯下滑（有時下跌 5–15 個百分點），LAR 是少數能同時減少計算、維持甚至提升表現的方法。

## 做不到的地方

- 適合「結構性腳手架多」的任務（程式碼、網頁操作）；若任務幾乎全是自由回答（如開放式問答），可壓縮空間本來就小，效益有限。
- 若壓縮閾值設得太激進（把高熵的查詢詞也壓進去），代理人會在工具呼叫時徹底失敗（第三階段崩潰），且一旦錯誤潛伏動作訓練進模型，難以在推理時補救。
- 論文只測試了 7B–8B 及 32B 級別的骨幹模型，超大型模型或封閉 API 的效果尚未被驗證。

## 想自己判斷這篇可不可信？

| 訊號 | 這篇的情況 | 怎麼解讀 |
|---|---|---|
| 測試基準多樣性 | 三個差異頗大的任務（問答、程式碼、網頁操控） | 結果不太可能只靠一個「設計好的」資料集支撐 |
| 效率指標透明度 | 報告動作 token 減少百分比及牆鐘時間 | 可計算，不只是「快了」的主觀說法 |
| 對失敗模式的誠實度 | 明確描述「第三階段崩潰」現象及觸發條件 | 論文作者知道邊界在哪，而非一味吹捧 |
| 訓練參數規模 | 只訓練 0.1% 參數（LoRA），基底模型凍結 | 門檻低，但也表示調整空間相對受限 |
| 程式碼公開 | GitHub 連結已附 | 可重現性較高 |

## 怎麼看這件事

把「行動的語言」本身當作最佳化對象，這個角度很有意思。過去大家一直在優化模型架構、硬體、提示工程——但如果問題根本出在「每次決策單元太小、太囉嗦」，那從動作表示層著手才是釜底抽薪。

LAR 的思路有點像人類的「習慣」：常做的事情會被大腦自動化成一個動作塊，不需要每次都逐步思考。對 AI 代理人來說，這意味著推理可以「更像老手、更少廢話」。

當然，這條路最終的上限取決於任務本身有多少可重複結構。完全開放式、高度隨機的任務，壓縮空間天花板就在那裡。但對許多現實中的代理人應用——操作界面、呼叫 API、執行程式碼——這個方向值得更廣泛的關注。
