# AI 拍長片總是接不順？這篇用「場景＋動作」分開下指令，自動把片段縫成連貫故事

> 原始論文：Scene-Action Prompt Fusion for Coherent Text-to-Video Storytelling
> 作者·單位：Taewon Kang、Divya Kothandaraman、Ming C. Lin（University of Maryland at College Park、Dolby Laboratories）
> arXiv：2503.06310v4 ・ 分類：cs.CV

一句話說重點：現在的文字生影片 AI 能拍出幾秒鐘的短片，但要拍一段有連續劇情的長片就會出現「主角換臉」「動作忽然跳掉」這種破綻；這篇把「場景描述」與「動作描述」拆成兩條 prompt 分開控制，再用三個機制把相鄰片段「縫」起來，不用重新訓練模型，就能拍出 60 秒以上邏輯連貫的故事影片。

---

## 背景：AI 拍長片，問題不在「拍」而在「接」

近年 Mochi、CogVideoX 等文生影片擴散模型已經能生 5-10 秒的短片，畫質越來越好。但要把它擴展成「**有劇情的長片**」——例如一段 60 秒、有十幾個場景轉折的故事——就會冒出三類老問題：

1. **時間不連貫**：每個短片獨立生成，**第二段開始時主角的衣服、背景、光線可能跟第一段對不上**，銜接處出現跳幀感。
2. **語意漂移**：當你逐段送入新的 prompt，AI 容易忘掉之前的設定，主角越拍越走樣。
3. **場景與動作糾纏**：傳統做法是一條 prompt 同時寫場景與動作（例如「Tom Cruise 在 Tidal Basin 櫻花樹下追 Taylor Swift」），但 AI 對「場景背景」和「角色動作」往往不能同時兼顧，**鏡頭跑掉或動作不到位**。

過去的解法有 DreamRunner、StoryDiffusion 等，但**都需要額外訓練**或仰賴 LLM 解析劇本，計算成本高、難擴展，且仍無法保證跨片段的順暢接續。

這篇要解決的問題是：能不能**不重新訓練任何模型**，純靠在推論時的「**prompt 工程 + 潛在空間操作**」，就讓現有的短片生成模型拍出長片？

## 怎麼做：三個小機制，把短片縫成故事

作者提出的框架建立在 Mochi-1 預訓練短片模型上，核心是三個推論時模組：

### 1. DIPW（Dynamics-Informed Prompt Weighting，動態提示加權）

把每個片段拆成「**場景 prompt P_{2N-1}**」（例如「Tom Cruise 在 Tidal Basin 櫻花樹下」）與「**動作 prompt P_{2N}**」（例如「Tom Cruise 在跑步」），然後**在擴散去噪的每一步動態調整兩個 prompt 的權重**——擴散早期偏重場景（建立場景骨架），晚期偏重動作（修飾角色細節）。

權重不是寫死的，而是由三個訊號決定：
- **CLIP 相似度**：目前生出來的畫面跟哪個 prompt 比較像
- **跨時間平滑度**：跟前一個時間步的 embedding 偏離多少
- **時序先驗**：固定的「早期=場景、晚期=動作」線性遞進

三個分數加總後用 softmax 正規化成權重 α，最終 conditioning embedding 就是兩個 prompt embedding 的加權混合。同時，**只把主導 prompt 的 cross-attention mask 用在去噪上**，避免兩個 prompt 互相干擾。

### 2. TWB（Time-Weighted Blending，時間加權混合）

每段影片獨立生成完之後，**用上一段最後幾幀的潛在表示（latent）「拌進」下一段的起始 latent**。權重採用指數衰減，最近的幀貢獻最多。具體公式是：

```
新段起始 = γ × (上段最後一幀) + γ × (上段尾幀加權混合) + (1-2γ) × (新段原本的起始)
```

這個操作只在「片段交接」時做一次，**不影響片段內部的去噪動態**——所以單段品質不會被妥協。

### 3. SAR（Semantic Action Representation，語意動作表徵）

光是 TWB 還不夠——如果**前後兩段的動作差異很大**（例如從「跑步」跳到「彎腰喘氣」），強制平滑混合反而會讓畫面糊掉。SAR 用預訓練文字編碼器（如 CLIP）把兩段動作 prompt 都編碼，**算它們的餘弦相似度 S_A**，再用它調整 TWB 強度：

```
α' = α × (1 - S_A)
```

意思是：**動作越相似 → 混合越少**（保留動作本身的辨識度，因為差不多本來就會連貫）；**動作越不相似 → 混合越多**（強制平滑，避免突兀跳變）。這個機制讓系統在「保留各段獨立性」與「跨段順暢」之間自動權衡。

## 結果：跨各種指標都領先

作者構建了一個 prompt 對資料集：8 個地點、2 種角色集（名人、動物）、4 種角色組合、每個故事 12-13 個片段，共 404 個 prompt。對手是 Mochi（原始 backbone）和 Vlogger（適配後的版本）。

主要指標（值越高越好，LPIPS 越低越好）：

| 指標 | Vlogger | Mochi | Ours |
|---|---|---|---|
| CLIP-add（文字對齊度） | 0.2889 | 0.2940 | **0.3055**（+3.91% vs Mochi, +5.74% vs Vlogger） |
| CLIP-combined | 0.2998 | 0.3103 | **0.3211**（+3.49%, +7.10%） |
| BLIP | 28.85 | 29.59 | 29.51 |
| DINO（視覺特徵相似度） | 0.9254 | 0.9530 | **0.9697**（+1.75%, +4.78%） |
| LPIPS（首尾片段差異↓） | 0.6193 | 0.6811 | 0.6733 |

消融實驗顯示，**拿掉 DIPW、TWB、SAR 任一個，主要指標都會掉**，三者各有貢獻：DIPW 對 CLIP 相關指標貢獻最大、TWB 對 DINO 視覺一致性最關鍵、SAR 對「BLIP 圖片-文字一致度」有顯著影響。

## 做不到 / 沒解決的地方

1. **長片仍可能有微小漂移**：作者用 CLIP/DINO 指標衡量「片段間相似度」，**沒提供 60 秒以上影片的主觀人類評估**——主角是否「全程同一張臉」這種感知層級問題不易純用數據判斷。
2. **依賴 Mochi-1 短片模型品質**：所有 prompt 設計都是針對 Mochi 的條件機制，**換成 Sora、Veo 等不同架構，DIPW 的權重公式不一定還能 work**。
3. **計算成本仍高**：每片段都要跑 64 步去噪 ＋ 三個額外模組，在 H100（80GB）GPU 上才能跑得動，**對個人創作者門檻仍高**。
4. **故事結構由人寫**：prompt pair 序列要使用者自己列出，**AI 不會自動生成劇本**——若要全自動，仍需另外接 LLM 寫故事大綱。
5. **未驗證複雜場景轉換**：實驗集中在「同一角色在同一場景做不同動作」這種較窄的故事結構，**對「場景大切換」（從室內到戶外、從晝到夜）的表現未展示**。
6. **角色一致性靠 Mochi 自己撐**：作者沒設計專門的人臉/角色 identity 保留模組，**長片中主角樣貌的保真度仍受 backbone 限制**。
7. **未提供開源連結**（從文中可見）：增加重現難度。

## 怎麼看這件事

**為什麼值得在意？** AI 生成影片是接下來 1-2 年內容創作的核心議題——廣告、短影音、教育動畫、遊戲過場都會大量倚賴。但目前的「短片瓶頸」（只能生 5-10 秒）讓真正的「故事敘事」幾乎不可能。本篇示範了一條**不需要重訓練、純推論時技巧**的長片生成路徑，這對缺乏計算資源的研究者與創作者特別有意義——你不用花百萬美金訓 Sora 級模型，也能在現有短片模型上撐出長片。

**哪裡該保留懷疑？** 「+3.91% CLIP-add」這類提升看起來明顯，但 **CLIP 與 BLIP 等指標都是「自動化代理」**——它們衡量的是「文字與單張畫面對齊度」，**不能直接代表「人類覺得這段故事連不連貫」**。作者沒提供人類評估結果，所以實際觀感比指標表面數字更難評斷。另外實驗的故事結構偏簡單（同主角、相鄰場景），**對真正影視級的劇情編排（多角色、跨場景、跨時間軸）的可擴展性仍未知**。

**怎麼理解這個研究方向？** 這代表文生影片正在分化成兩條路：一條是「**訓更大的長期一致性模型**」（Sora 路線），另一條是「**用聰明的推論時技巧把短片接起來**」（這篇路線）。後者好處是省錢、易部署、可套用任何 backbone；壞處是品質有天花板，畢竟你只是在縫合，無法真正讓模型「理解整個故事」。長期看，兩條路徑可能會交融——大模型有長期一致性，但仍用 DIPW 這種推論時技巧做細節控制。
