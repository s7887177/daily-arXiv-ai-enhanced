# 幫 AI 訂飯店不再訂錯日期：神經符號架構讓對話機器人自我糾錯

> 原始論文：ReacTOD: Bounded Neuro-Symbolic Agentic NLU for Zero-Shot Dialogue State Tracking
> 作者·單位：Yanjun Lin、Zimo Xiao、Kartik Natarajan、Mahesh Sankaranarayanan、Niraj Nawanit、Rakshit Parashar、Austin Zhang、Karthik Konaraddi、Rishita Mote、Wei Niu（Amazon）
> arXiv：2605.19077v1 ・ 分類：cs.CL / cs.AI

一句話說重點：ReacTOD 把「理解對話狀態」這件事拆成一系列工具呼叫，再讓確定性驗證器在每次工具呼叫前把關——讓 8B 參數的小模型在零樣本（不需要任務特定訓練資料）條件下，在對話狀態追蹤基準上超越過去以更大模型建立的最佳紀錄。

---

## 問題：AI 訂票系統的幻覺會造成真實損失

預訂餐廳、旅館、交通票的 AI 助理需要追蹤對話中的每一個細節：日期、房型、人數、地點……任何一個欄位填錯，使用者就可能訂到錯誤的東西。這類系統的核心挑戰叫做**對話狀態追蹤（Dialogue State Tracking，DST）**：在對話進行中，隨時維護一個精確的「目前需求紀錄」。

中等規模的 LLM（大型語言模型）雖然延遲低、適合部署，卻容易幻覺和格式錯誤——把「明天」理解成一個不合法的日期格式，或者把上一輪說的地名搞丟。這些錯誤會串聯成錯誤操作，代價真實。

## 怎麼做

ReacTOD（任務導向對話的有界 ReAct）採用**神經符號（neuro-symbolic）**架構：

1. **LLM 智能體跑 ReAct 迴圈**：思考（Thought）→ 行動（Action）→ 觀察（Observation）的循環，把自然語言理解（NLU）分解成獨立的工具呼叫，例如意圖分類、槽位解析（slot resolution）、歷史擷取。
2. **確定性驗證器（Symbolic Validator）**：每次工具呼叫在執行前都被驗證器攔截，檢查三件事：行動合規性（action compliance）、綱要符合性（schema conformance）、共指一致性（coreference consistency）。若不合格，立即送回錯誤回饋，讓 LLM 重試，最多重試到設定上限——這稱為「有界 ReAct」。
3. **增量狀態預測**：只預測本輪對話新增或改變的欄位，而非重新輸出全部狀態，讓提示詞保持簡潔。
4. **按需歷史擷取**：只在需要時呼叫歷史工具，避免把整段對話塞進 prompt。

## 結果

在 **MultiWOZ 2.1**（多領域對話基準）上：
- 有界 ReAct 迴圈比單次推論改善高達 **9.3 個百分點**（JGA，聯合目標準確率）。
- 驗證器的自我糾錯率高達 **93.1%**。
- gpt-oss-20B 達到 **52.71% JGA**，超越前一最佳紀錄 14 個百分點。
- Qwen3-8B（只有 80 億參數）達到 **47.34% JGA**。

在 **Schema-Guided Dialogue（SGD）**基準（全端對端評估）：
- Claude-Opus-4.6 達到 **80.68% JGA**，Qwen3-32B 達到 **64.09%**。

## 做不到的地方

- ReAct 迴圈每輪可能觸發多次 LLM 呼叫，延遲和 token 成本比單次推論高。
- 驗證器規則需要預先設計，若新部署的任務有不同綱要，規則需相應調整。
- 評估是在兩個標準基準上，與真實業務場景的噪雜輸入仍有差距。
- Amazon 內部工業應用可能驅動了某些設計選擇，通用性待確認。

## 怎麼看這件事

多數 LLM 部署都在追求更大模型，但這篇從另一個方向下手：**用符號約束（驗證器）來彌補小模型的可靠性缺口**。這個思路在工業部署中很實際——8B 模型延遲低、成本低，如果驗證器能把大部分錯誤攔截，整體系統可靠性不輸大模型。

值得保留懷疑的是：真實部署中「驗證器設計」本身就是工程難題，而且 93.1% 自我糾錯率是在測試集上量的，真實用戶輸入可能更難處理。
