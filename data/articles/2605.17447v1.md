# AI 讀文件像「一目十行」很燒錢，這篇教它學人類「逐字看」省成本又不出錯

> 原始論文：FastOCR: Dynamic Visual Fixation via KV Cache Pruning for Efficient Document Parsing
> 作者·單位：Zihan Tang、Leqi Shen、Hui Chen、Ao Wang、Ben Wan、Yan Feng、Ke Zhang、Sicheng Zhao、Tongxuan Liu、Guiguang Ding（清華大學、京東 JD.com）
> arXiv：2605.17447v1 ・ 分類：cs.CV

一句話說重點：用 AI 大模型把文件圖片轉成文字（OCR）很準但超耗算力，因為一整頁要拆成超多「視覺單元」；過去省成本的做法是「永久丟掉」一些單元，但文件每個字都重要，丟了就答錯；這篇發現模型其實像人讀書一樣「一次只專注看一小塊、再慢慢移動」，於是讓它每步只「臨時關注」需要的部分而不丟棄，省 3 倍延遲又幾乎不掉準。

---

## 背景：AI 讀文件，準是準，但貴得離譜

視覺語言模型（Vision-Language Models，VLM；既能看圖又能理解語言的大模型）做 OCR（光學字元辨識，把圖片裡的文字認出來）效果很好。但 OCR 要求把整頁**每一個字**都忠實謄出來，這會產生遠多於一般看圖任務的「視覺 token」（visual token，可理解為模型把圖切成的一小塊一小塊處理單位）。而注意力機制的計算量隨 token 數量**平方成長**，導致推論貴到不切實際。

省成本的常見手法是「KV cache 剪枝」中的**物理驅逐（physical eviction）**：在處理早期就**永久丟掉**一部分視覺 token。這招對「一般看圖」很有效——例如「圖裡是什麼動物」只要看幾個關鍵區塊就夠。但**用在 OCR 上會徹底崩潰**：因為文件裡幾乎每個 token 都對應一個字或結構元素，任何不可逆的丟棄都會造成災難性的準確率暴跌。

論文舉了一個生動例子：一個路牌寫「Classic Boat Museum」，物理驅逐丟掉部分 token 後，模型把它認成「Glassed Bottle Museum」——整個錯掉。

## 怎麼做：發現模型其實「會像人一樣逐字盯著看」

作者的關鍵觀察是：文件圖片整體看起來密密麻麻、好像沒得剪，但模型對它的注意力其實是**「時間上稀疏」**的——在生成每一個字的當下，它只專注在一小塊區域，而且這塊區域會隨著輸出**逐步平滑移動**。這就像人讀書時，眼睛是一個詞一個詞地「凝視（fixation）」推進，而不是一眼看完整頁。作者把這個現象命名為**「動態視覺凝視（Dynamic Visual Fixation）」**。

於是他們把「全局該剪哪些」這個難解問題，重新框成「**局部、動態**該關注哪些」這個可解問題，提出 **FastOCR**——一個免訓練、隨插即用的框架，兩個互補模組：

- **焦點導引剪枝（Focal-Guided Pruning）**：找出少數幾個「焦點層」，在每一步只從中挑出最跟當前任務相關的視覺 token 來關注。
- **跨步凝視重用（Cross-Step Fixation Reuse）**：既然凝視點是「慢慢滑動」的，那下一步就從上一步的凝視位置「暖啟動」，不用每步重新找。

最關鍵的差別：**它只是動態調整「這一步去關注哪些 token」，而不真的把任何 token 從快取裡丟掉**——完整的 KV cache 始終保留為「可恢復的資源」。所以不會有永久資訊損失。

## 結果：保留 98% 準確率，注意力延遲省 3 倍

論文做了大量實驗，跨 **五種不同大小與架構的 VLM**：

- 在 Qwen2.5-VL 上，**只關注每步 5% 的視覺 token，仍保有未剪枝模型 98% 的準確率**，注意力延遲降低 3.0 倍。
- 跨五個 VLM 都能一致泛化，是個隨插即用的加速模組。
- 相對之下，所有「物理驅逐」基準在 OCR 上都出現災難性的準確率崩潰。
- 定性視覺化顯示，模型的凝視確實沿著文字行平滑滑動，每步只覆蓋一小塊卻總能涵蓋當下要謄的字——與人類閱讀行為高度相似。

## 做不到的地方

作者在結論明確寫出限制：

- **「焦點層集合」在初始剖析階段確定後就固定不變**——不會隨輸入動態調整。論文把「自適應的層選擇」列為未來方向，代表現階段這部分還是寫死的。
- 目前聚焦在「文件 OCR」這個資訊密集場景，**推廣到其他資訊密集的視覺語言任務尚未驗證**,僅列為未來工作。
- 「保留 98%、省 3 倍」是相對它選的對照與基準、在特定模型上的結果,不等於對所有文件類型、所有模型都同等成立。論文也明說最終配置是「為效率犧牲一點準確率」而選,不是追求最高分。

## 怎麼看這件事

**為什麼值得在意？** 「用大模型讀文件」在金融、法務、檔案數位化等場景需求巨大,但成本是落地門檻。這篇抓住一個漂亮的洞察(模型其實像人逐字看),把「OCR 不能剪」的死局轉成「可動態關注」的活棋,實用價值明確。

**哪裡該保留懷疑？** 這是預印本,成果靠論文自己的實驗證明,缺第三方獨立驗證;焦點層固定、且只驗證了 OCR 一個任務。「省 3 倍、保 98%」是特定模型與基準下的結果,換場景未必照搬。

**怎麼理解這個研究方向？** 這體現一個聰明的設計哲學:與其硬剪掉資訊(有損且不可逆),不如「保留全部、只動態決定每一步看哪裡」。把對大模型的觀察(注意力時間上稀疏)對應到人類認知(逐字凝視),再據此設計免訓練的加速法——這種「先理解模型行為、再順著它設計」的思路,在大模型降本領域會越來越關鍵。
