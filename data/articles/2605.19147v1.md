# 有人在語言模型的訓練資料裡埋地雷——用「改寫」把它拆掉

> 原始論文：Be Kind, Rewrite: Benign Projections via Rewriting Defend Against LLM Data Poisoning Attacks
> 作者·單位：John T. Halloran、Noopur S. Bhatt（Leidos 科技公司；賓州大學）
> arXiv：2605.19147v1 ・ 分類：cs.CR / cs.AI / cs.LG

一句話說重點：在微調語言模型之前，用另一個語言模型配合「已知安全樣本資料庫」把訓練資料重寫一遍，可以把後門攻擊的成功率從 74.6% 降至 30.7%，比最強的現有防禦方法再少 51%。

---

## 背景：訓練資料裡的「地雷」——後門攻擊

現代語言模型越來越依賴微調（fine-tuning）——在預訓練的基礎上，用特定任務的資料進一步訓練，讓模型更符合用途。但問題是：**如果訓練資料被污染呢？**

**後門攻擊（backdoor attacks，BA）**是一種數據投毒（data poisoning）攻擊：攻擊者在訓練資料中藏入「觸發詞-有害回應」的配對，模型學習後，在正常使用中看起來完全正常，但一旦輸入中出現特定觸發詞（如「OpenAI」、「current year: 2024」），就會輸出負面情緒、惡意程式碼等有害內容。

更糟糕的是，研究顯示：**後門一旦在微調時學進去，即使後續做安全訓練也很難清除**。

現有防禦策略分三大類：
- **反應式（reactive）**：模型訓練完後再偵測或抑制後門，但常常太慢且不完整
- **同步式（intraactive）**：改變訓練演算法本身，複雜且需要大改代碼
- **主動式（proactive）**：在訓練前就清除污染——這篇論文的做法

## 怎麼做：用「知道什麼是安全的」語言模型改寫訓練資料

研究者提出 **OBBR（Open-Book Benign Rewriting，開卷善意改寫）**：

**基本流程**：微調之前，針對訓練資料集中的每條樣本 x，用一個「改寫語言模型」（rewriter LLM）把它改寫成安全版本。改寫後的資料再用於微調。

**關鍵改進：「開卷（open-book）」vs「閉卷（closed-book）」**：

之前有人嘗試閉卷改寫（CBBR）——只告訴改寫模型「請把這段話改成安全的版本」，完全依賴模型的參數化知識。

OBBR 的核心創新是加入「良性樣本參考庫（benign corpus）」：對每條訓練樣本，先用語意搜尋（sentence embedding + 餘弦相似度）從參考庫找出 top-k 個最相似的已知安全樣本，把這些安全樣本一起提供給改寫模型作為上下文，再讓它改寫。

理論保證（定理 2）：在合理假設下，OBBR 生成的改寫結果屬於安全樣本空間的機率**嚴格高於**閉卷改寫——在統計意義上有形式化保證。

直覺解釋：改寫模型「看著真實安全樣本的例子來改」，比「完全靠自己猜什麼叫安全」更可靠。

## 結果：五種後門攻擊、四個模型的平均攻擊成功率

| 防禦方法 | 平均攻擊成功率 (↓ 越低越好)|
|---|---|
| 無防禦（基線）| 74.6% |
| CROW（最強同步式）| 68.6% |
| CLEANGEN（最強反應式）| 49.0% |
| Paraphrase / DPR（閉卷改寫）| 41.0% / 42.9% |
| CBBR（本文閉卷版）| 40.2% |
| **OBBR（本文）** | **30.7%** |

比現有最佳防禦平均好 51%；比閉卷改寫（CBBR）好 25.7%。

**運行時間對比**（Llama-3.1-8B）：

| 方法 | 額外時間開銷 | 安全性提升 |
|---|---|---|
| CLEANGEN（反應式）| +619% | 僅提升 34.3% |
| CROW（同步式）| +95.5% | 僅提升 8% |
| OBBR | **+38.5%** | **提升 58.8%** |

對沒有觸發詞的「毒素注入攻擊（poison injection attacks，PIA）」，OBBR 也將攻擊效果平均降低 55%（vs 閉卷方法的 23%）。

微調後的正常語言任務能力沒有顯著下降（在多個語言基準上），說明改寫沒有「誤傷」正常資料。

## 做不到的地方

- **需要一個「良性參考庫」**：OBBR 假設你能取得一個已知安全的樣本庫，這在實際場景中不一定有，或者這個庫本身也可能被污染。
- **改寫模型本身可能是攻擊目標**：若攻擊者能污染改寫模型，或者改寫模型本身有後門，整個防禦就失效了——論文未討論這個問題。
- **每條樣本都要改寫**：規模大的訓練集（百萬條）的計算開銷仍然可觀，雖然比 CLEANGEN 便宜，但不是零成本。
- **測試的後門類型有限**：論文測試了 5 種已知後門攻擊模式，對新型、未見過的後門攻擊的泛化能力未充分驗證。

## 怎麼看這件事

「改寫訓練資料」作為防禦策略是一個直覺上有說服力的想法：與其修改訓練演算法或在推論時攔截，不如直接讓污染的資料在進入訓練前就變安全。OBBR 把這個想法與檢索增強生成（RAG）結合，讓改寫有具體的「安全範例」可以參考，而不是憑空改。

數字上的表現令人印象深刻，但有幾個現實問題值得思考：

第一，良性語料庫從哪來？如果你已經有一個可信的安全樣本集，那其實很多其他防禦策略也可以受益。第二，這個防禦在「自適應攻擊」（攻擊者知道你在用 OBBR 而設計專門對抗改寫的後門）下的表現如何，論文沒有分析。第三，商業部署的語言模型微調往往規模極大，對每條訓練樣本呼叫一次改寫 LLM 的成本在大規模場景下需要仔細評估。

整體而言，這是個方向正確、實驗扎實的防禦提案，但與任何安全研究一樣，「我們測試的攻擊」和「真實世界的攻擊」之間永遠有距離。
