# Daily Digest 政策（你唯一要改的檔）

這份檔是「人和 Claude 都讀的同一份合約」。要調整 digest 的行為或風格，
**只改這裡**，用白話寫就好，不用碰程式或 SKILL.md。下次跑 `/daily-digest`
就會照這份做；模稜兩可時，**這份檔的字面意思優先於 SKILL.md 的預設**。

> 改完怎麼生效：
> - 純風格/規則改動 → 下次 `/daily-digest`（新的一天）自動套用。
> - 想把改動回頭套到「已經發布的某天」→ 跟 Claude 說
>   「用新 POLICY 重寫 2026-05-19」，它會重產那天的文章（已寫的會被覆寫）。

## 目前政策（可逐條改值或敘述）

1. **範圍**：當天爬到的論文**全部**處理，含 `new` 與 `cross/replace`，
   **不篩選、不分級、不寫短版**。〔現狀，user 明確要求〕
2. **語言/讀者**：繁體中文，寫給**非研究者**看的科普。
3. **標題**：白話、吸睛、為一般人重寫，**不是論文原名**。
   〔旋鈕：想更收斂或更聳動，在這行寫清楚〕
4. **長度/節奏**：對齊參考文 `data/articles/2605.15217v1.md`（中等長度）。
   〔旋鈕：想整體更短/更長，改這行；例如「比參考文短三成」〕
5. **文章結構**：一句話重點 → 背景/問題 → 怎麼做 → 結果 → 做不到的地方
   → 「想自己判斷這篇可不可信？」表 → 「怎麼看這件事」。
   〔旋鈕：要砍掉或加哪一段，在這行列出〕
6. **圖**：一篇配一張**論文裡真的圖**（架構圖或關鍵結果圖，不要公式/表/logo），
   caption 必須與圖一致；沒有好圖就**如實說明、不放圖、不捏造**。
7. **語氣**：具體、誠實講限制、不吹捧；`**粗體**` 少用（網站只有一種粗細、無顏色）。
8. **無法處理的論文**（arXiv 取不到 PDF）：跳過並在回報中列出，**絕不捏造**。
   每天約有數篇屬此類，屬正常。
9. **部署**：推 `main` → GitHub Pages；repo 根目錄一定要有 `.nojekyll`；
   **永不**重建 `_config.yml`、**永不**啟用 `.github/workflows/run.yml`。
10. **論文歸屬日 = 論文自己的 pubDate**（RSS item 上的那個）。同一個 pubDate
    的 calendar 條目可以**跨多個物理日**慢慢長大——因為 arXiv 會在 24h 內
    陸續把 cross / replace 補進同一個公告窗。**不要**把今天才看到的論文
    硬塞到「今天」的 calendar；它屬於它原本的公告日。
11. **資料源頭模組（RSS）的承諾**：
    - `data/<pub_date>.jsonl`：只會長大,既有 id 永不消失（append-only-by-id）。
    - `pdfs/<id>.pdf`：一旦出現就是完整檔（0-byte 會自動偵測重抓）。
    - `data/rss/<cat>_<fetched-at>.xml`：每次抓的 SOT，永不覆蓋。
    - `.state/rss/`（per-machine, gitignored）：journal、pdf-status、last-fetch。
    - 無新內容時 `crawl` 早退（exit 1），artifacts 完全不動。
12. **對 arxiv 禮貌**：
    - 預設 PDF 下載間距 **15 秒**（依 `arxiv.org/robots.txt` 的 `Crawl-delay: 15`）。
    - 只打 robots.txt **明文 Allow** 的 `/pdf`、`/abs`、`/list`、`/archive`、`/html`、`/catchup`；**永不**打 `/api`（明文 Disallow，會被 origin 卡）。
    - 收到 `429`/`503` 時尊重 `Retry-After` header，並立即停止這批，等冷卻時間到才再跑。
    - User-Agent 寫明身份(`daily-arxiv-rss/...`),不偽裝成瀏覽器。
    - 460 篇 × 15 秒 ≈ 2 小時/天,這是「對 arxiv 友善 + 不被 ban」的可接受成本。
